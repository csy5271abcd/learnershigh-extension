# 원본 기반 세 시안 검토 기록

2026-10-24. 적용 기준: [요구사항 및 표현 근거](student-care-baseline-requirements.md).

## 조사와 구현의 구분

공식 도움말·디자인 지침에서 데이터형별 표현과 상세 공개 원리를 확인했다. 출결 날짜 칸, 입실 시각 편차, 주간 보드는 해당 원리를 이 서비스의 데이터에 맞춰 적용한 설계다. 세 UI가 학습관 업계 표준이라거나 실제 업무 효율을 높였다고 검증한 것은 아니다.

## 독립 코드 검토에서 발견하고 수정한 항목

- 선택 기간 평균을 최근 7일로 고정 표기하던 오류를 선택 기간으로 수정했다.
- 재확인 예정인 관리 중 학생을 학습관 화면에서 신규로 표시하던 분류를 수정했다.
- 미입실 날짜를 지운 후 입실 시각 점을 앞당겨 배치하던 계산을 원래 달력 인덱스 기준으로 수정했다.
- 미입실/미제출, 미기록, 주말 제외를 각각 ×/?/– 기호로 구분했다.

## 맥락 없는 화면 검토

새 에이전트에 코드·요구사항·의도를 주지 않고 세 시안의 실제 전체 화면 캡처만 제공했다. 학생, 기간, 지표 의미, 눈에 띄는 날짜, 상세 진입을 자유롭게 읽게 했다.

- 학생·기간과 미입실·미제출 날짜를 세 시안에서 읽었다.
- 지표별 카드, 날짜 열 보드, 날짜 행 비교라는 차이를 구별했다. 같은 날짜의 입실과 미제출 조합은 주간 보드에서 가장 쉽게 찾았다고 보고했다.
- 지표별 카드는 반복 기간·범례와 달성률 분모가 문제였다. 중복 기간을 제거하고 비교에 사용한 일수를 명시했다.
- 날짜 행 비교는 스크롤이 길고 상세 화살표가 작았다. 넓은 본문에서는 네 그래프를 나란히 놓고 빈 헤더 높이를 줄였다. 상세 버튼에는 글자를 추가했다.
- 계획 제출 상태와 계획 시간 기록의 차이가 불분명했다. 계획이 없더라도 관측된 실제 학습 시간은 보존하도록 모델을 수정했고 회귀 테스트로 확인했다.

이는 단일 AI 화면 해석이다. 실제 관리자 사용성 실험이나 세 시안 중 최종 승자 판정이 아니다.

## 직접 화면 확인

IAB에서 현재 소스가 실행되는 학생 케어 2/3/4를 확인했다. 850px 주간 보드에서는 날짜가 줄바꿈되고 시각 축이 겹쳤다. 본문의 실제 너비에 반응하는 container query로 날짜 카드 전환 기준을 바꿨다. 1600/850/390px 및 밝은/어두운 테마의 캡처는 baseline-2/3/4-* 파일명으로 저장한다. 이전 proposal-* 이미지는 이번 시안의 검증 자료가 아니다.

## 범위 및 남는 제약

원본 1은 HEAD의 학생 케어 소스 22개와 해시 일치를 확인했다. API/DB/다른 담당 기능은 변경하지 않았다. 전체 명부와 일부 지표 일별 데이터는 FE 예시다. 직전 28일 및 일별 과목 자료를 추가 생성하지 않았다. 화면 스크롤은 허용하며, 여섯 지표의 시각화를 선택 탭 뒤에 숨기지 않았다. 운영 기준값은 예시 정책이며 최적값 검증은 남아 있다.

## 실행한 검증

- Admin build / lint 통과.
- 모델·FE API 테스트 25개 통과. 미제출 상태라도 실제 학습 시간을 보존하는 회귀 검증과 주말 제외 시 시각/시간 미표시 검증을 포함한다.
- Playwright 전체 6개 통과 후 후속 데이터·레이아웃 변경에 대해 관련 5개를 다시 실행해 통과했다. 최종 목록 스크롤/비교 일수 표시 조정 후 밝은/어두운 화면 검증 2개도 다시 통과했다.
- 원본 소스 22개 해시 일치. backend/docs/api/docs/specs 변경 없음.
- 최종 맥락 없는 검토에서 비교 2일의 범위가 제목에서 보이지 않는다는 지적을 받아 제목에 비교 일수를 표시했다. 학생 목록의 검색/전체 인원은 고정하고 목록 항목만 스크롤하도록 조정했다.
