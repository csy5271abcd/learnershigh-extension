# 학생 케어: 요구사항 재검토와 데이터 표현 기준

2026-10-24. 최신 사용자 지시가 이전 시안 문서보다 우선한다. 이 문서는 구현 완료나 사용성 검증 결과가 아니라, 수정·검수의 기준이다.

## 사용자가 하려는 일

학습관 관리자가 전체 학생 중 먼저 확인할 학생을 찾고, 학생을 클릭해 무엇이 언제 달라졌는지 확인한 다음 상담·재확인 기록을 남긴다. 수업 중심 대형 학원이 아니라 자습 중심 학습관이다.

## 유지할 것

- 학생 케어 1은 수정 전 원본으로 유지한다. 원본의 목록→학생 상세, 지표와 상담·관리 이력의 연결을 세 시안의 뼈대로 삼는다.
- 학생별 화면은 전체 학생 목록을 기본으로 보여 준다. 확인 필요 학생을 위에 정렬하되 나머지 학생을 숨기지 않는다.
- 학습관별 화면은 여러 학생의 지표를 동시에 비교한다. 단순 명부나 선택 지표 하나만 보여 주는 화면으로 대체하지 않는다.
- 학생 선택 후 여섯 지표가 모두 시각적으로 제시된다. 한 지표 선택이 다른 지표들을 본문에서 없애지 않는다.
- 상세 날짜·정확한 수치·기록은 명확한 클릭 대상과 펼치기 또는 큰 상세 창으로 연결한다.

## 반복해서 지적된 실패와 제외할 방식

1. 기존 화면을 버리고 새 대시보드로 교체: 기존 탐색과 상담 흐름이 사라졌다. 원본 구조 안에서 발전시킨다.
2. 숫자·설명문만 늘리기: 읽어야 이해하는 화면이 됐다. 짧은 제목·수치·날짜·범례 외 반복 설명은 제거한다. 텍스트만 남는 지표는 허용하지 않는다.
3. 모든 지표를 막대로 통일: 입실 5일, 하루 제출 여부, 시각, 시간량을 같은 시각적 의미로 오인하게 했다. 데이터의 질문과 단위를 먼저 정한다.
4. 기간 버튼이 차트 날짜만 변경: 합계·평균·분모·비교 기간도 함께 재계산한다.
5. 날짜 생략: 언제 미입실·미제출이었는지 알 수 없다. 선택 기간의 모든 날짜를 읽을 수 있게 한다.
6. 무조건 스크롤 없애기: 작은 글씨·작은 차트로 압축했다. 스크롤은 허용하며, 여섯 지표의 시각적 요약을 숨기지 않는 것을 우선한다.
7. 본문을 지표 하나로 교체: 전체 파악이 불가능해졌다. 상세는 기존 요약 위에 추가로 연다.
8. 색·배치만 바꾼 세 시안: 자가복제 금지. 집계 데이터만 공유하고 시각화 구조를 각각 설계한다.
9. 다크 모드에서 흰 배경·불충분한 대비: 실제 브라우저에서 밝은/어두운 테마와 확대 창까지 확인한다.
10. '도래/판단 필요/지표 추세/확인일 지남': 화면에 필요한 업무 용어로 바꾼다. 확인 필요 상태의 작업 종류는 신규/재확인이다. 확인 날짜는 보조 정보다.
11. 자료 조사만 나열: 사례가 해결하는 질문·데이터형·적용 범위·차용하지 않을 부분까지 연결한다.

## 확정된 집계 계약

- 최근 N일은 기준일을 포함한 달력 7/14/28일이다. 그 안의 입실 기록으로 학습 시간·평균 입실 시각 등을 계산한다. 미입실 날짜도 날짜축에는 남긴다.
- 미입실과 미제출은 별개 기록이다. 입실한 날에도 미제출일 수 있다.
- 0, 미기록, 주말 제외를 구분한다. 계획 미기록을 0분 계획으로 바꾸지 않는다.
- 비교값은 직전 동일 길이 기간의 실제 기록이 있을 때만 표시한다. 28일 자료만 있는 예시에서 직전 28일을 생성하지 않는다.
- 조회 기간과 확인 대상 선별 정책의 기간은 별개다. 조회 버튼이 관리 기준을 바꾸지 않는다.
- 등록 등원일·목표 입실 시각이 없으므로 미입실을 결석, 늦은 입실을 지각으로 단정하지 않는다.
- 과목 비율은 현재 최근 7일 집계만 있다. 14/28일이나 일별 과목 비율을 만들어 내지 않는다.

## 지표별 질문과 보편적인 표현

### 입실 일수 / 미입실

질문: 며칠 왔는가보다 어느 날짜에 입실 기록이 없는가, 공백이 이어지는가.
자료형: 날짜별 범주 상태. 날짜 칸·상태 타임라인·이벤트 위치 표시가 적합하다. 입실/미입실/미기록/제외를 색 외 기호로도 구분한다. 5일 합계는 보조 숫자이며 긴 5 대 5 막대가 주 표현이 아니다.

근거: [Grafana status history](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/status-history/)는 시간별 상태와 비어 있는 기록을 구별한다. [Canvas Roll Call](https://community.instructure.com/en/kb/articles/660707-how-do-i-take-roll-call-using-the-attendance-tool)은 출석 상태를 기호로 구분한다. 여러 날짜를 학생 케어에 배치하는 것은 이 자료를 바탕으로 한 설계 응용이다.

### 계획 제출

질문: 어느 날 제출하지 않았는가. 입실했는데 미제출인 날은 언제인가.
자료형: 날짜별 제출 상태. 날짜 표시·제출 여부·누락 표시가 우선이다. 일별 0회/1회 수량 막대는 사용하지 않는다. 제출률만으로 누락 날짜를 감추지 않는다.

근거: [Google Classroom](https://support.google.com/edu/classroom/answer/9157286?hl=en)은 제출 상태와 학생별 상세 확인을 제공한다. 마감 전/지연 제출 판정은 현재 데이터에 없으므로 차용하지 않는다.

### 학습 시간

질문: 어느 날짜에 얼마나 공부했고 선택 기간에 늘거나 줄었는가.
자료형: 날짜별 비음수 시간량. 일별 열, 시간에 따른 선, 날짜 격자의 색 농도 등이 후보이다. 열은 0 기준, 선은 미기록을 연결하지 않는다. 히트맵은 패턴 확인에 쓰며 정확한 값을 함께 제공한다. 총 시간과 입실일 평균을 구별한다.

근거: [Analysis Function](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/)은 시간 변화·크기·편차 등 목적에 따라 차트를 선택한다. [Carbon](https://v10.carbondesignsystem.com/data-visualization/simple-charts/)은 열로 개별 값 및 시간 변화를 비교한다. [Visa heatmap](https://design.visa.com/data-visualization/charts/heatmap/)은 패턴에는 적합하지만 정확한 개별 값 비교에는 불리하다고 명시한다.

### 평균 입실 시각

질문: 실제 몇 시에 왔으며 자기 이전 기록보다 얼마나 달라졌는가.
자료형: HH:mm 시각. 날짜×시각 점, 시각의 연속 변화, 개인 기준 대비 분 단위 편차가 후보이다. 19:20을 19시간 20분의 학습량으로 표현하지 않는다. 입실 기록이 없는 날에는 점을 만들지 않는다.

근거: [Clockify attendance](https://clockify.me/help/reports/attendance-overtime)는 시작 시각과 일일 시간량을 분리한다. [Oura Trends](https://support.ouraring.com/hc/en-us/articles/360055983614-Using-Trends)는 일/주/월/년과 실제 시각 축을 다룬다. 입실 점과 편차 차트는 이 원리를 현재 자료에 적용한 설계안이며 검증된 학습관 표준이라고 주장하지 않는다.

### 계획 대비 학습

질문: 계획한 시간과 실제 학습 시간은 얼마나 차이나는가. 어느 날짜에 차이가 큰가.
자료형: 같은 날짜·같은 단위의 목표와 실적 두 값. 외곽 목표+채움 실적, 기준선이 있는 불릿, 두 점을 연결한 범위 비교가 후보이다. 비율에는 분모를 명확히 두고, 계획 없음·0 계획·실적 0을 구별한다. 100% 초과를 자동으로 나쁜 결과로 표시하지 않는다.

근거: [Toggl workload/utilization](https://docs.toggl.com/utilization-and-workload-reports-in-toggl-2-0)은 목표와 실제 시간을 함께 비교한다. [Datawrapper range plot](https://www.datawrapper.de/academy/customizing-your-range-plot)은 두 값과 그 차이를 같은 척도에서 보여 준다. 매출·가동률의 업무 판정을 학습 시간에 그대로 옮기지 않는다.

### 과목별 학습 비율

질문: 어떤 과목의 실제 비중이 계획과 얼마나 다른가.
자료형: 과목별 계획/실제 구성비. 과목별 두 점 비교, 계획/실제 100% 누적 띠, 0 기준 차이(%p) 표시가 후보이다. 계획과 실제가 시간 전후 비교로 읽히지 않도록 직접 표기한다. 원형 차트 여러 개나 의미 없는 일별 추세는 만들지 않는다.

근거: [Analysis Function](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/)의 전체 대비 부분·편차 구분과 [Datawrapper range plot](https://www.datawrapper.de/academy/customizing-your-range-plot)의 두 값 비교를 적용한다. 세 표현의 비교 가능성과 사용성은 화면 검토 대상이다.

## 서로 다른 세 시안의 표현 설계

공통은 원본 탐색 구조·집계 계약·상담 흐름이다. 그래프와 배치를 복제하지 않는다.

1. 시안 A — 지표별 차트: 여섯 지표를 개별 패널로 동시에 펼친다. 상태는 날짜 칸, 시간량은 일별 열, 시각은 점, 목표/실적은 겹친 열, 과목은 계획/실제 두 점 비교다. 원본에 가장 가까운 발전형이다.
2. 시안 B — 주간 보드: 날짜를 열로 맞춘 주간 단위 보드에서 입실·제출·시간·시각·계획을 함께 읽는다. 상태는 기록 스탬프, 시간량은 값이 적힌 농도 셀, 시각은 일별 시간 눈금의 위치, 목표/실적은 셀 안 가로 불릿으로 표현한다. 과목은 계획/실제 누적 띠로 제시한다. 한 날짜의 지표 간 관계 확인에 초점을 둔다.
3. 시안 C — 날짜별 비교 차트: 날짜가 세로로 흐르는 기록 축을 사용한다. 입실·제출은 독립 이벤트 위치, 시간량은 가로 시간 축의 점, 입실 시각은 이전 기준에서 앞/뒤 편차, 목표/실적은 연결된 두 점, 과목은 %p 편차로 표현한다. 표처럼 정렬하되 텍스트 셀을 본문으로 삼지 않는다.

여섯 지표가 최초 화면 문서에 시각적으로 존재해야 한다. 모든 지표를 반드시 물리적 한 화면에 압축하는 것은 아니며, 읽을 수 있는 크기와 날짜를 우선하고 스크롤을 허용한다. 모바일에서는 주간 보드를 날짜 카드로 재배치하며 가로로 잘라 숨기지 않는다.

## 상호작용과 검수

- [NN/g progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)에 따라 요약은 기본 화면에 남기고 상세 기록만 추가로 연다.
- [Carbon modal](https://www.carbondesignsystem.com/building-blocks/core/components/modal/guidelines)에 따라 날짜별 그래프/표를 담는 상세 창은 크게 한다. 내용이 넘치면 스크롤을 허용한다. 이전/다음 버튼으로 억지로 쪼개지 않는다.
- 날짜 클릭은 해당 학생·해당 날짜 상세, 지표 상세는 학생명·항목명·기간을 명시한다. 키보드 실행·닫기·포커스 복귀를 확인한다.
- 실제 브라우저에서 전체 명부, 학생 변경, 지점 변경, 7/14/28 집계, 모든 날짜, 주말 제외, 0/미기록, 상담/재확인, 밝은/어두운 테마를 점검한다.
- 맥락 없는 새 에이전트에게 화면만 제공해 목적·기간·누락 날짜·차트 단위·상세 진입을 읽게 한다. 정답이나 설계 의도는 주지 않는다. 이는 AI 오독 점검이며 실제 관리자 사용성 실험은 아니다.

## 추가 지표와 기본값

새 카드부터 늘리지 않는다. 현재 기록에서 계산할 수 있는 입실일 평균 학습 시간, 마지막 입실일, 연속 미제출 일수, 계획/실제 시간 차이, 집계에 쓰인 기록 수를 기존 지표의 보조 값이나 상세에 넣는 것을 우선 검토한다. 효과는 아직 검증하지 않았다. 추가 점수·종합 위험 점수·학생 순위는 산식과 운영 근거가 없으므로 넣지 않는다.

현재 FE 기본값(미입실 5일, 최근 7일 미제출 3일, 학습 시간 40% 감소, 달성률 60% 미만, 과목 차이 20%p, 입실 시각 120분 변화, 유효 학습일 3일, 알림 간격 7일)은 예시 정책이다. 학습관에 최적인 값이나 업계 표준이라고 보고하지 않는다. 설정에서 값·조건·적용 기간을 함께 확인하고 복원할 수 있어야 한다.

실제 API는 일부 지표의 일별 원본과 전체 학생 명부를 아직 제공하지 않는다. 이번 범위는 FE 예시이며 API/DB/다른 담당자 기능을 변경하지 않는다.
