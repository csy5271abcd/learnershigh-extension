# 시안 5 — 10월 26일 화면 피드백 반영

사용자의 대화 전체와 이번 첨부 8개 화면을 기준으로 작성했다. 이전 통과 기록을 디자인 승인으로 취급하지 않는다. 이전 F01–F24 중 명부→학생 선택, 원본 보존, 7/28 기간, API/DB·누락 처리 경계는 유지한다. 표현·상호작용에 관한 과거 기준이 아래와 충돌하면 아래를 우선한다.

## 최신 피드백과 적용

### 후속 정정: 통계적 극단값과 상담 필요를 분리

학습 시간이 길다는 이유만으로 경고색과 ‘이상치’ 명칭을 부여하면 상담 필요로 오인할 수 있다. 최종5에서 IQR 기반의 주황 점·건수·툴팁 ‘이상치’ 표시를 제거했다. 계산 모듈의 통계 기능이나 과거 비교안은 삭제하지 않는다. 평균·중간50%는 집단을 설명하는 비교 자료이며, 상담 판정에 쓰는 표시가 아니다. 그래프 축은 실제 표시하는 평균·범위·선택한 학생 선을 모두 포함한다. 장시간 학생도 선택하면 해당 값이 잘리지 않는 축으로 비교한다.

학습관 상단 `BranchCareQueue`는 기존 board.needsCheck의 이름·상담 사유·근거 수치를 노출하며 행/이름을 누르면 기존 학생별 탭과 해당 학생 상세로 이동한다. 새로운 경고 계산이나 임계치 변경은 없다. 확인일이 된 관리 학생은 별도 ‘상담 후 확인’ 영역에 표시하고 ‘상담 당시 사유’로 과거 snapshot임을 명시한다. 전체 학생의 그래프 비교 목록에도 상담/확인일 표식을 추가한다. 단순 장시간 학생을 새 상담 대상으로 만들지 않는다.

[Datawrapper의 선 차트 지침](https://www.datawrapper.de/academy/what-to-consider-when-creating-line-charts)에서 비교 자료와 강조할 자료를 선·색·설명으로 구분하는 방법을 검토했다. 이 화면에서는 집단 분포와 상담 업무 목록의 역할을 구분하는 데 적용한다. 산업 공정 관리도의 통계적 경계를 학생 상담 기준으로 가져오지 않는다. 실제 관리자 작업 시간 감소나 판별 정확도 향상은 측정하지 않았다.

독립 정적 리뷰에서 확인일 대상의 과거 상담 사유를 최신 이상으로 오인할 수 있음을 지적했고, 역사적 사유 표시를 추가했다. 새 E2E는 장시간 학생의 상담 목록 제외·이상치 표시 제거·일반 비교 가능·상담 사유 노출·이름 클릭 후 정확한 상세 이동·기한 도착 건 분리를 검증한다.

- **보기 버튼·행 정렬**: ‘보기’ 반복을 제거했다. 이름 옆 펼침 표시와 행 클릭을 사용한다. 학생명·상태·지표의 첫 줄을 같은 행 구조로 배치한다. 신규 상담 필요와 이전 건 확인일을 보조 줄로 구분하고, 존재하지 않는 예약 기능으로 설명하지 않는다.
- **출결 용어**: 확인된 예정일 미입실은 ‘결석’, 정상은 ‘입실’. 원본 누락은 ‘미확인’, 일정 미확인 로그 부재는 ‘미입실’. 이를 임의로 결석으로 변환하지 않는다. ‘입실 기록 없음’은 최종5의 표·차트에서 제거했다.
- **네모 박스**: 날짜 hit 영역의 시각적 테두리를 제거했다. 키보드 포커스는 날짜 글자 표시로 구분한다. 보조 정보는 역할·날짜·값이 있는 툴팁이며, 빈 hit 영역과 구분한다.
- **정확값**: 하단 고정 readout 대신 가까운 툴팁. 마우스·키보드·터치 날짜 선택을 지원한다. Escape로 닫힌다. 날짜·y축을 가리지 않도록 제한하고 가능한 빈 위치를 선택한다. 툴팁 자체는 마우스를 옮겨 읽을 수 있다.
- **결석과 입실 시각**: 실제 입실 점을 키우고, 시각이 없는 날은 실제 선을 끊는다. 결석은 0시로 그리지 않고 날짜 아래에 표시한다. 입실 시각만 누락된 경우 ‘시각 없음’으로 표시한다. 실제 학습 0과 원본 누락도 분리한다.
- **계획 데이터의 원본**: `phapi/v2/items/stats/subject_study_stats.php` 49–52,71–72,100–101행에서 `activity_item.total_time_plan`, `total_time_study`를 조회·반환함을 직접 확인했다. 기존 Mapper도 이를 분으로 변환한다. 과목 비중은 이 시간의 구성비다. 임의의 새 계획 시간 필드를 만든 것은 아니다.
- **계획 표현**: 최종5에서는 일별 계획 달성률을 우선 표시한다. 계획·실제 분 단위 값은 툴팁에 남긴다. 미제출·기록 누락을 0%로 채우지 않으며 100% 초과를 자르지 않는다.
- **과목별 비중**: 0–100% 고정 축, 계획/실제의 서로 다른 두께·색, 수치와 %p 차이를 함께 표시한다. 선택 과목 한 줄만 요약하던 중복 문구를 없앴다. 10%/90% 예시로 막대 길이 차이도 검증한다.
- **중복 제거·상담**: 위 그래프와 같은 자료를 반복하던 ‘최근 7일 기록’ 표 제거. 기존 업무 규칙에서 허용되는 상담 입력/재점검은 기본 노출하고 과거 관리 이력만 접는다. 정상 학생에게 허용되지 않는 새 수동 관리 API는 추가하지 않는다.
- **학습관 비교**: 평균·중간50% 범위·통계적 이상치를 표시하며, 여러 학생을 동시에 선택할 수 있다. 두 차트의 선택을 공유한다. 주황은 이상치, 파랑은 평균에 사용하고 학생 색과 분리했다. 학생 색은 ID 기준으로 정해 정렬 때문에 바뀌지 않는다.
- **학습관 정확값**: hover는 근처 툴팁으로 읽는다. 옆 학생 표는 기본 ‘7일 평균’이며 날짜 클릭/선택으로 일별 값을 볼 수 있다. hover와 고정 조회값을 서로 다른 날짜로 오인하지 않도록 조회 기준을 명시했다.
- **출결·계획 제출의 학습관 요약**: 학생×날짜별 긴 상태 문구 표를 제거했다. 7개 날짜의 입실·제출 인원과 결석·미제출·미확인 부분을 요약한다. 날짜를 클릭하면 결석·미제출 학생을 선택해 개인 화면으로 이동할 수 있다.
- **학습관 입실 시각**: 오전/저녁 학생의 원시 시각 평균 대신 각자의 이전 같은 요일 평균 대비 분 차이를 그린다. 실제 시각은 개인 값에 함께 남긴다. 기준 없는 학생은 편차를 0으로 만들어 넣지 않는다.
- **장황한 설명·접기**: 최종5에서 통계 산식 장문, 분포 기준 접기, 중복 학생별 날짜표를 제거했다. 필요한 단위·기간·표본 의미는 유지한다.
- **화면 폭·테마**: SVG 고정 좌표를 축소하는 대신 실제 폭에 좌표를 맞춘다. 좁은 화면은 월과 일 축을 분리해 7일 모두 유지한다. 1600/850/390px와 밝은/어두운 테마를 검토한다.

### 추가 지적: 데이터가 화면에 유리하게 단순화됨

기존에는 대부분 매일 입실·제출, 같은 과목 비중, ±10분 시각 변화였다. 오전 입실과 10%/90%만 추가해도 이런 구조는 유지됐다. 이를 실제 학습관을 검증한 데이터로 설명하지 않는다.

두 지점 13명에 대해 최근 7일은 날짜별 관측 시나리오를 명시하고, 이전 28일은 개인별 평일/주말 입실 패턴·주 단위 변동·독립적인 일별 학습량/계획량/과목 비중을 사용한다. 같은 학생·날짜는 재조회해도 동일하다. 실제 운영 표본이나 통계적으로 대표적인 집단은 아니다. 무작위 값을 늘리는 대신 다음 구분이 유지되는지 확인한다.

- 입실했지만 미제출, 계획은 제출했지만 결석, 입실 후 실제 0분을 서로 다르게 표현한다.
- 꾸준히 입실하는 학생과 간헐적·연속 결석 학생이 함께 있다. 모든 학생에게 경고 조건을 하나씩 배정하지 않는다.
- 오전/저녁, 주말 장시간/평일 짧은 학습, 하루별 초과·미달 달성률을 포함한다.
- 과목별 선호와 날짜별 집중 과목이 다르다. 윤서연의 수학 계획은 주간 약10%, 실제는 일별55~100%로 변하고 주간 약84%다. 매일90%로 고정하지 않는다.
- 최근 원본 누락, 입실 시각만 누락, 일정 미확인 로그 부재, 이전28일의 원본 누락을 포함한다. 이를 결석/실제0으로 바꾸지 않는다.
- 입실 시각이 있는 날의 실제 학습시간은 해당 날짜의 남은 시간보다 길지 않다. 날짜 기준일이 바뀌어도 실제 요일을 따른다.

독립 적대적 리뷰에서 초기 수정안의 전원 결석과 기준일 상대 인덱스/요일 불일치를 발견해 수정했다. 기존 계산기는 결석 경고가 있으면 일부 다른 변화 신호를 생략하므로 데이터 필드 다양성만 검사해서는 충분하지 않았다. 기본 설정을 사용하는 서비스 검사로 신호 없는 학생, 결석·미제출·학습량 감소·입실 지연, 복수 신호가 모두 존재하는지 확인한다. 이 다양성은 합성 검증 범위이며 운영상의 발생률은 검증하지 않았다.

수정 범위는 Mock 데이터·검증·이 문서다. FE 레이아웃/실제 어댑터/API JSON/DB/판정 기준/과거 상담 스냅샷은 바꾸지 않는다. 최신 데이터 캡처와 API 원문은 기존 증거를 덮지 않고 `oct26-diverse-data` 폴더에 저장한다. 이전 단락의 검증 수치는 당시 작업본의 기록이며 이번 작업의 재실행 결과와 혼동하지 않는다.

스크린샷만 제공한 별도 리뷰에서는 날짜별 출결/제출 차이와 학생별 시간 차이는 읽었으나, 보라 계열 학생 두 명의 선 구별, 중간분포/이상치의 설명, 회색 범례의 미확인/일정 없음 구분, 집단 그래프의 0분 사유 구분에 한계가 있다고 보고했다. 이는 데이터 변경으로 UI 전체가 승인되었다는 근거가 아니며 이번 데이터 작업에서 해결했다고 보고하지 않는다. 긴 전체 페이지 이미지를 축소해서 보는 조건의 작은 글씨 문제도 실제 화면 결함과 구분한다.

이번 데이터 변경 검증: Backend 단위259건 실패0, E2E17건 실패0(6.3분), E2E TypeScript 검사 통과. 기존 회귀 fixture 보존, 합성자료의 관측 의미/시간상한/재현성/요일/기준기간 누락, 기본 설정의 다양한 판정, 실제 API→화면 값 일치와 양테마3폭 검사를 포함한다. 분당3명 관측표 추가 후 단위259건을 다시 실행하고 서버 재시작 뒤 해당 지점 API 응답을 따로 저장했다. MySQL 통합104건은 이번 변경에서 재실행하지 않았으며 이전 통과 기록을 이번 실행으로 계산하지 않는다. FE 제품코드는 수정하지 않았다.

## 참고 자료와 적용 범위

- [Datawrapper: missing data in line charts](https://www.datawrapper.de/academy/patchy-data): 공백을 그대로 남기는 경우와 관측점 표시를 검토했다. 결석 시각을 임의로 연결하지 않고 실제 관측점이 드러나도록 적용했다.
- [W3C: Content on Hover or Focus](https://www.w3.org/WAI/WCAG21/Understanding/content-on-hover-or-focus): hover·focus 정보의 접근, 지속, 닫기 기준을 검토했다. 전체 화면의 WCAG 준수 인증을 주장하지 않는다.

## 독립 검토에서 발견하고 고친 문제

첫 코드 리뷰에서 출결 툴팁이 날짜 클릭을 가로채는 문제, 기존 CSS가 이름 정렬을 덮는 문제, 툴팁과 키보드 대상의 설명 연결 누락을 지적했다. 각각 이벤트 연결·선택자 우선순위·id/aria-describedby로 수정했다.

맥락 없는 이미지 독해에서는 이상치와 선택 학생의 주황색 중복, 0분 의미, 조회 날짜 혼동, 좁은 화면 축과 툴팁의 가림을 지적했다. 색 예약·‘0분 · 결석’·7일 평균 명시·월/일 축·툴팁 크기 및 위치 선택에 반영했다. 키보드 포커스 강조와 사용자 선택 날짜를 동일하게 해석하지 않는다.

이 문서는 화면 검수 기록이다. 발표자료용 별도 적대적 리뷰 문서는 만들지 않는다.
