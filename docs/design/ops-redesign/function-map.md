# 기능 보존표

기존 학생 케어(`/student-care`)의 기능이 개선안(`/student-care/ops`)에서 같은 동작으로 남아 있는지 대응시킨 표다. API는 두 화면이 같은 것을 쓴다(`httpStudentCareApi`). "검증" 열은 실제로 확인한 방법과 결과이며, 확인 전이면 "미확인"으로 둔다.

## 바뀐 표현과 이유

- 상담 필요 배지를 행마다 반복하지 않는다. 행 왼쪽 선과 사유 칩이 같은 정보를 전한다(텍스트 감소).
- 결석 신호(`CONSECUTIVE_ABSENCE`)는 서버에서 연속이 아니라 횟수다. 칩에는 날짜에서 계산한 "연속"·"(띄엄띄엄)"을 붙이고, 같은 날짜의 계획 미제출은 따로 칩을 만들지 않고 "그날 계획 없음"으로 합친다.
- "매주 ○ 결석"은 서버 신호가 아니라 35일 날짜에서 화면이 계산한 표시이며, 점선 칩으로 구별한다. 판정(상담 필요 여부)에는 영향을 주지 않는다.
- 관리 중 학생의 사유는 관리 시작 때의 신호라 "관리 사유 ○○"로 쓰고 현재 7일 값으로 다시 세지 않는다.
- 예정 없는 날의 제출 상태를 서버는 `MISSING`으로 보내지만, 화면은 미제출로 세지 않는다.
