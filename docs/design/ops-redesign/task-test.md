# 과업 시험 (4판, 2026-11-07 고정)

1판은 Codex 계획 검사에서 정답 오류(Q3·Q4가 관리 중 학생을 빠뜨림), 쓰기 과업을 하지 않아도 통과하는 채점, 두 화면 시험 사이의 DB 오염, 빠진 과업을 지적받았다. 2판은 3차 심사에서 기록기 누출, Q10 기준 불일치, 개인 종합·결석 패턴 과업 부족을 지적받았다. 3판은 이를 고친 판이며, 와이어프레임을 만들기 전에 고정한다. 이후 정답 계산에서 오류가 발견되면 고치되, 판 번호를 올리고 바꾼 이유를 이 문서 끝에 적는다.

정답은 API 스냅숏(`data-snapshot/`)에서 `scripts/research/care-task-answers.mjs`로 계산해 `task-answers.json`에 두며 시험관에게 주지 않는다.

## 실행 절차

1. 화면마다 새 시험관(맥락 없는 Codex 실행)을 쓴다. 시험관은 정답, 다른 화면의 시험 기록, 소스 코드, API, 데이터 파일, 이 폴더의 다른 문서를 받지 않는다. 받는 것은 화면 주소, 아래 "문항" 절(학생 이름을 채운 것), 조작 기록기 사용법뿐이다. 전달한 프롬프트 원문은 `task-runs/<화면>-prompt.md`에 남긴다.
2. 시험 순서는 기존 화면 → 개선안이다. 각 화면 시험 직전에 `scripts/research/care-db-state.sh restore initial`로 상담·설정 테이블을 같은 초기 상태로 되돌리고, board API로 상담 필요 49명·관리 중 5명을 확인한다. 시험 전에 `node scripts/research/care-snapshot-check.mjs`가 통과해야 한다(상세·metrics·board·정답·시드 해시 일치). 업무일은 백엔드 `app.fixed-date=2026-10-28`로 고정돼 있다.
3. 시험관은 `scripts/research/care-task-harness.mjs`의 함수로만 화면을 조작한다. 문항을 시작할 때 `question('Q1')`처럼 문항 번호를 알린다. 기록기는 문항별로 명시적 조작, 조작으로 생긴 자동 이동, 읽은 내용(`read()` 결과 전문), 저장 요청(POST/PUT)과 응답 코드를 남긴다. `read()`는 지금 뷰포트 안에 있고, 투명하지 않고, 상위 영역에 잘리거나 다른 요소에 가려지지 않은 텍스트와 입력값만 돌려준다. 이 동작은 `care-task-harness.test.mjs`(잘림·투명·가림·화면 아래·내부 스크롤 밖 텍스트를 넣은 합성 화면)로 회귀 시험한다. 두 화면 모두 같은 기록기 판으로 시험한다. 화면 크기는 1600×900, 라이트 테마다.
4. 읽기 과업(1–8, 11–15)을 먼저 하고, 쓰기 과업(9, 10)을 마지막에 한다. 쓰기 과업이 상태를 바꿔 읽기 정답과 어긋나는 것을 막기 위해서다.
5. 시험이 끝나면 API로 상담 이력과 설정을 재조회해 저장 결과를 확인하고, 다시 `restore initial`로 되돌린다.

## 문항

강남점을 기준으로 답한다(문항에 다른 지점이 있으면 그 지점). 학생 이름은 `task-answers.json`의 해당 문항 `student` 값으로 채운다.

1. 지금 "상담 필요"로 표시된 학생은 몇 명인가?
2. 최근 7일 중 4일 이상 결석한 학생을 모두 쓰라.
3. 최근 7일 결석은 없는데 학습 시간이 평소보다 줄었다는 표시가 있는 학생을 모두 쓰라(관리 상태와 무관).
4. 입실 시각이 평소보다 늦어졌다는 표시가 있는 학생을 모두 쓰라(관리 상태와 무관).
5. {Q5}의 최근 7일 중 등원 예정일인데 계획을 제출하지 않은 날짜를 모두 쓰라.
6. {Q6}의 최근 7일 중 첫 입실 시각이 가장 늦었던 날짜와 시각을 쓰라.
7. 상담 후 관리 중인 학생은 몇 명인가?
8. {Q8}의 최근 7일 학습 시간 합계를 쓰라.
9. {Q9}에게 "면담"으로 상담하고 결과를 "계속 관리", 다음 확인을 1주 뒤로 기록해 저장하라. 그 뒤 관리 이력에서 이 기록의 다음 확인 날짜를 찾아 쓰라.
10. 수지점의 관리 기준 설정에서 결석 기준 일수를 확인해 쓰라. 그 값을 1 늘려 저장하라. 저장 후 설정을 다시 열어 화면에 보이는 값을 쓰라. 그다음 원래 값으로 저장하라.
11. {Q11}이 관리 대상으로 표시된 이유를 모두 쓰라.
12. 최근 7일 결석이 2일 이상인 학생을 결석이 이어진 학생과 흩어진 학생으로 나눠 쓰라(등원 예정이 없는 날은 이어짐을 끊지 않는다).
13. 강남점 전체의 최근 7일 학습 시간은 평소(같은 요일 기준)보다 늘었는가, 줄었는가? 대략 몇 %인가?
14. {Q14}의 최근 7일 계획 대비 진행률을 쓰고, 계획 비중과 실제 비중의 차이가 가장 큰 과목과 그 차이(%p)를 쓰라.
15. 최근 35일(이전 28일 + 최근 7일) 동안 매주 같은 요일에 결석한 학생과 그 요일을 쓰라(4번 이상).

## 채점

문항당 10점, 150점 만점.

| 유형 | 문항 | 규칙 |
|---|---|---|
| 수 | 1, 7 | 정확히 같으면 10점 |
| 명단 | 2, 3, 4, 11, 15 | 정답과의 일치율(교집합 ÷ 합집합) 80% 이상 10점, 50% 이상 5점, 그 미만 0점. 순서는 보지 않는다 |
| 날짜 목록 | 5 | 명단과 같은 규칙 |
| 날짜·시각 | 6 | 날짜가 같고 시각 ±5분이면 10점, 날짜만 같으면 5점 |
| 결석 패턴 | 12 | 연속 명단과 흩어짐 명단 각각 명단 규칙을 적용해 5점씩 |
| 시간 합계 | 8 | ±10분이면 10점 |
| 비율 | 13 | 방향이 같고 ±3%p이면 10점, 방향만 같으면 5점 |
| 개인 종합 | 14 | 진행률 ±2%p이면 5점, 과목이 같고 차이 ±3%p이면 5점 |
| 업무 | 9 | 기록기의 저장 요청이 지정 학생·면담·계속 관리·다음 확인 2026-11-04이고 응답이 성공, 서버 재조회 이력에 같은 기록이 있고, 시험관이 답한 날짜가 같으면 10점. 저장은 맞는데 답이 틀리면 5점. 저장 요청이 없거나 내용이 다르면 0점 |
| 업무 | 10 | 다음 4가지를 모두 만족하면 10점: ① 처음 답한 값이 정답 ② `branchId=demo_small`인 저장 요청이 순서대로 2회(값+1, 원래 값) 성공 ③ 첫 저장 뒤 Q10 문항 안에서 서버 설정 조회(GET `/settings?branchId=demo_small`) 응답의 `absenceDays`가 값+1이고, 같은 문항의 `read()` 기록에 값+1이 보이며, 시험관이 그 값을 답함 ④ 두 번째 저장 뒤 서버 조회 응답과 시험 후 API 값이 원래 값. ①과 ④만 만족하거나 ③이 없으면 5점. 저장 요청이 없으면 0점 |

**개선 판정.** 개선안 총점이 기존 화면보다 높아야 한다. 기존 화면에서 10점을 받은 문항을 개선안에서 10점 미만으로 받으면 퇴보이며 불통과다. 문항별 조작 수는 명시적 조작(클릭·입력·선택·스크롤)과 자동 이동을 더해 센다. 9·10번의 조작 수는 기존 화면 이하여야 한다. 읽기 문항 전체의 조작 수 합도 기존 화면 이하여야 하며, 이를 넘으면 페이지 분할이나 가로 이동으로 부담을 옮긴 것으로 보고 불통과다.

## 시험으로 확인하지 않는 기능

학습관별의 학생 제외·복원은 운영자 일상 과업이 아니므로 시험에서 빼고, `function-map.md`의 실행 검증(제외 전후 값, 복원 후 원래 값 일치)으로 확인한다.

재확인 처리는 현재 데이터에 확인일이 지난 학생이 없어(관리 중 5명 모두 `recheckDue: false`) 과업 시험 대신 별도 시험 상태로 검증한다. `restore initial` 뒤 관리 중 학생 한 명(`demo_s014`)의 `care_case.recheck_date`를 업무일(2026-10-28)로 바꾼 상태를 `care-db-state.sh save recheck-due`로 저장하고, 두 화면에서 재확인 화면이 열리는지, 재확인 결정 저장이 성공하는지, 저장 후 상태가 바뀌는지 확인한 다음 `restore initial`로 되돌린다. 화면마다 시험 직전에 `restore recheck-due`를 실행해 두 화면이 같은 상태에서 시작한다. 저장 후 기대 상태는 board에서 해당 학생이 관리 중 목록의 `recheckDue: true`에서 빠지고(계속 관리면 새 다음 확인일, 종료면 관리 중에서 제외), 이력에 재확인 결정 기록이 1건 늘어나는 것이다.
