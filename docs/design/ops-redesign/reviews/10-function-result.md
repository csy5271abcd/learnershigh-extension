2026-11-07. 결론: **필수 위반 잔존. 정보 탐색은 일부 개선됐지만 기능 보존 완료로 볼 수 없다.** 전체 검사의 최초 필수 위반은 V01–V08이며, 작성자의 동시 수정 후 좁은 재검사에서 **V02·V04·V05 해소, V01 일부 복구**를 확인했다. **V03·V06·V07·V08은 남아 있다.** 아래 1장의 후속 상태표가 최초 판정·수정 요청보다 우선한다. 이 결과는 다음 수정에 반영할 검토 의견이며 진행 중단 명령이 아니다. 다음 수정의 기본안은 **table**을 추천한다. 현재 구현을 통과시킨다는 뜻은 아니다.

**근거 범위.** 모든 신규 시험 파일·캡처는 [10-evidence](10-evidence/) 안에 있다. 검사 도중 외부에서 `ops.css`, `opsModel.ts`, `OpsRoster.tsx`, `StudentCareOpsPage.tsx`가 변경됐다. 초기 결과는 `initial/`, 중간 결과는 `pre-grid-change/`로 분리했고, 아래 최종 폭·테마 수치는 마지막 CSS 변경(08:06:46, 이후 외부 커밋 `1e0bd00`) 이후 다시 실행한 `layout-results.json`, `final-probes.json`을 사용한다. 소스 식별은 `source-hashes-final.json` 참조. 초기의 “그날 계획 없음”은 최종 화면에서 “·미제출”로 바뀌었으므로 잔존 결함으로 세지 않았다.

### 숫자가 맞아도 의미가 달라지는 지점

1. **연속의 단위가 생략됐다.** `absencePattern`은 예정 없음이면 연속을 끊지 않는다(`opsModel.ts:74`). 박예준의 24·26·27을 “등원 예정일 3회 연속”이라 쓰면 맞지만 현재 “3일 연속”은 달력일로 읽힌다. 연속 여부는 BE `CONSECUTIVE_ABSENCE` 코드의 의미가 아니라 FE 추론이다. 판정 공식은 최근 7일 결석 횟수다(`docs/specs/wangyu/domain.md:21`).
2. **‘매주’가 과도한 확신이다.** 화면은 35일 중 3회 조건만 사용한다. API 계약의 정기 패턴 추정 조건은 이전 같은 요일 4회 모두 관측·미입실이다(`api-contract.md:3472`). 이와도 다르다. `edge-results.json` 반례는 이전 목요일 3회 결석·1회 입실, 이번 목요일 입실인데도 “매주 목 결석”을 표시한다. `35일 목요일 3/5회 결석(화면 계산)` 정도로 관측과 추론을 분리해야 한다.
3. **학습관 묶음의 인원이 현재 사실을 나타내지 않는다.** 실제 최근 결석 학생 18명인데 새 학습관 “결석 19명”에는 최근 결석 없는 이지우가 과거 관리 사유로 포함된다. 실제 계획 미제출 학생은 35명인데 새 묶음은 17명이다. 그중 김도현은 현재 미제출 0일이다. `chipsFor`가 결석과 합친 PLAN_MISSING 칩을 제거하고(`opsModel.ts:109`), `OpsBranch.tsx:20`이 칩을 다시 집계하기 때문이다. 표에 표시할 이유를 줄인 결과가 대상 학생 집합까지 바꿨다. 요약 문구를 “서버 신호 대상/과거 관리 이유”라고 정확히 구분하거나 원자료로 집계해야 한다.
4. **부분 자료 합계가 완전한 주 합계처럼 보인다.** 권예준(s148)은 API recordedDays=4/7·studyMinutes=429인데 상세는 “7일 7시간 9분·입실 3/3일·제출 3/3일”이다. 출결 줄에는 기록 없음이 보이지만 요약의 분모는 관측된 예정일만 세고 자료 완전성을 표시하지 않는다. `OpsDetail.tsx:85`, `opsModel.ts:139` 참조. BE가 정상 분류했다는 사실과 완전한 관측이라는 주장은 다르다.
5. **정밀도 감소·불릿 축 변동.** 권유진 6:07→명부 6시간, 강하준 8:51→9시간이다. 평소 주 숫자는 상세에만 있다. `OpsRoster.tsx:48`은 현재 검색 결과의 최대값으로 축을 재계산하므로 같은 학생의 막대 길이가 검색 전후 달라진다. 시각적 변화가 학생 데이터 변화인 것처럼 읽힐 수 있는데 눈금이 없다. M은 이 숫자를 정확히 보존한다.
6. **요일 평균의 정확값이 접근성 텍스트에만 남았다.** 기간 주평균과 같은 요일 평균은 서로 다른 기준인데 화면 상단은 “평소는 이전 28일 같은 요일”로 일괄 설명한다(`StudentCareOpsPage.tsx:82`). 목록의 평소 주가 실제로는 28일 합/4라는 점을 구분해야 한다. 상세 학습 단위도 `3:08`과 입실 `18:39`가 같은 형식이라 시간량과 시각 혼동 위험이 있다.

시드에서 예정 없음+실제 제출/비입실+양수 학습 조합은 없었다. V04는 유효한 일별 DTO를 브라우저 GET에 치환한 별도 반례이며 운영 DB에서 관측한 현상이라고 주장하지 않는다. 그 반례는 일별 렌더링만 분리하기 위해 기간 합계를 고정했으므로 합계 불일치 자체는 결함 근거로 사용하지 않았다.

다음 표는 마지막 CSS 기준 1600×900·라이트·강남 150명이다. 원본은 명부 기본/첫 학생 상세를 각각 측정했고, 개선안은 첫 학생 상세가 **자동 표시되는 초기 상태**다. `final-probes.cjs`는 기존 `care-screen-metrics.mjs`의 probe 함수를 그대로 읽어 사용했다. 따라서 두 화면의 측정 정의는 같지만 초기 표시 범위가 다르다. 숨은 텍스트는 기존 측정기가 세는 title·닫힌 영역 등이며, 모든 aria-label 길이를 뜻하지 않는다.

0개 전환 조작은 펼치기 대신 행 선택으로 바뀌어 `aria-expanded` 등이 없어졌다는 뜻이다. **실제로 학생 선택 150개가 사라졌다는 뜻은 아니다.** 선택 후 다른 학생을 보는 조작 수는 여전히 남고, 모바일에서는 긴 자동 스크롤과 수동 복귀가 추가된다. 지표만으로 복잡성 제거를 입증할 수 없다.

학습관은 세 안 모두 같은 컴포넌트다. 기존 1,310자·1,741조작·숨은 텍스트 2,249자에서 새 화면 714자·79조작·53자로 감소했다. 이 수치 개선의 일부는 V01/V02의 기능 삭제로 얻었다. 유지 항목 실패를 상쇄하는 효과 근거가 아니다.

분당 table은 1,194자·2.3화면(기존 명부 1,917자·4.9화면), 수지 table은 634자·1.6화면(기존 명부 476자·1.3화면)이다. 수지 기본 노출은 자동 상세 때문에 더 많다. 기존의 상세를 연 상태(수지 980자·3.5화면)와는 개선되므로 비교 상태를 선택해 유리하게만 보고하면 안 된다. plan 5장 “소규모도 기준점보다 나빠지지 않음”을 무조건 달성했다고 할 수 없다.

## 7. 우선순위 순 수정 요청

아래 순서는 전체 검사판의 요청 목록이다. **1장 후속 상태표가 우선하며, 이미 해소한 항목을 다시 구현하라는 요청이 아니다.** 현재 우선순위는 3·4·5·7번 및 연속 결석의 단위 표기다. 1번은 기능 복구 후 비교·시각 표현 재검토, 2번의 독립 기록/요일 문구와 8번의 제외 상태는 후속 반영을 확인했다.
