너는 학원·독서실 관리자용 "학생 케어" 화면 개선 작업의 계획을 심사하는 독립 검토자다. 작성자(다른 에이전트)는 직전에 같은 작업을 실패했다. 사용자는 작업 중 자리를 비우므로 네 검사가 사용자 승인을 대신한다. 통과시키는 것이 아니라 실패할 경로를 찾는 것이 목적이다.

## 사용자 요구 (원문 요약, 2026-11-07)
- 목표1 목적에 맞는 기능 개선: 운영자 입장에서 더 보기 편하게, 문제 학생이 더 잘 보이고 관리하기 쉽게. PM으로서 사용자 가이드 문서를 만든다는 생각, 또는 튜토리얼·도움말. 그러나 가장 좋은 것은 보자마자 이해되고 바로 쓸 수 있는 디자인. 현재 학습관별은 다량의 학생을 보여주기에 부적합하고, 개인별은 한눈에 보기 힘들다.
- 목표2 기존 지표 개선: 다량의 학생을 잘 보여주는 법, 개인 학생을 한눈에(희망, 강요 아님), 시계열·날짜가 비어 있는 시간값·비율·횟수 표현이 적절한지와 의미가 퇴색되지 않았는지.
- 과거 문제: A/B/C가 사실상 같음. 피드백한 것에 무조건 걸림. 개선 근거가 허황됨. 텍스트 양이 줄어야 함. 펼치기·접기·추가·제외는 복잡성을 늘림. 스크롤 과다나 과밀 금지. 결석은 횟수와 날짜 패턴 중 무엇이 중요한지 같은 고찰 필요. 참고자료는 작업 후 출처를 던지는 식이 아니라 실제로 써야 하고, 공신력 있는 자료와 스킬을 써야 함.
- 이번 결정: 기존 지표·기능을 줄이지 않는다(케어 대상 선별용 지표이므로). 실제 React 앱에 별도 안을 만든다. 초기값 필터링·운영자 설정·문제 학생 식별 유지. 계약과 충돌하면 이번 목표 우선, 변경 기록. 지점 인원은 150/50/10명. 중간에 사용자에게 묻지 않는다.

## 채점
100점 만점으로 아래 항목을 채점하고, 항목마다 근거(파일·줄·측정값)를 적어라.
1. 목표 적합성 25: 계획이 사용자 요구 각 항목에 답하는가. 빠진 요구가 있으면 감점.
2. 측정 가능성 20: 개선 판정 지표와 목표치가 개선을 실제로 증명하는가. 대리 지표의 허점(예: 내부 스크롤로 문서 높이만 줄이기, 텍스트를 툴팁에 숨기기, 조작을 다른 이름으로 바꾸기)을 막는가.
3. 실패 반복 방지 20: 직전 실패(기능 축소, 설명 문장 추가, 서랍 기본 탐색, 정상 학생 숨김, 색만 다른 시안, 자기 기준 채점)와 과거 실패(피드백 항목 땜질, A/B/C 동일)를 구조적으로 막는가.
4. 실행 가능성 15: 기존 API로 구현 가능한가, 단계와 검사가 현실적인가, 위험 대응이 있는가.
5. 근거 사용 15: 참고자료 사용 방식이 실제 결정을 바꾸게 설계됐는가.
6. 범위·정직성 5: 과장, 확인 안 한 주장, 과설계가 없는가.
