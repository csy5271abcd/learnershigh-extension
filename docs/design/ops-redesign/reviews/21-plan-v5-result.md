## 3. 필수 지적 — 이 상태로 구현하면 안 되는 것

### R01 / M06 잔여: 미지원 축의 집계 분모를 통일하고 사진 없음에서 출결을 추론하지 말 것

**근거:** 계획 57–58행, 비전 초안 ‘단위와 규칙’, `visionExample.ts:62`, `:88`, `:113`, [독립 반례 결과](21-evidence/vision-check.json).

계획은 학생별 날짜·7일 합의 분모를 분석 장수로 두고, 학습관 비율도 관찰 합÷분석 합, 학생 분포도 분석 1장 이상 학생으로 정의한다. 초안은 미지원 축을 unknown에 포함하고 yes+no+unknown=analyzed로 둔다. 반면 현재 `branchVisionDay()`는 **미지원 학생·날의 분석 사진을 그 축의 분모와 학생 분포에서 통째로 제외**한다. `sumVision()`은 그 사진들을 전체 분석 분모와 unknown에 포함한다. 코드만 보고 어느 집계가 계획의 정답인지 확정하면 안 된다.

독립적으로 유효한 사진 셈을 만들었다. 읽기·쓰기 지원 학생 10장 중 yes 1장, 미지원 학생 10장 중 unknown 10장일 때 계획 문장대로의 합산은 **1/20=5%**, 현재 학습관 함수는 **1/10=10%**다. 같은 사진 셈을 학생 기간 합 함수에 넣으면 분모는 20으로 남는다. 계산 오류라고 단정하는 것이 아니라, **지원 관측만의 비율인지 전체 분석 사진 중 yes 비율인지 계약이 갈라져 있다는 재현**이다. 전안 공용 함수와 테스트 통과만으로 의미 일치를 보장할 수 없다.

또한 계획의 ‘사진 없음(입실 안 함)’은 허용할 수 없다. 생성기는 출결을 받지 않고 `minutes`가 null·0이면 사진 0장을 반환한다. 학습 기록이 없거나 0인 것, 사진이 없는 것, 입실하지 않은 것은 다른 사실이다. 예시 생성 편의가 화면의 출결 근거가 되면 안 된다.

**해소 조건:**

1. 축별로 전체 분석 사진을 포함할지 지원 분석 사진만 포함할지 하나의 집계 정의를 명시한다. 지원 관측만 쓰는 선택도 가능하지만 축별 실제 분모·제외된 미지원 장수/학생 수를 구분해야 한다. 초안과 다른 선택은 5판의 예시 집계 규칙으로 명시하며 실제 API 채택으로 쓰지 않는다.
2. 같은 정의를 학생 날짜·7일 합과 학습관 날짜·학생 분포에 적용한다. 학생 기간 중 지원/미지원 모델이 섞인 경우도 포함한다. ‘지원 안 함’ 전체와 ‘일부 관측 미지원’을 구별하고 미지원 사실을 합계에서 잃지 않는다.
3. 사진 0장은 ‘사진 없음’으로 표시한다. 별도 출결 원본으로 확인된 경우에만 입실 상태를 함께 표시한다. 입실했지만 학습 기록 null/0, 사진 없음, 실패만 있는 날을 별도 반례로 둔다.
4. 위 1/20 대 1/10 반례와 기간 내 혼합 모델 반례의 기대 분모·unknown·미지원 표시를 고정한다. 구현 1단계 통과 조건에 이 독립 예제 대조를 포함한다. 휴대폰 축 Q16·Q17만 맞는 것으로 다른 축의 의미 검증을 대신하지 않는다.

이는 촬영 간격이나 실제 비전 API를 새로 확정하라는 요구가 아니다. 현재 허용된 예시 데이터의 의미만 일치시키면 된다.

## 4. C·D 승인 여부

### C — 조건부 승인

이전 거부의 핵심인 ‘저장하면 처리함’과 숫자표만 있는 학습관 현황은 제거됐다. 확인 대상 학생 중복 제거 → 사유·근거 확인 → 넓은 서랍에서 개인 지표와 기록 → 서버 상태·다음 확인일 확인 → 선택 줄 복귀라는 흐름은 관리자 업무 목적과 연결된다. 별도 업무 상태를 만들지 않는 수정이 더 단순하고 기존 기능과 중복도 적다.
