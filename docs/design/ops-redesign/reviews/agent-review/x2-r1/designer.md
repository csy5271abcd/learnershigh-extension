# 시안 X′ 1회차 — 시니어 디자이너 + 기획 검토

범위: 1280 폭, 라이트·다크, 학생 탁예린·문가영·구서아·변지호. 학생별 명단, 학생 겹창 세 탭, 학습관별, 상담 기록. 캡처는 모두 `designer/` 아래(원래 크기, 겹창은 잘림 없이 전체). 스크립트 `designer/shoot.mjs`, 색 측정 `designer/contrast.mjs`.
비교 기준: 원래 화면 `student-study-status-list.png`(경계 분명한 표, 한 줄 한 학생), `study-plan-create-modal.png`(어두운 머리 띠 + 흰 본문 겹창). 겹창 틀과 명단 짜임은 원래 화면과 잘 맞는다.

그래도 되는 것: 명단 한 줄 구성(구분·이름·반·사유와 값), 겹창 머리 띠, 탭 글자색으로 문제 탭 표시(R02), 확인 필요 띠, 출결·계획 제출 표, 핵심 숫자를 제목 옆에 크게(결정 8장), 학습관별 한 행 한 지표, 맨 위 사유별 학생 수.
화면 콘솔 오류: 응답 404 한 건(어느 주소인지 이 검토에서 찾지 못함, 사진 서버 관련으로 추정, 확인 필요).

## 기획 관점: 결정 문서 대비

- 결정 1장(원래 화면 모양 우선, 겹창, 같은 틀을 학습관별에서도): 겹창 틀은 원래 '학습계획 추가' 겹창과 같은 짜임으로 들어감. 학습관별에서 학생을 누르는 동작은 이번에 열어 보지 않음(확인 안 함).
- 결정 8장 '계획은 점선으로 앞에, 실제는 막대가 계획을 넘어 보이게': 이번 요청대로 뒤 회색 넓은 막대 + 앞 파란 좁은 막대로 구현. 변지호처럼 실제가 계획을 넘는 경우 파란 막대가 회색 위로 튀어나와 보임(좋음). 다만 D1의 명암비 때문에 계획이 흐려 '더 공부했다'는 읽힘이 약함. 문서가 요구한 '테두리 없고 반투명한 바탕과 합쳤을 때 잘 보이는지 직접 확인'이 라이트에서 통과하지 못함.
- 결정 8장 핵심 숫자: 제목 옆에 크게 들어감(통과). 단 문구 '/ 계획 19시간 36분 · 달성률 19%'에서 '평소 한 주'와 '평소 3시간 4분' 같은 되풀이가 있다(D4a).
- 결정 4장 학습관별: 한 행 한 지표, 변화량(늘어남·줄어듦 학생 수와 합) 포함, 맨 위 사유별 학생 수로 요약 줄을 다시 구성함(통과). 이름·수 불일치는 D8, 비몰입 줄 D4.
- 결정 1장 비몰입 시간당 3건 기준과 관리 기준에서 바꾸기: 그림에 '1시간당 3건 이상' 문구는 있으나 풀이 문구 형태(D3).
- 결정 5장 'NO.' 삭제, 이름 칸 쪼개짐: 명단에서 해결됨(1280에서 한 줄로 읽힘). 1024는 이번 범위가 아니어서 안 봄.

## 컨셉

러너스하이 관리 화면 모양(좌 메뉴, 흰 카드, 어두운 겹창 머리 띠)에는 잘 맞고, 경계도 분명하다. 흔한 막대그래프 꼴이다. 남은 문제는 구조가 아니라 막대의 색·글자 위치와 범례 문구로, D1–D3만 고치면 막힘이 풀린다. 막힌 곳의 색 후보:
- 계획 막대(라이트): 현재 rgb(221,227,236) → 후보 A rgb(176,188,206)(흰 바탕 약 2 대 1 이상으로 올라가나 3 대 1에는 아직 부족), 후보 B 같은 색에 1픽셀 진한 테두리(rgb(120,134,158), 3 대 1 이상), 후보 C 속 빈 점선 테두리(결정 8장 원안). 테두리 후보 B·C가 3 대 1을 지키는 가장 쉬운 길.
- 계획 막대(다크): 현재 rgb(58,63,85) → 후보 rgb(92,100,128) 또는 같은 색에 밝은 테두리 rgb(140,150,175).
- 막대 폭: 파랑 40 / 회색 72. 두 번째 후보로 파랑 48 / 회색 72, 세 번째로 파랑 44 / 회색 80을 실제 화면에서 나란히 비교.
