### E1. 단계 막대 — 적합한 뼈대, 단계의 뜻은 숨김

[A 1600 라이트 첫 화면](27-evidence/a-1600-light-branch.png), 막대 영역 (445,365)–(1083,602). 결석 18/132, 학습 30/3/117, 입실 3/2/145, 계획 31/4/115다. **숫자와 색은 있지만 ‘정상·주의·기록 없음’의 보이는 표지가 없다.** 작은 3명·2명 칸에는 숫자도 없다. 개별 칸 hover/focus 안내는 작동하므로 정확값 접근과 첫눈 이해를 구분했다.

[1명 예외 합성](27-evidence/bands-one-1280-light.png), [전원 결측 합성](27-evidence/bands-none-1280-light.png). 칸의 최소 폭·여백 때문에 1/150의 비율을 정확한 면적으로 읽을 수 없다. 미세한 집단을 누를 수 있게 하는 절충은 가능하되 면적을 정밀 비율처럼 해석시키지 않아야 한다. 단계 순서를 고정하고 막대 위 공통 짧은 단계 표지, 선택 칸의 값만 안내하는 편이 긴 설명보다 낫다.

실제 단계 선택 시험은 16조합 모두 학습 기준 넘음 30명→오도현 상세를 열었다(`bandCount=30`, `chosen=opened`). 데이터 규모를 요약하고 대상을 여는 골격은 승인한다. 신설된 단계 판정이 서버의 ‘상담 필요’와 같다는 승인은 아니다.

### E2. 작은 추이선 — 비교 단위와 결측, 접근 경로

E1 캡처 (1095,365)–(1215,600)의 선은 같은 높이로 크게 출렁여 보이나, 행별 최댓값으로 배율을 따로 정한다. 행 사이 진폭으로 규모를 비교하면 안 된다. 특히 결석·미제출의 오른쪽 숫자는 **7일 누적 일수 기준을 넘은 학생 수**, 선은 **그날 결석·미제출 학생 수**다. 두 값을 같은 ‘기준 넘음’으로 읽게 해서는 안 된다. 학습도 주간 합계, 입실도 주간 평균과 일별 기준 인원이 다르다.

[전원 결측](27-evidence/bands-none-1280-light.png)에서는 네 운영 지표 모두 150명이 기록 없음인데 선은 7일 0명이다. 실제 코드가 유효 관측 수 없이 조건 만족자만 센 결과다. [중간 사진 결측](27-evidence/trend-gap-1280-light.png), 비전의 x=60인 10/24 점이 없는데 한 `polyline`이 x=41.33에서 78.67로 연결된다. 결측을 건너뛴 연속 추세다. 학생 5주 선도 같은 연결 방식이다.

추이 SVG는 `role=img`의 전체 `aria-label`만 있고 Tab 대상·날짜별 hover/focus·선택 동작이 없다. 스크린리더가 읽을 수 있는 문자열을 화면 키보드 안내와 동등하다고 보지 않았다. 짧은 ‘일별 결석 인원’ 같은 측정명, 끝값/선택 날짜 한 값, 결측 구간 단절, 선택 시 그 날짜 결과 연결을 사용한다. 같은 수의 정의를 쓸 수 없는 주간 숫자는 별도 열 제목으로 구분한다.

### E3. 비전 첫 화면 — 휴대폰 한 축을 전체처럼 대표하지 않는다

E1 캡처 비전 행 (295,575)–(1512,602)의 제목은 ‘비전 관찰 (예시)’, 단계 28/34/88은 **학생별 7일 휴대폰 사용 비율의 20% 이상/10–20%/10% 미만**이다. 선은 **날짜별 사진 합산 휴대폰 비율**이다. 두 집계 모두 제목에서 알 수 없다. `10~20%` 표지도 경계 20% 포함 여부가 모호하다(실제 분기는 20% 이상을 별도 분류).

이 10/20%가 학습 위험이나 관리 개입 기준이라는 근거는 제공되지 않았다. 서비스 판정에는 쓰지 않는 구현이지만, 인접한 정상·주의·기준 넘음 막대와 같은 문법이므로 의미 오독을 막아야 한다. **이번 검토는 새 비전 관리 기준을 승인하지 않는다.** 가장 작은 수정은 ‘휴대폰 사용 관찰·사진 기준’으로 정확히 이름 붙이고 중립적인 비율 분포로 표시하는 것이다. 네 축은 눌러 펼치는 같은 위치에서 선택할 수 있어야 한다. 모든 축을 합산한 ‘비전 점수’를 새로 만들 필요는 없다.

사진 수신 0·분석 실패만·전부 축 미지원은 같은 ‘사진 없음’이 아니다. 현 `weekValue`는 모두 null이고 단계 이름은 사진 없음이다. 기록 상태를 분리하여 안내한다. 긴 네 문장을 첫 화면에 넣는 방식은 권하지 않는다.

### E4. 결석 행렬 — 날짜 충돌은 해소, 비결석 대상의 생략은 남음

[A 1280 라이트 행렬](27-evidence/a-1280-light-metric-absence.png), 날짜 (112,70)–(438,98), 학생 블록 (60,122)–(439,281). 날짜/요일 두 줄로 바뀌어 가로 충돌이 없어졌다. 결석의 연속 블록은 이 질문에 아령이나 선보다 적합하다. 이름과 날짜에서 개별 상세·일별 결과로 간다.

하단 (20,330)–(440,409)은 ‘결석 없이 미제출 2일 이상 17명’인데 이름 버튼은 첫 8명뿐이다. 결석 행의 ‘나머지 10명 보기’는 그 9명을 복구하지 않는다. 미제출 반복 대상 전체 목록으로 이어지는 인원 버튼이 더 단순하다. 또한 `rows.length - absent.length`를 ‘결석 없음’으로 쓰므로 전부 출결 미상인 학생도 포함한다. 확인된 무결석과 출결 미상을 나눠야 한다. 기본 결석 행 개수 제한 자체는 승인한다.

### E5. 날짜별 분포 — 원 겹침 수 0이 의미 보존을 뜻하지 않는다

[A 1280 실제 학습 그림](27-evidence/a-1280-light-metric-study.png), [C 1280 실제 그림](27-evidence/c-1280-light-metric-study.png). C의 날짜 그림 로컬 (447,128)–(919,184)에 `+인원`이 중앙값 띠·점과 겹친다. 아래 평균 행은 ‘입실/학생/평균’으로 꺾이고 1280에서는 날짜별 시간 글자도 서로 붙어 보인다. 그림 안 숫자를 늘려 밀집을 해결한 상태다.

[같은 값 150명·A 폭](27-evidence/focused-day-A-card-1280-light.png), 원래 1050개여야 하는 점 중 **354개**만 렌더된다(1600은 485개). C 534px는 418개, 넓은 910px도 809개다. 남은 수는 비활성 `+n` 글자이고 해당 학생을 점의 마우스·화살표 순서에서 제거한다. 날짜 전체 결과에서 다시 찾을 수 있지만 개별 점 보존의 해소는 아니다.

[넓은 같은 값](27-evidence/focused-day-wide-1600-light.png)은 1050점·원 겹침 0이다. 그러나 같은 0%가 **y=85.384–114.616px**로 퍼져 있다(참값 y=100). 220px 그림의 값 영역 116px에서 약 ±25.2%p의 가짜 차이다. `maxStack=0`을 줘도 초기 배치의 세로 이동이 남는다. C 높이 190의 값 영역은 더 작다.

[+250% 다수 극단](27-evidence/focused-rails-day-1280-light.png)에는 삼각형 809개만 남는다. 극단 모양의 실제 너비는 7px인데 작은 원의 배치 간격을 재사용한다. 같은 높이 삼각형의 가로 겹침만 세어도 215쌍(1600 넓은 그림은 296쌍)이다. 원 겹침 검사로는 검출되지 않는다. 강조/극단 학생 이름도 나오지 않는다.

더 나은 해결은 날짜 선택 후 **한 날짜를 넓게, 값은 가로축·학생은 세로 행으로 놓는 점 그림**이다. 150명이 같은 값이어도 행이 달라 값 좌표가 보존된다. 날짜 선택 앞에는 7일 중앙값·가운데 절반의 가벼운 요약을 둘 수 있다. 모든 학생 점을 7개의 좁은 열에 우겨넣는 비용보다 작고 기존 학생 결과를 재사용할 수 있다. +인원 묶음을 유지한다면 최소한 선택으로 전원을 열어야 하지만, 그것만으로 현 ‘학생마다 점 하나’ 기준을 충족한다고 판정하지 않는다.

### E6. 계획 미제출 막대 — 형태는 맞고 0·정확값만 고치면 된다

[B 1600 라이트 계획](27-evidence/b-1600-light-metric-plan.png), [0명 합성](27-evidence/plan-zero-1280-light.png). 인원을 막대 높이로 나타내는 선택은 적합하다. 단, 전원 제출인 0명에도 `height=1`이어서 7개의 양의 막대가 생긴다. 0은 기준선/날짜 선택 영역만 남긴다.

일별 ‘미제출·제출·대상’은 SVG 날짜의 `aria-label`에 있지만 보이는 안내 상자가 없다(`PlanBars`에는 안내 상태/렌더가 없음). 마우스와 키보드 초점에 같은 짧은 안내를 제공한다. 날짜 누르기→학생 전원 결과와 미제출 우선 정렬은 유지한다. 알 수 없는 제출 기록까지 정상 제출로 간주하지 않도록 유효 대상 수를 안내한다.

### E7. 비전 네 분포 — 축 분리는 보존, 사진 합산/학생 분포 안내는 불완전

[B 1600 다크 네 축](27-evidence/b-1600-dark-metric-vision.png), [2장 대 100장](27-evidence/focused-vision-weighted-1280-light.png). 고정 예제의 1/2·10/100은 사진 기준 11/102≈11%, 학생 비율 중앙값 30%로 올바르게 서로 다르다. 머리 숫자 11%, 가운데 선 30%의 **정체를 선택 안내에서 분리**해야 한다. 현재 날짜 안내는 학생 수·중앙값·가운데 절반만 주며 사진 합산 관찰/분모·판단 불가·실패 전체를 제공하지 않는다. 미지원은 별도 긴 날짜 나열로 떨어져 있다. 학생 점 안내도 일부 실패 사진이 있는 정상 분석일의 실패 수를 생략한다.

표본에 따른 크기 변화와 10장 미만 빈 원은 생겼다. 고정 두 표본의 반지름은 약 1.695/2.6px로 달라진다. 다만 밀집 배치에서 반지름 상한이 작아져 큰 표본끼리는 비슷해진다. 이를 정밀 신뢰도 척도로 해석하지 않는다. **크기·빈 원 추가 자체는 N03 개선으로 인정**하며, 실패/분모 안내와 E5의 값 이동을 그대로 통과시키지는 않는다.

선택한 축·날짜의 안내 한 곳에 사진 합산 관찰/분모, 학생 수·중앙값·가운데 절반, 판단 불가·실패·미지원/사진 없음의 구분을 두면 된다. 본문에 긴 산출식을 추가할 필요는 없다.

### E8. C 주간 분포 — 동률·극단과 정확값

[C 1280 학습](27-evidence/c-1280-light-metric-study.png), 주간 그림 로컬 (20,80)–(374,210). 실제 자료의 150개 원 겹침은 두 폭 모두 0으로 개선됐다. 그러나 [150명 동률](27-evidence/focused-week-equal-1280-light.png)은 98점과 `+52`만 남고 값축도 이동한다. [전원 +250%](27-evidence/focused-rails-week-1280-light.png)는 150명 중 23개의 삼각형만 남으며 총 인원 글자에서 전체 학생을 열 수 없다.

실제 화살표 안내는 ‘오도현 · −69%’뿐이다. 학습 실제·평소 합계, 입실 요약의 분 단위 원값, 비전 관찰/분석 장수가 없다. C 설정 연동도 불일치한다: 주간 결석 강조는 2일, 미제출은 3일로 고정이며 입실 강조는 설정의 절반이다. 실제 학습관 단계의 설정 기준과 같은 ‘기준 넘음’으로 읽을 수 없다. 서버 관리 상태 조건까지 붙어 있어 단순 임계값 초과 인원과도 다르다.

연속값은 E5의 학생 행 점 그림으로 재사용하고 정확값 안내를 붙이는 편이 낫다. 결석·미제출은 0–7일 범주에 선택 가능한 인원 열을 두는 대안도 있으나, 그 대안을 채택할 때는 개별 학생 점 요구와 C 구조 설명을 함께 정리해야 한다. 날짜 분포를 복제한 작은 그림을 추가하는 것이 목적이 아니다.

### E9. 학생 요약 — 학습 비교는 유효, 입실·결측·안내가 취약

[A 실제 상세](27-evidence/a-1600-light-detail.png), 요약 (286,441)–(1358,778). 학습 실제 6시간 7분·−69%, 평소 길이와 기준 눈금은 감소를 빠르게 보이게 한다. 회색 띠는 **평소 주 한 값까지의 막대**이며 관측 변동 범위가 아니다. ‘평소 범위’를 표현했다는 성과 주장은 할 수 없다.

[−60분 입실](27-evidence/student-early-1280-light.png)에서 값 길이는 0이다. 실제 권유진도 ‘평소보다 7분 이름’인데 막대는 빈다. 0 중심의 좌우 차이점/막대를 쓰고 ‘60분 일찍’처럼 자연스러운 말을 쓴다. 같은 줄의 5주 선은 절대 평균 입실 시각이고 막대는 평소와의 평균 차이다. 동일 값인 듯 병치하지 말고 같은 비교량으로 통일하거나 짧은 측정명을 구분한다.

[학생 결측](27-evidence/student-missing-1280-light.png)은 출결·제출 전부 unknown인데 결석 ‘0일 / 예정 0일’, 미제출 ‘0일’, 5주 결석/미제출은 0의 선이다. 학습·입실처럼 모름을 빈 상태로 두어야 한다. 진행률 null은 무조건 ‘계획 없음’이므로 계획은 있지만 실제 기록을 모르는 경우도 잘못 명명한다.

[큰 값](27-evidence/student-extreme-1280-light.png)은 진행률 300%를 150%에서 잘라 같은 가득 찬 막대로 만든다. 날짜별 진행률처럼 초과 기호와 정확값으로 경계를 알려야 한다. 새 주간 막대·5주 선은 모두 Tab 대상이 아니다. `audit.json` 16조합에서 막대 `.focus()`도 실패했다. 마우스에는 평소 주·기준 안내가 나오지만 키보드 사용자는 같은 값을 못 본다. 주별 기간/값도 `aria-label` 외에는 접근할 수 없다. **날짜별 보기 버튼이 있다는 이유로 요약의 정확값 요구를 면제하지 않는다.**

### E10. 달력·과목 — 7일 제출 정보의 새 누락

[D 1280 학생 상세](27-evidence/d-1280-light-detail.png), 달력 (276,599)–(547,809), 과목 (760,600)–(1145,752). 달력의 결석·예정 없음·출결 미상, 화살표 날짜 안내는 적합하다. 하지만 최신 `StudentFull`에서 7일 출결/제출 줄이 사라졌다. 35일 달력은 미제출을 hover/focus 글자에만 붙이고 제출/미상/예정 없음은 구별하지 않는다. 최근 7일도 그림에서 별도 표시되지 않는다. **날짜별 펼침에도 이 줄은 없다.**

보존할 기능은 7일 모든 상태다. 달력 최근 7일에 얇은 경계와 미제출 밑선, 제출 상태별 안내를 추가하거나 날짜별 펼침에 짧은 7칸 줄을 복구하면 된다. 35일 날짜 숫자를 전부 상시 출력할 필요는 없다.

[과목 결측 합성](27-evidence/calendar-subject-1280-light.png)은 null 계획/실제 비중에 각각 0% 원을 그리고 안내도 0.0%라고 말한다. ‘실제만 있는 과목’에는 null 계획을 0%로 바꿔 +100%p 차이를 생성한다. null은 해당 원/연결선을 생략하고 모름을 안내해야 한다. 두 값이 있는 과목의 아령 형태는 유지한다.

### E11. 날짜별 세부 — 학생 비전의 이전 오답은 해소

[A 1280 날짜별 뷰포트](27-evidence/a-byday-viewport-1280-light.png), [B 다크](27-evidence/b-byday-viewport-1280-dark.png), [고정 비전 상태](27-evidence/focused-vision-states-1280-light.png). 날짜별 아령·진행률·비전은 접힌 상세에 배치하는 것이 맞다. 실제/평소 학습 분, 입실 시각·차이, 진행률 계획/실제, 네 비전 축·7일 합 장수는 hover/focus·화살표 안내를 유지한다.
