# 학생 케어 개선안 2차 기능 심사

2026-11-07. **V01·V03·V06은 부분 해결, V02·V04·V05·V07·V08은 해결로 판정한다.** 개인값·대상 명단·전체 이력·빈 상태 복구는 확인했다. 그러나 개인 변화의 동시 비교, 명부의 정확한 시간 비교, 390px 상세 가독성은 남았다. 새로 추가된 학습관 목록에는 결석 인원 오표기와 모바일 열 배치 문제가 있다. 이 의견은 다음 수정에 반영하며 **진행을 막는 판정이 아니다.**

## 4. 새 문제와 수정 부작용

### N1. nowrap만으로 390px 읽기 문제를 옮김 — P0

V06의 핵심이다. [모바일 라이트](11-evidence/mobile-detail-light.png)와 [다크](11-evidence/mobile-detail-dark.png)에서 날짜 `10/2110/22…`, 시각 `18:3918:30`, 실제/계획 문자열이 붙거나 중첩된다. ‘평소(같은 요일)’ 행 제목도 여러 줄로 길어져 열 대응이 어렵다. 문서 scrollWidth가 viewport를 넘지 않는 것으로 가독성을 통과시키면 안 된다. 날짜별 최소 폭을 확보한 내부 가로 탐색 또는 좁은 화면용 날짜 묶음이 더 직접적인 대안이다. 값 자체를 다시 숨길 필요는 없다.

### N2. 결석 목록 제목이 미기록 학생까지 결석 인원으로 셈 — P1

강남 → 학습관별 → 결석 지표 이름: **‘결석 최근 7일 28명’**, 원자료는 결석 학생 **18명 + 결석 없고 기록 없음인 학생 10명**이다. `10/22 결석 학생 보기`는 **‘결석 10/22 14명’**인데 목록은 결석 **4명 + 기록 없음 10명**이다([followup.json](11-evidence/followup.json)).

원인은 `OpsBranch.tsx:40`의 `n>0 || unknown>0`와 `:91`의 전체 행 개수다. 셀 자체는 결석·기록 없음을 구분하지만, 펼친 제목이 이를 합친다. ‘결석 4명·기록 없음 10명’처럼 따로 세면 충분하다. 추가로 `:41`이 만든 ‘기록 없음 N일’ 보조 값은 헤더가 두 칸이라 `:95`의 slice에서 탈락한다. 실제 원자료를 바꾸거나 서버 신호를 추가할 필요는 없다.

### N3. 학습관 칸은 눌리지만 결과 발견과 모바일 읽기가 불편 — P1

**동작하는 부분:** 버튼 32개, 날짜 버튼 최소 **80×44px**, 마우스 클릭·Enter·Space 모두 결과 전환 확인. `aria-pressed`, 이름과 focus-visible 스타일도 있다. 작은 터치 표적이나 키보드 작동 불가로 판정하지 않는다.

**남은 문제:** `all:unset` 기반 평문 숫자여서 선택 전에는 버튼임을 드러내는 단서가 약하다(`ops.css:172`). 시각 단서가 실제 발견 시간을 늦추는지는 사람 시험이 필요하다. 확정 관측은 다음과 같다.

- 390px에서 마지막 날짜 계획 칸 클릭 후 표 폭 **316px / 내용 738px / scrollLeft 422px**. 왼쪽 지표 이름이 화면 밖으로 사라진다. 날짜·행 제목을 고정하거나 선택한 날짜/지표를 보이는 위치에 유지할 필요가 있다(`ops.css:126`).

## 5. 저장 실행 검증과 DB 복원

### 복원 사전·사후 실행

`bash scripts/research/care-db-state.sh restore initial`을 실행했다. 기본 `bash`는 WSL `E_ACCESSDENIED`로 실행 실패하여 설치된 **Git Bash**로 같은 스크립트를 다시 실행했다. Git Bash 결과는 **exit 1**:

```text
Error loading config file: open C:\Users\green\.docker\config.json: Access is denied.
... open //./pipe/docker_engine: Access is denied.
```

`docker cp` 단계에서 실패해 restore SQL 실행까지 도달하지 못했다. 권한 확대가 불가능한 실행 환경이며 권한 우회를 시도하지 않았다. 각 audit의 finally에서도 같은 restore를 호출했고 마지막 `rerun.json.restoreAfter.status`도 **1**이다. **원복 성공이 아니다.** 사전 복원 실패를 확인한 뒤 실제 DB 변경을 피했으므로 이 심사가 만든 시험 데이터를 남기지는 않았다.

### 개선안 브라우저에서 실제로 누른 저장

서버로 보내기 직전 POST/PUT을 가로채 **503**으로 응답했다. 다음은 DB 저장 시험의 대체 성공 결과가 아니라 **UI·요청 경로 검증**이다. 원문은 `rerun.json.writes`와 `results`에 있다.

| 과업 | 브라우저 조작 / 수집한 요청 | 확인된 결과 | 실제 저장·재조회 |
|---|---|---|---|
| 상담 신규 | 강하준(`demo_s055`) 선택 → 면담·내용 입력·계속 관리·저장. `POST /cases`: branch `demo_large`, reason `ADJUSTMENT_NEEDED`, recheckDate **2026-11-04**(업무일 10/28 + 7일) | 요청 생성 1회, 503 오류가 상담 폼에 보임. 성공 상태로 바뀌지 않음 | **미검증**. 서버 전송 0회 |
| 관리 중 노트 | 초기 `inAdjustment[0]` 학생 선택 → 면담·내용·저장. `POST /cases/{caseId}/notes?branchId=demo_large`, channel `MEETING`, content 입력문 | 기존 건에 notes 요청 1회, 오류 표시 | **미검증**. 서버 전송 0회 |

쓰기 차단 후 API board와 settings를 다시 GET했고 각 audit의 시작 응답과 종료 응답이 동일했다. 이는 **변경되지 않았음**을 확인한 것이며 저장 후 영속성 검증이 아니다. 이번 판정으로 상담·노트·설정이 고장났다고 단정하지도 않는다. 실제 저장 성공/재판정/이력 반영은 복원이 가능한 환경에서 후속 실행해야 한다.

## 6. 우선순위 순 수정 요청

1. **P0 — 390px에서 날짜·시각·실제/계획이 서로 침범하지 않게 한다.** nowrap 유지 여부보다 열의 최소 읽기 폭을 먼저 확보한다. 허용된 내부 가로 스크롤이나 날짜 단위 묶음 중 단순한 방식을 택하고, 라이트·다크에서 긴 값까지 확인한다. 학생 선택 도착 위치에는 헤더 여백을 두어 복귀 버튼이 즉시 보이게 한다. 범위: V06/N1.
2. **P1 — 결석과 기록 없음의 제목·인원을 분리한다.** 10/22는 ‘결석 4명 / 기록 없음 10명’, 7일은 결석 18명과 미기록만 있는 10명을 혼동하지 않게 표시한다. 잘리는 보조 셀도 헤더와 맞춘다. 서버나 원자료 수정 없이 가능하다. 범위: N2.
3. **P1 — 학습관 결과 목록의 모바일 열과 이동 경로를 고친다.** 학생/실제/평소/차이의 최소 폭·행 높이를 보장하고, 오른쪽 날짜 탐색에도 지표·날짜 문맥이 남게 한다. 칸 선택 후 결과로 가는 짧은 경로를 제공한다. 버튼 자체 크기는 현재 80×44px 이상이므로 별도 큰 버튼 32개를 더 만들 필요는 없다. 범위: N3.
4. **P1 — 개인 변화·명부 정밀도 비교의 남은 축소를 정리한다.** 150개 그래프 재도입 대신 소수 학생 고정 비교나 동일 날짜 축의 간단한 값 배열 등으로 두 학생의 날짜 변화 비교를 보존한다. 명부 주합은 분 단위 또는 정확값을 가까이 읽을 수 있게 한다. 추가 상태·조작 비용을 함께 재측정한다. 범위: V01/V03.
5. **P1 — 실제 쓰기 검증을 재실행한다.** Docker 복원이 되는 환경에서 initial 복원 성공 확인 → 개선안 상담 신규·관리 중 노트·설정 1항목 저장 → 새 GET/새로고침으로 상태·이력·설정 확인 → 설정 원복 → 최종 지정 restore 성공을 기록한다. 현재 환경 제약을 UI 성공이나 제품 결함으로 치환하지 않는다.
6. **P1/P2 — 부분 자료·연속 단위·기능표를 짧고 정확하게 정리한다.** ‘관측 4/7일 부분 합’, ‘등원 예정일 기준 연속’처럼 필요한 위치에서만 표기한다. 기능표의 최근 5건/매주/그날 계획 없음 등을 실제 코드에 맞춘다. 안내 문구를 모든 행에 반복 추가해 텍스트를 더 늘리지 않는다.
7. **P2 — 복구 후 열린 상태까지 재측정한다.** 범례를 명부 처음에서도 이해할 수 있게 하고, 학습관 날짜 선택 136명·소규모 자동 상세·모바일 왕복을 포함해 측정한다. 3,045자→2,800자 달성을 위해 값이나 학생을 삭제하지 않는다. 운영자 이해 속도 향상은 가설로 남기고 동일 과업의 오류·시간·조작 수로 확인한다.
