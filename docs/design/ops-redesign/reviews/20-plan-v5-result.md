# 학생 케어 5판 계획 검토

검토일: 2026-11-07. 대상: `plan-v5.md`. **총점 76/100, 필수 지적 7건으로 불통과다. C는 현재 제안 거부, D는 조건부 승인이다. 이 결과는 A–D 구현 착수 승인이 아니다.** 계획을 고쳐 필수 지적이 해소됐는지 재검토받아야 한다.

점수는 아래 근거에 따른 검토자의 판단이며 객관적인 사용성 측정값이 아니다. 계획의 결함과 아직 만들지 않은 화면의 결함을 구분했다. 이하 행 번호는 이번 검토 시점의 `plan-v5.md` 기준이다.

## 1. 항목별 점수와 근거

### 1.1 사용자 피드백·결정 반영 — 20/25

사용자 피드백 1–6과 A–D 네 안, 비전·과업 시험 전안 적용, 전안 93점·필수 위반 0건을 명시했다. P1–P5도 4판에서 실패한 상세 폭, 학습관 목적, 내부 스크롤, 범례 의존을 정확히 겨냥한다. A의 원본 보존과 B의 큰 모달은 이번 결정에 맞는다.

감점은 선언과 실행 규칙의 충돌 때문이다. 29행의 ‘계획 통과 후 구현’과 88행의 ‘3회 불통과면 진행’은 함께 적용할 수 없다. C의 작은 숫자 표만으로 구성한 학습관 현황, D의 전체 폭 그래프 사이로 열리는 학생 표는 사용자가 지적한 학습관 지표의 약화·밀려남을 반복할 위험이 있다. 위험을 금지하는 P2는 있으나 안별로 어떻게 피할지는 부족하다. 과거 96점 통과를 이번 목적 충족의 증거로 재사용하지 않은 점은 적절하다.

### 1.2 네 안의 구분과 타당성 — 19/25

A는 기존 표와 행 펼침, B는 명단과 모달, C는 사유 중심 업무 목록과 서랍, D는 학습관 우선 화면과 학생 전용 화면이다. 명부 표현만 바꾼 4판의 변형과 달리 주된 탐색 구조가 구분된다. B와 C가 같은 상세·폼을 재사용하는 것 자체는 자가복제가 아니다. 전체 구조와 주요 과업 동선이 달라야 한다.

다만 B 첫 화면은 비교표에서 ‘이름·반·상태·사유만’, 본문에서는 학습 시간·진행률도 포함한다고 달리 적었다. C는 사유가 여러 개인 학생의 중복, 기록만 추가한 학생과 재확인을 마친 학생의 차이, ‘오늘 처리함’의 근거가 정해지지 않았다. 학습관 표현을 B와 다르게 보이게 하려고 그래프를 없애는 것은 사용자 목적에 대한 근거가 아니다. D의 방향은 적합하지만 그래프 다섯 개를 세로로 늘어놓는 것만으로 전체 지표가 쉽게 식별된다고 보장할 수 없다.

### 1.3 기능·지표 보존과 데이터 의미 — 16/20

공용 모델로 날짜 정규화·사유·분포 계산을 통일하고 API·DB·판정을 유지하는 선택은 적절하다. 비전의 네 축 독립, 사진 표본 분모, 예시 표시, 판정·사유·관리 정렬 제외, 합 규칙도 명시했다. 이는 실제 비전 서비스 연결 승인이 아니라 프론트엔드 예시의 의미 보존 계획이다.

감점 사유는 다음과 같다. 기존 `function-map.md`는 `/ops` 한 안의 대응표로, A–D별 경로와 실행 검증표가 아니다. 특히 복수 학생 비교, 제외·복원, 전체 이력, 재확인은 새 네 구조에서의 접근 방법이 구체적이지 않다. C의 처리함은 기존 관리 상태와 혼동될 수 있다. 비전 학습관 비율의 집계식·0분모·동률·관측 학생 수가 미정이며, 초안이 요구하는 unknown·실패·미지원 축을 화면에서 어떻게 확인하는지도 충분히 고정하지 않았다. 공용 생성기의 합 규칙만으로 화면 의미와 집계 정확성까지 증명할 수는 없다.

### 1.4 검증 설계 — 12/20

P3·P4 측정 추가, 열린 상세 상태 검사, 1280px 추가, 네 안 독립 채점, Q16·Q17 추가는 개선이다. 그러나 이번 계획에서 가장 약한 부분도 검증이다.

- P3의 정상 모달 허용 규칙과 ‘페이지 외 스크롤 0개’라는 측정 기준이 충돌한다. 현행 probe는 `main` 밖 대화상자를 세지 않으며 배경 잠금을 검증하지 않는다. 아래 합성 시험으로 재현했다.
- Q3·Q4의 ‘표시’ 해석 문제와 기존 1회·개선 반복 시험 문제는 14차 보고서에서 이미 확인됐다. 125점 기준과 한계 고지만 유지하면 문제가 해결되지 않는다.
- 기존 만점 문항 보존과 총점 하한은 퇴보 방지 장치다. 학습관의 여러 지표를 구분하고 분포를 읽고 학생 상세로 이어지는 핵심 목적을 직접 통과시키는 과업이 부족하다. 기존 Q13의 학습 시간 변화 한 문항으로 전체 목적을 대체할 수 없다.
- ‘기존보다 나빠지지 않음’의 비교 상태·지표별 적용 범위가 미정이다. 비전 정보와 직접 단위를 더한 화면에 전체 글자 수를 일괄 적용하면 다시 값을 숨기거나 압축할 유인이 생긴다.
- Q16·Q17의 정확한 문항·채점 규칙이 없고 생성기로 만든 정답을 생성기 검증의 독립 근거로 쓸 위험이 있다.

93점이라는 문턱 자체를 낮출 이유는 없다. 문제는 그 점수를 부여하기 전에 반드시 확보해야 할 목적별 증거가 고정되지 않았다는 점이다.

### 1.5 실행 가능성·범위 — 9/10

프론트엔드 범위, 별도 네 경로, 공용 계산과 기존 저장 컴포넌트 재사용, 백엔드·원본 화면 보존은 실행 가능하다. 네 안은 사용자가 요구했으므로 수량 자체를 과설계로 감점하지 않는다. 비전·측정 장치를 먼저 준비하고 전안을 최종 심사하는 순서도 타당하다.

다만 공용 모델 ‘이동’이 비교용 `/ops`의 import와 테스트를 바꿀 수 있으므로 기존 경로 재수출 등 회귀 방지 방법을 정해야 한다. 네 개의 독립 업무 상태 모델이나 범용 대시보드 프레임워크까지 만들 필요는 없다. 단계 2·3의 구현 전, 네 안의 주요 화면 상태를 간단히 확인하는 중간 관문이 비용을 줄일 가능성이 있다.

## 2. 필수 지적 — 수정·재검토 전 구현 금지

### M01. 계획 불통과 상태의 자동 진행을 제거할 것

근거: 24·29·88행. 현재 사용자 지시는 C·D를 검토자가 승인해야 구현한다는 것이다. 이전 작업의 예외를 인용해 이번 승인 조건을 무효화하면 안 된다.

해소 조건: 88행을 ‘불통과 시 지적 수정 후 재검토, 필수 지적이 남으면 구현하지 않음’으로 정리한다. 반복 심사 비용은 지적별 수정 대조표로 줄일 수 있지만 횟수로 승인을 대체하지 않는다. 점수가 85점 이상이어도 필수 지적이 남으면 불통과임을 유지한다.

### M02. C의 ‘오늘 처리함’을 기존 상태와 분리하고 사유 중복을 정의할 것

근거: 60·68행, `CounselForm.tsx`, API 계약 §65-4·65-6·65-7. 상담 신규 저장은 계속 관리 또는 종료가 될 수 있고, 관리 중 상담 노트 저장은 재확인 결정과 다르다. 모두 저장 직후 같은 ‘처리함’으로 보내면 확인일이 된 업무까지 완료로 오인할 수 있다. 기존 API에는 C 전용 처리 상태가 없다.

해소 조건:

- 학생을 사유별로 여러 번 그릴지 한 번만 그릴지, 인원은 학생 중복을 제거하는지 명시한다. 권고는 학생 한 줄에 관련 사유를 함께 두고 사유별 필터를 제공하는 방식이다.
- 가장 단순한 수정은 별도 처리함 상태를 없애고 성공 후 board 재조회 결과의 관리 상태·다음 확인일을 표시하는 것이다.
- 처리함을 유지하려면 ‘오늘 기록함’ 같은 작업 표시로 한정하고 근거·수명·새로고침·지점 변경 동작을 적는다. 서버 관리 상태를 덮어쓰거나 노트 저장만으로 미완료 재확인을 감추면 안 된다. 저장 실패·409도 이동시키지 않는다.
- 서랍은 좁은 보조 칸이 아니라 7일 값·단위·폼을 읽을 폭을 확보하고 1280px에서 검증한다. 미저장 입력을 둔 채 학생 변경·닫기를 할 때의 동작도 정한다.

### M03. 안별 학습관 목적과 기능 보존 경로를 구체화할 것

근거: 38·44·64–70행, `plan.md` 2장, `function-map.md` B1–B4·D7, 기존 G06–G17·G21·G27–G33. ‘공용 컴포넌트 사용’은 접근 경로와 상태 전이의 실행 검증을 대신하지 못한다.

해소 조건:

- 기존 기능 ID마다 A–D의 실제 위치·접근 경로·검증 방법을 적는다. 전원 개인 값, 복수 학생 7일 비교, 제외·복원, 전체 이력, 재확인 처리도 포함한다. 비교 방식 변경은 허용할 수 있으나 기능 삭제로 처리하지 않는다.
- C의 ‘작은 숫자 표, 그래프 없음’을 그대로 승인하지 않는다. 학습관 현황에는 날짜별 변화, 개인 평소 대비 분포, 큰 변화 학생을 식별할 표현과 실제·평소·정확값 접근을 명시한다. 표를 보조로 쓰되 4판의 숫자표 중심 문제를 다시 만들지 않는다.
- A의 ‘학생 표를 한 곳으로’는 모든 카드 아래 멀리 떨어진 공통 상세로 이동하는 뜻인지 명확히 한다. 선택 지표·날짜와 결과의 관계가 바로 보이고 다른 지표 접근이 유지돼야 한다.
- B의 ‘짧게 열린다’가 일부 학생 삭제·상위 몇 명만 제공하는 뜻이 아니게 한다. D는 첫 지표의 학생 150행이 뒤 지표를 밀어내지 않도록 전체 요약과 결과 영역의 관계를 고정한다.
- D에도 정상·기록 부족 학생을 포함한 전원 명부의 진입 경로와 인원을 둔다. 이름을 아는 학생 검색만으로 전원 명부 보존을 대신하지 않는다.

### M04. P3·P4 측정의 판정 대상과 반례를 수정할 것

근거: 39–40·76행, 현행 `care-screen-metrics.mjs`의 probe, [합성 시험 결과](20-evidence/probe-fixtures.json).

같은 대화상자 스크롤이 `main` 안에서는 `scrollAreas=1`, 밖에서는 `0`으로 나왔다. 배경이 잠긴 단일 모달 스크롤은 P3상 허용인데 76행의 ‘페이지 외 0개’로는 실패한다. 반대로 `overflow:hidden`으로 값이 잘려도 `hScrollAreas=0`, 문서 `overflow=false`다. P4의 잘림 금지는 가로 스크롤 수 하나로 검증되지 않는다.

해소 조건: 일반 화면은 페이지와 콘텐츠 내부의 중첩 스크롤을 금지하고, 모달·서랍은 배경 스크롤 잠금 + 활성 콘텐츠의 스크롤 한 곳을 허용하도록 분리한다. 포털을 포함한 활성 화면 전체를 검사한다. 1600/1280/850/390의 기본·상세·학습관 결과·비교·설정 상태에서 배경 스크롤, 내부 중첩, 가로 넘침과 값 잘림을 각각 확인한다. 정상 모달·배경 미잠금·중첩 스크롤·포털·숨김 잘림을 양성/음성 시험에 넣는다. 측정 대상은 가려진 배경이나 단순 DOM 존재와 구별한다.

### M05. 과업 시험과 최종 필수 관문이 사용자 목적을 직접 검사하게 할 것

근거: 76–80행, `task-test.md`, `14-final-result.md` 1.2절. 한계를 기록하는 것과 비교 오류를 통제하는 것은 다르다.

해소 조건:

- 시험 전에 Q3·Q4가 서버 관리 사유를 묻는지 날짜별 기준 초과를 묻는지 고정한다. 둘 다 필요하면 별도 문항으로 분리한다. 고친 문항은 기존 화면도 같은 조건으로 다시 시험하고, 동일한 기록기·데이터·시험 예산을 사용한다. 최초 결과와 수정 후 결과를 구분하고 한쪽의 최고점만 골라 비교하지 않는다.
- 학생 선택 → 해당 학생의 7일 지표 종합 확인 → 기록·다음 확인 → 원래 위치 복귀를 전안에서 수행한다. 학습관은 날짜별 전체 상태와 분포 → 여러 변화 학생 식별 → 정상 개인 차이와 구별 → 학생 상세 → 필터·선택 복귀를 수행한다. 비전은 두 흐름에 실제로 포함한다. 자동 스크롤·내부 이동까지 조작 로그에 남긴다.
