### N01. 분포의 좌표·개별 학생·극단 대상 보존 — 공통, P5 (S01·S02 잔여)

[같은 값 150명, 넓은 그림](26-evidence/focused-day-wide-1280-light.png), [A 실제 430px 폭](26-evidence/focused-day-A-card-1280-dark.png), [C 실제 534px 폭](26-evidence/focused-day-C-card-1280-light.png), [C 주간 동률](26-evidence/focused-week-equal-1280-light.png), [다수 일별 초과](26-evidence/focused-rails-day-1280-dark.png), [다수 주간 초과](26-evidence/focused-rails-week-1280-light.png).

문제는 세 가지다.

1. **겹침:** A 1280의 1050원은 고유 중심 817·겹침 3995쌍, C 날짜는 고유 중심 967·537쌍이다. C 주간은 동률 150원의 중심은 150개여도 원끼리 62쌍 겹친다. 실제 데이터에서도 C 주간 113/120쌍이 겹친다. `packFit`의 반환 반지름과 실제 그리는 2.4px 반지름이 다른 것이 주간 겹침의 원인이다.
2. **값 왜곡:** 겹침 0인 넓은 그림도 통과할 수 없다. 같은 값 0%인데 값 축으로 크게 이동한다. C 1280에서 0의 원래 y=85, 실제 y=44.98–125.02다. ±100%/86px 축에서 약 +93%~−93%처럼 보이는 배치다. A 1600도 약 ±60–70% 폭으로 퍼진다. `packFit`이 공간 부족을 값 축 이동 최대 약 40px로 해결하므로, tooltip 숫자만 맞는 것으로 모양의 오류를 상쇄할 수 없다.
3. **극단·식별:** 150명 전부 +250%일 때 일별 1050삼각형은 고유 경로 1280=576개, 1600=766개로 포개진다. C 주간은 150원이 중심 9개로 겹친다. 주간 초과점은 일반 원이고 관리/극단 학생 이름도 상시 최대 3명+나머지 인원이 아니라 모두 사라졌다. 이름 충돌을 고친 대신 원래 약속을 삭제했다.

완료 조건: 실제 A–D 배치 폭·두 테마에서 값 좌표와 동일값의 의미를 지키고, 150명·다수 초과를 가리거나 경계의 정상값처럼 그리지 않는다. 필요한 폭/확장 상태를 확보하고 극단 묶음의 방향·인원·대상 선택 경로를 제공한다. 극단·관리 대상 이름은 충돌 없이 최대 3명/나머지 인원, 또는 선택한 대상에 표시하는 구체적 배치를 마련한다. 숫자·이름을 전원에게 붙이는 방식은 승인하지 않는다.

### N02. 화면에 보이는 hover·focus 정확값 경로 마무리 — 공통, P5·P8 (S03 잔여)

[실제 학생 점 키보드 안내](26-evidence/c-keyboard-point-1280-dark.png), [학생 비전 안내](26-evidence/b-vision-focus-1280-dark.png), [조작·속성 기록](26-evidence/audit.json).

- 학생 7일 출결/제출 칸은 포커스 대상 0개다. 10/22 ‘입실·계획 제출’, 10/24 ‘결석·계획 미제출’은 `title`에서만 확인한다. 모양의 짧은 선이 있어도 날짜별 제출 상태를 키보드로 읽을 길이 없다.
- 일별 분포 날짜에 hover/focus해도 표시되는 안내는 빈 배열이었다. 유효 인원·중앙값·가운데 절반은 `aria-label`에만 있다. 화살표를 누르면 학생 실제·평소·차이 안내는 잘 나오지만 사분위 범위를 보여 주지는 않는다. 스크린리더 접근 개선은 인정하지만 일반 마우스/키보드 사용자의 정확 범위 확인을 대신하지 않는다.
- C 주간 점 안내는 이름+반올림된 변화/비율뿐이다. 주간 실제·평소 합계나 비전의 관찰·분석 장수에 같은 지점에서 도달하지 못한다.

완료 조건: 날짜 단위 제한된 탐색으로 마우스와 키보드 모두 같은 원단위 값·상태·분포 통계에 도달한다. 학생 제출 7칸도 한 Tab+화살표 방식 등을 사용한다. 모든 숫자를 상시 노출하거나 1050개의 Tab 정지를 만들지 않는다.

### N03. 비전의 상태·표본·분모를 모양과 안내에서 일치시킨다 — 공통, P5·P6·P8 (S04·S02 잔여)

[판단 불가 100%·관찰 0 반례](26-evidence/focused-vision-states-1280-light.png), [1장/20장 동일 반지름](26-evidence/focused-vision-samples-1280-light-all.png), [사진 가중 비율 반례](26-evidence/focused-vision-weighted-1280-light.png), [실제 학생 비전](26-evidence/c-detail-vision-1280-dark.png), [계산값·CSS 실측](26-evidence/focused.json).

- 판단 불가 10/10장·관찰 0인 칸(10/24)이 관찰 100%처럼 단색으로 찬다. `unknownBackground`와 `yesBackground`가 둘 다 light `rgb(78,89,104)`이며 `background-image:none`이다. `.v5-vision-bar span`의 배경 선언이 판단 불가 빗금보다 우선한다. 또한 `Math.max(3, …)` 때문에 관찰 0도 양의 막대를 갖는다. 모양 우선 화면에서 핵심 의미 오류다.
- 10장 미만 빈 원은 정상 작동한다(합성 한 축 7개 빈 원). 하지만 1장/20장, 2장/100장의 점 반지름은 각각 같은 값이다. 요구된 ‘점 크기=분석 장수’는 구현되지 않았다.
- 학습관 네 축 머리의 사진 합산 비율은 고쳐졌지만, 축별 합산 분모·판단 불가·실패·무자료 학생의 확인이 불완전하다. 점 안내는 유효 학생의 관찰/분석/판단 불가, 결과 표는 그날 유효 학생만 보여 준다. 실패만/사진 없음/전부 미지원으로 점과 결과에서 빠진 대상을 이 경로로 구별할 수 없다. 휴대폰 요약의 사진 장수 안내만으로 네 축 전체의 요구를 충족하지 않는다.
- 5항목 범례·해독 문장의 상시 노출도 표현 기준에 맞게 정리해야 한다. 상태 구분을 없애고 글자만 줄여서는 안 된다.

완료 조건: 관찰 0은 0으로, 판단 불가는 독립된 빗금/구획으로 보이고 100%/혼합 비율이 왜곡되지 않는다. 네 축의 분모·관찰·판단 불가·분석 실패·미지원·사진 없음에 hover·focus/선택 안내로 도달한다. 분석 장수 크기·10장 미만 빈 원을 함께 충족하며 범례는 짧게 제한한다. 1/2+10/100, 실패만, 전부 미지원, 미지원 혼합, 관찰 0/판단 불가 100% 반례를 실제 화면에서도 재확인한다.

### N05. B·C에서 미저장 버리기 후 문서 스크롤을 복구한다 — B·C, P3·P8 (S06 잔여)

[B 복귀 화면](26-evidence/b-after-discard-1280-dark.png), [C 복귀 화면](26-evidence/c-after-discard-1280-dark.png), [독립 재현](26-evidence/discard.json), [두 폭·테마 재현](26-evidence/modal-complete.json).

학생 팝업/서랍 → 상담 임시 입력 → 닫기 → ‘버리기’로 두 창을 닫으면 B·C는 `<html>`의 `overflow-y:hidden`이 남는다. 명부는 높이 5983px, 열린 dialog/alertdialog는 0개인데 휠 500px을 보내도 `scrollY=0→0`이다. 두 폭·테마 총 8조합에서 재현했다. 같은 절차의 A·D는 `overflow-y:visible`, 휠 후 0→400으로 복구됐다. 열린 확인창 안의 잠금/포커스만 시험하면 이 회귀를 놓친다.

완료 조건: ‘계속 작성’은 학생 창의 잠금을 유지하고 ‘버리기’로 학생 창까지 닫으면 문서 스크롤을 되돌린다. 두 창의 독립적인 overflow 복원이 이전 `hidden`을 다시 남기지 않게 수명을 맞춘다. 문서/학생 창의 위치·포커스 복원을 함께 확인하고 B·C 두 폭·테마에서 실제 휠로 재검증한다.
