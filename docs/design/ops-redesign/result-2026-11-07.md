# 학생 케어 개선안 결과 (2026-11-07)

기존 학생 케어(`/student-care`)는 그대로 두고, 같은 API·판정·저장 기능을 쓰는 개선안을 `/student-care/ops`(메뉴 "학생 케어 개선안")로 만들었다. 지표와 기능은 줄이지 않았고 보여주는 방식만 바꿨다. 데이터는 로컬 DB 예시(강남 150 · 분당 50 · 수지 10명, 기준일 10/27)이며 실제 운영 데이터가 아니다.

## 1. 바뀐 화면

학생별 탭은 학생 한 명을 한 줄(26px)로 쓴다. 줄마다 사유 칩(예: `결석 4일 연속·미제출`, `학습 −9시간 45분 (−55%)`), 7일 출결·제출 띠, 같은 축의 학습 시간 막대와 "7일 / 평소 주" 시간, 진행률이 있다. 상담 필요 학생이 위로 오고 왼쪽에 주황 선이 있다. 학생을 누르면 오른쪽에 고정된 상세가 바뀐다. 상세는 날짜 열 7개를 공유하는 표(출결·계획·학습 실제/평소·입실 시각/평소/차이·진행률 실제/계획), 35일 출결 달력, 과목 비중, 상담 기록, 전체 관리 이력으로 이뤄진다.

학습관별 탭은 지표별 카드 4개를 날짜 열을 공유하는 표 하나로 합쳤다. 칸을 누르면 그 날짜·지표의 학생 전원이 실제·평소·차이와 함께 아래에 나오고 최대 3명을 골라 7일 값을 같은 표에서 비교할 수 있다. 관리 이력 탭은 기존 컴포넌트를 그대로 쓴다.

## 2. 측정 결과

`scripts/research/care-screen-metrics.mjs`로 기존(`baseline-v3/`)과 개선안(`ops-final/`)을 같은 조건(3폭 × 2테마, 3개 지점)에서 쟀다. 표는 1600px 라이트, 강남 150명이다.

|---|---:|---:|---:|---|

| 학생 상세를 연 상태 탐색 거리 | 16.0화면 | 5.3화면 | 6화면 이하 | 달성 |
| 학생별 보이는 텍스트 | 5,595자 | 4,009자 | 2,800자 이하 | 미달 |

학생별 텍스트는 1차 구현에서 2,802자까지 줄였다가, Codex 기능 심사가 지적한 정확값(평소 주 시간, 시:분 단위, 같은 요일 평소, 실제/계획 분, 과목 비중 소수점)을 되살리면서 4,009자로 늘었다. 값을 다시 숨기지 않고 미달로 남겼다. 수지점(10명) 학생별 초기 텍스트는 상세가 자동으로 열려 있어 476자 → 858자로 늘었고 상세를 연 상태끼리 비교하면 980자 → 858자다.

## 3. 과업 시험

화면마다 새 Codex 시험관이 소스·API·정답 없이 화면 조작 기록기만으로 15문항(읽기 13, 쓰기 2)을 풀었다(`task-test.md`, 채점 `scripts/research/care-task-score.mjs`). 화면별 시험 전에 DB를 같은 초기 상태로 되돌렸다.

| | 기존 | 개선안 |
|---|---:|---:|
| 점수 (150점) | 125 | 135 |
| 읽기 문항 조작 수(클릭·입력·스크롤·자동 이동) | 450 | 81 |
| Q9 상담 저장 조작 수 | 27 | 18 |
| Q10 설정 변경·복원 조작 수 | 11 | 9 |

기존에서 10점을 받은 12문항은 개선안에서도 모두 10점이다. 개선안이 새로 맞힌 문항은 Q15(35일 중 같은 요일 반복 결석)다. 두 화면 모두 Q3(5점)과 Q4(0점)를 놓쳤다. 시험관이 "표시가 있는 학생"을 서버 신호가 아니라 날짜별 기준을 넘은 학생으로 읽었기 때문이며 문항 해석의 문제로 본다.

개선안 1차 시험은 130점이었고 Q14(과목 비중 차이가 가장 큰 과목)를 틀렸다. 상세가 과목 비중을 정수로 반올림해 두 과목의 차이가 같아 보인 탓이었다. 소수 첫째 자리와 차이(%p)를 표시하도록 고친 뒤 새 시험관으로 다시 시험했다. 1차 기록은 `task-runs/ops-run1/`에 남겼다. 기존 화면 시험 뒤 채점기 버그 2건(Q9 이력 날짜 글, Q11 사유 이름 차이)을 고쳤고 두 화면에 같은 채점기를 썼다.

## 4. Codex 심사 경과

| 단계 | 결과 | 처리 |
|---|---|---|
| 계획 심사 1–4차 | 65 → 78 → 83 → 82점, 불통과 | 대부분 시험 장치(기록기 누출, 스냅숏 불일치, 채점 허점) 지적. 사용자 지시로 심사가 진행을 막지 않는 별도 흐름으로 바꿈 |
| 기능 심사 1차 | 필수 위반 8건(V01–V08) | 학습관 개인 값·전원 목록 복구, 정확값, 데이터 독립성, 같은 요일 결석 표현, 390px, 전체 이력, 빈 지점 상태 수정 |
| 기능 심사 2차 | V02·V04·V05·V07·V08 해결, V01·V03·V06 부분 | 학생 날짜 비교, 결석/기록 없음 분리, 시:분 정밀도, 좁은 화면 가로 스크롤과 결과 이동, 부분 기록 표시 수정 |

2차 심사 이후 수정분은 별도 Codex 심사를 다시 받지 않았고 과업 시험과 실측으로 확인했다.

## 5. 검증

Admin 타입 검사·lint·build 통과, 개선안 모델 테스트 9건, 시드 생성기 테스트 6건, 조작 기록기 회귀 테스트 1건, E2E 타입 검사 통과. 기존 수용 E2E(`e2e/tests/student-care-*.spec.ts`)는 150명 기준으로 인원 값만 바꿔 두었으나 이번 환경에서 끝까지 실행하지 못했다(실행 중 세션이 끊김). 상담 저장과 설정 변경·복원은 두 화면 과업 시험(Q9·Q10)에서 서버 재조회로 확인했다.

## 6. 남은 것

학생별 텍스트(4,009자)와 탐색 거리(5.3화면)는 계획 목표를 넘는다. 재확인 처리(관리 중 학생의 확인일 도래)는 데이터에 해당 학생이 없어 실행 검증하지 못했다. 시험관이 사람 운영자가 아니라 Codex라서 점수는 기존 화면과의 상대 비교로만 쓴다. 비전 AI 관찰은 응답 형태 초안(`vision-contract-draft.md`)까지만 썼고 화면에는 넣지 않았다. 계획에서 핵심 개선 이후 별도로 추가하기로 했고 서비스 백엔드와 촬영 주기가 정해지지 않았기 때문이다.
