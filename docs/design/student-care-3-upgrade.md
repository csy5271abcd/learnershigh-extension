# 학생 케어 3 후속 개선

2026-10-24. 사용자가 첨부한 카드형 3번을 대상으로 한다. 경로 `/student-care/3`과 메뉴/제목의 번호를 일치시킨다. 현재 소스의 세 시안 번호와 이전 브라우저에 남은 번호가 달랐고, 5174 실행 서버도 정지해 있었다. 서버를 다시 실행하고 실제 탭을 새로 불러와 결과를 확인한다.

## 지표와 표현을 연결한 기준
- 입실: 원본은 날짜당 입실 여부다. 입실 이벤트 횟수 데이터가 아니므로 ‘5회’가 아닌 ‘5일 입실’로 표시한다. 최근 7일의 날짜별 상태를 기본으로 하고 미입실 날짜가 드러나게 한다. 예정 등원일이 없으므로 결석률/지각은 계산하지 않는다. 이전 3주 평균과의 소수 일수 차이는 기본 화면에서 제거한다.
- 계획 제출: 제출률 대신 최근 7일 미제출 일수와 해당 날짜를 우선 표시한다. 입실과 제출은 별도 상태다. 미입실했지만 제출한 날도 표현한다.
- 학습 시간: 주간 합계 및 같은 단위의 이전 주간 평균 비교. 그래프는 선택 기간의 일별 시간을 0 기준 날짜순 막대로 표현한다. 입실 상태와 같은 횟수 막대로 처리하지 않는다.
- 평균 입실 시각: 날짜×시각 점과 개인 평균선. 미입실을 0시로 그리지 않는다.
- 계획 달성률: 학습 시간 비율이며 일별 계획 시간과 실제 시간을 같은 눈금에서 비교한다. 계획 미제출은 0 계획으로 채우지 않는다. 계획 작성일만 집계함을 표시한다.
- 과목 비율: 기본은 비교 과목 한 개의 계획/실제 점 비교, 전체 과목은 명시적 ‘전체 과목’ 버튼으로 연다. 작은 카드에 전체 과목을 상시 나열하지 않는다.

## 상세
날짜 상태 칸을 누르면 해당 날짜 기록을 연다. 상세 버튼은 선택한 14/28일 전체를 큰 창으로 연다. 날짜별 기록표는 필요할 때 펼친다. 기존 날짜 그리드는 ‘날짜별 기록’ 보기로 유지한다.

## 근거
- [Grafana Status history](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/status-history/): 주기별 상태는 같은 크기의 칸, 상태 누락은 별도로 구분.
- [Toggl Workload](https://docs.toggl.com/utilization-and-workload-reports-in-toggl-2-0): 날짜별 시간량, 계획/실제의 동일 단위 비교, 필요 시 상세.
- [Analysis Function](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/): 비교하려는 관계에 따라 차트를 고르며 값의 크기/시점/상태를 구분.

위 적용은 이 데이터에 대한 설계 판단이다. 실제 관리자 사용성 실험 결과로 주장하지 않는다. API·DB와 원본 화면의 소스는 변경하지 않는다.

## 추가 피드백 반영: 원본의 목록 → 학생 → 지표 흐름
사용자가 기간 의미를 ‘최근 달력 7/14/28일 안의 입실 기록’으로 확정했다. 또한 전체 학생 목록을 계속 보여주고 학생을 클릭해 지표를 확인해야 한다고 명시했다. 이에 3번의 드롭다운과 작은 차트 6개 동시 배치를 철회했다.

- 왼쪽 전체 학생 명부, 오른쪽 선택 학생의 6개 요약과 선택 지표 상세. 검색과 확인 대상 우선 순서는 유지한다.
- 선택 기간이 날짜뿐 아니라 입실 일수·학습 합계·입실일 평균·평균 입실 시각·계획 달성률·미제출 집계에 반영된다. 7/14일은 직전 동일 길이 기간과 비교한다. 28일의 직전 28일 기록은 현재 자료에 없어 비교 불가로 표시한다.
- 날짜를 생략하던 축 대신 7일씩 공통 눈금의 차트를 배치해 모든 날짜를 표시한다. 축의 날짜/데이터 지점으로 그날 기록을 열 수 있다.
- 과목별 자료는 최근 7일 집계만 있으므로 14/28일 비율을 만들지 않고 자료 범위를 표시한다.
- 관리 기준의 경고 상태는 원래 7/14일 정책 기준이다. 조회 기간을 바꾼다고 상담 판단 정책을 임의 변경하지 않는다.
