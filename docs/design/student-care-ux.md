# 학생 케어 UX

> 화면 문구와 구조의 기준. 기능 규칙은 `docs/specs/wangyu/features/student-care.md`.

## 원칙

- 화면 하나에 판단 하나. 첫 화면에서 할 일이 바로 보여야 한다.
- 설명 문장을 쓰지 않는다. 라벨, 숫자, 색으로 보여 준다.
- 필요한 것만 만든다. 나머지는 사용해 본 피드백으로 추가한다.
- 한국 학원 현장의 말을 쓴다: 특이사항, 상담, 다음 점검일.

참고: 행정안전부 디지털 정부서비스 UI/UX 가이드라인(KRDS), 토스 UX 라이팅(간결함, 한 화면 한 판단), NN/g 대시보드 가이드(핵심 수치만 강조).

## 흐름

```text
특이사항 학생 → 학생 선택 → 상담 기록 → (계속 관리면) 다음 점검일에 점검 → 관리 종료
```

## 화면

| 영역 | 보여 주는 것 |
|---|---|
| 상단 | 지점 선택, 기준일 |
| 왼쪽 | 특이사항 학생 목록: 이름 · 특이사항 · 한 줄 수치. 관리 중 학생은 다음 점검일 표시, 점검일이 된 학생이 맨 위 |
| 오른쪽 | 선택한 학생: 무엇이 달라졌는지 한 줄 + 14일 그래프 → 상담 기록 → 이력 |

## 상담 기록

| 항목 | 입력 |
|---|---|
| 방식 | 면담 · 통화 · 문자 |
| 내용 | 자유 입력 |
| 결과 | 문제없음 · 기록 오류 · 계속 관리 |
| 다음 점검일 | 계속 관리일 때만: 3일 · 1주 · 2주 |

## 점검

지난번 수치와 지금 수치를 나란히 보여 준다. 버튼은 `관리 종료`, `계속 관리` 두 개.

## 용어

| 내부 | 화면 |
|---|---|
| signal | 특이사항 |
| CareCase | 관리 |
| reason EXPECTED_CHANGE / RECORD_ISSUE / ADJUSTMENT_NEEDED | 문제없음 / 기록 오류 / 계속 관리 |
| recheckDate | 다음 점검일 |
| decision CLOSE / CONTINUE | 관리 종료 / 계속 관리 |
| deferred | 기록 부족 |
| settings | 특이사항 기준 (설정 아이콘 안) |

## 이번에 넣지 않는 것

지점 요약 탭, 확인할 질문, 약속 예시, 부담 한도, 학생 합의 체크, 계획 수정 결정. 필요하면 피드백 후 추가한다.

## 시각

Pretendard. 본문 16px, 행간 1.5. 크기는 4단계. 강조색은 하나(파랑), 특이사항은 주황 한 가지. 버튼 높이 44px 이상.
