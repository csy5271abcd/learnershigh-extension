# student-care

> 위치: `docs/specs/wangyu/features/student-care.md`  
> Entity / State는 `docs/specs/wangyu/domain.md`, API는 `docs/api/api-contract.md` §65, 화면 문구와 구조는 `docs/design/student-care-ux.md`를 따른다.

## 1. Scope

관리자(원장 / 매니저)가 평소와 달라진 학생(특이사항)을 찾아 상담하고, 필요하면 다음 점검일에 다시 본다.

```text
특이사항 학생 → 학생 선택 → 상담 기록 → (계속 관리면) 다음 점검일에 점검 → 관리 종료
```

포함: 특이사항 목록, 학생 상세(달라진 점 · 14일 그래프), 상담 기록, 점검, 이력, 특이사항 기준.

제외: 성적 신호, 기존 학습계획 자동 변경, 학부모 발송, 지점 요약, 확인할 질문, 약속 예시, 부담 한도, 학생 합의 체크, 계획 수정 결정.

## 2. Surface

```text
Admin 콘솔 › 학습관리 › 학생 케어
frontend/admin  →  /api/admin/student-care/**
```

한 화면(탭 없음):

| 영역 | 내용 |
|---|---|
| 상단 | 지점 선택, 기준일, 설정 버튼(특이사항 기준) |
| 왼쪽 | 특이사항 학생 목록, 기록 부족 한 줄 |
| 오른쪽 | 선택한 학생: 달라진 점 한 줄 + 14일 그래프 → 상담 기록 또는 점검 → 이력 |

## 3. 왼쪽 목록

- 점검일이 된 관리 학생 → 특이사항 학생(신호 수 많은 순 → 이름) → 점검일 전 관리 학생(점검일 빠른 순).
- 행: 이름 · 특이사항 라벨 · 한 줄 수치. 관리 학생은 `다음 점검 M월 D일`, 점검일이 되면 `점검` 표시.
- 기록 부족(deferred): `기록 부족 · 이름 N명` 한 줄. 특이사항 목록에는 넣지 않는다.
- 종결 후 `cooldownDays` 동안 같은 특이사항으로 다시 올리지 않는다.
- 빈 목록: `특이사항 없음`. 연동 실패: `불러오지 못했습니다` + 다시 시도. 빈 목록으로 보이지 않는다.

## 4. 오른쪽 패널

### 4-1. 상담 기록 (관리 중이 아닌 학생)

| 항목 | 입력 | 규칙 |
|---|---|---|
| 방식 | 면담 · 통화 · 문자 | 필수 |
| 내용 | 자유 입력 | 0~1000자 |
| 결과 | 문제없음 · 기록 오류 · 계속 관리 | 필수 |
| 다음 점검일 | 3일 · 1주 · 2주 | 계속 관리일 때만 필수 |

- 문제없음 / 기록 오류: 저장하면 바로 관리 종료. 목록에서 빠진다.
- 계속 관리: 관리 시작. 목록에 다음 점검일이 붙는다.
- 중복 클릭 / 이미 관리 중이면 새 관리를 만들지 않는다.

### 4-2. 관리 중, 점검일 전

- `다음 점검 M월 D일`.
- 상담 기록(방식 + 내용)만 남길 수 있다. 결과는 점검일에 정한다.

### 4-3. 점검 (기준일 ≥ 다음 점검일)

- 특이사항별 `지난번 → 지금` 수치와 결과(좋아짐 · 그대로 · 나빠짐 · 일부 좋아짐). 비교 결과는 판정이 아니다.
- 버튼: `관리 종료`, `계속 관리`(다음 점검일 3일 · 1주 · 2주).
- 점검일 전에는 버튼이 없다(서버도 거부).

### 4-4. 이력

- 이 학생의 모든 기록, 최신순. 날짜 · 한 줄.

## 5. 특이사항 기준 (설정 버튼)

| 키 | 기본값 | 의미 |
|---|---|---|
| `absenceDays` | 3 | 연속 결석 일수 이상 |
| `planMissingDays` | 3 | 최근 7일 계획 미제출 일수 이상 |
| `studyDropPercent` | 40 | 최근 7일 공부 시간이 평소보다 N% 이상 감소 |
| `executionRatePercent` | 60 | 최근 2주 계획 대비 실천율 N% 미만 |
| `subjectShareGapPoints` | 15 | 계획 과목 비중과 실제 비중 차이 N%p 이상 |
| `startShiftMinutes` | 90 | 평소보다 등원 시간이 N분 이상 늦어짐 |
| `minValidDays` | 3 | 최근 7일 공부한 날이 N일 미만이면 기록 부족 |
| `cooldownDays` | 7 | 관리 종료 후 같은 특이사항을 다시 올리지 않는 기간 |

지점 단위. 범위 밖 값은 422.

## 6. Guardrail

- 특이사항과 점검 결과는 판정이 아니다. 결과 선택과 관리 종료는 선생님이 한다.
- Existing 출결·학습·계획은 읽기만 한다.
- Mentor Surface에 이 데이터를 노출하지 않는다.
