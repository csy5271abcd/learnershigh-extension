# 수행평가·활동 Seed 계획과 실제 결과

> 스크립트: `scripts/seed-student-activities.mjs` · 실제 Backend API → MySQL(`lh_demo_manual_20261111`). 모든 내용은 합성 시연 데이터.

## 1. 원칙

- 기존 Backend API·서버 검증만 사용(수강 과목 검증, 상태 전이, Snapshot, 버전 순서). DB 직접 INSERT·초기화·Migration 수정 없음.
- 인증: 기존 개발용 Mock Header. **학생 Header는 그 학생 본인 자료에만**, 관리자 Header는 **그 학생 지점의 담당 관리자만**(A → a01/a02 교대, B → b01, C → c01). 다른 학생·지점으로 가장하지 않음.
- localhost Backend만 허용. 비밀번호·토큰 미사용.
- 중복 방지: Manifest ID → 없으면 서버 목록에서 설명 끝 `[seed:<Key>]`(학생·학년도-학기·과목·유형) / 노트·결과물·피드백은 부모 ID·Snapshot으로 찾음. 제목만으로 판단하지 않음.
- 중간 실패: 실패 학생에서 멈추고 Manifest 저장 → 재실행 시 이어서 진행(이미 만든 ID 보존).
- 작은 Batch: 학교 단위(4명) 순차, 파일 업로드 순차, 파일은 1~3KB PDF / 수 KB PNG.

## 2. 학생별 계획 (결정적)

| 항목 | 규칙 | 목표 | 실제(재조회) |
|---|---|---|---|
| 수행평가 | 학기마다 수강 과목에서 2·3·4건(평균 3) | ~360 | **360** (1학기 180 / 2학기 180) |
| 상태 | 1학기 대부분 완료, 2학기 마감 기준으로 완료·진행 중·시작 전 | 고르게 | 완료 236 / 진행 중 78 / 시작 전 46 |
| 일정 | 1학기 4~7월, 2학기 9~12월 합성 날짜 | — | `ACTIVITY-DISTRIBUTION.md` |
| 탐구 노트 | 학생당 1건(2학기 진행·완료 과제 우선) | 60+ | **60** |
| Revision | 결과물 학생 + 짝수 번째 학생 v2 (v1은 불변) | 일부 | **48명 v2** |
| 결과물 | 학생 번호 mod 5 ∈ {0,1,3} → PDF v1(+짝수 v2), 과학·수학 과제는 PNG 그래프 추가 | 30명+ | **36명 · 결과물 49 · 버전 67** |
| 피드백 | 결과물 학생 전원 요청(최신 Revision + 최신 PDF 버전 Snapshot). 6명 주기로 전달 4 / 초안 1 / 요청만 1 | 요청 30+ · 전달 20+ · 대기·초안 ~10 | **요청 36 · 전달 24 · 초안 6 · 요청만 6** |
| 성장 기록 | 학생당 1건, 노트의 수행평가·결과물 연결 | 60+ | **60** |
| 중요 표시 | 학생 번호 mod 3 = 0 → 마지막 수행평가 즐겨찾기(계약 범위 `PUT archive/favorites`) | — | **20** |

## 3. 수행평가 유형

교과군별 유형 34종(`TEMPLATES`): 국어(비평문·서평·토론 논증·매체 분석), 수학(풀이 과정 서술·모델링·통계 분석·개념 탐구), 영어(발표·에세이·원서 읽기·토론), 사회(조사 보고서·쟁점 토론·자료 분석·인물 탐구), 과학(실험 설계·주제 탐구·결과 분석·관찰), 정보(프로그래밍·데이터 분석·정보 윤리), 체육(실기·체력 관리), 예술(작품 제작·감상 비평·연주·창작), 기술·가정, 제2외국어, 교양. 유형마다 15개교 문서의 키워드 근거 쪽을 `ASSESSMENT-REFERENCE-SOURCES.md`에 남겼다. 설명란에 "합성 시연 데이터, 공식 학교 일정 아님"과 참고 근거 학교·쪽을 적었다.
