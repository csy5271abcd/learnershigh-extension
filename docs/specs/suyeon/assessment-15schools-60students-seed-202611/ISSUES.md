## 2. 기술적 제약 (미완료로 보고)

| # | 항목 | 상태 |
|---|---|---|
| C-1 | **실제 관리자 로그인·로그아웃·Session** | 시스템에 없음(API-OD-A01). 관리자 4명은 **개발용 Mock Header 계정**이다. "로그아웃 후 세션 데이터 비노출"은 검증할 대상이 없어 **미검증**. 계정 전환 = 개발 서버를 다른 ID로 띄우는 것(새 브라우저 Context, 이전 계정 데이터 미표시 확인). |
| C-2 | **Header 조작만으로 우회 불가** 요구 | Mock 인증은 Header 값이 곧 신원이라, 실제 인증이 붙기 전에는 Header를 바꾸면 다른 계정이 된다. 이번 구현은 **각 계정의 서버 측 지점 범위 검사**만 보장한다(다른 지점 학생 → 404). |
| C-3 | 학교별 관리자 | 기존 권한 모델은 학원 지점 단위. 학교 단위 관리자 권한은 만들지 않았다(사용자 결정: 지점 3개). |
| C-4 | 평가계획서 공식 데이터 | 15개교 PDF는 참고자료로만 사용. 공식 평가계획서 등록·검토 확정 없음. 시연 학교는 평가계획서 운영 슬롯 없음. |
| C-5 | 과목 카탈로그 근거 | 키워드 매칭 집계(사람 검토 전). 학년 폴더가 없는 문서(대신·가좌·한솔)는 본문 `N학년` 근접 판정이라 오판 가능. |
| C-6 | Student Care Playwright E2E | 별도 e2e Profile Backend(test endpoint)가 필요해 이번에 실행하지 않음. Student Care는 단위 테스트(17개 클래스)와 실행 중 Backend API 확인으로 대신함(`REGRESSION-RESULT.md`). |
| C-7 | 기존 18080 Backend | 사용자가 `--server.port` 없이 재시작해 현재 **8080**. 기존 5173/5174 개발 서버의 Proxy(18080)는 502 → 시연 전 `--server.port=18080`으로 재시작 필요. |
