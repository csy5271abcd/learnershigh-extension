# 원문 수동 검토 A안 보완 (승인 요청용, 2026-11-10)

이전 설계: `../assessment-multiformat-review-next/SOURCE-REVIEW-DESIGN.md`(A/B/C 비교, 단기 A·장기 B 권장). 이 문서는 A안 절차와 기록의 의미만 보완한다.

## 1. A안 관리자 절차 (승인 후)

| # | 단계 | 누가 / 무엇이 |
|---|---|---|
| 1 | Admin에서 평가계획서 Revision 열기 | 관리자 |
| 2 | 관리자 PC의 HWP·HWPX 원본 선택 | 관리자 |
| 3 | 브라우저가 SHA-256 계산 | 브라우저(파일은 전송하지 않음) |
| 4 | 서버 Revision `checksum`과 비교, 다르면 다음 단계 불가 | 화면 |
| 5 | 같은 파일을 한글 프로그램으로 열기 | 관리자(화면 밖) |
| 6 | AI 후보값과 근거 노드의 Locator(구역·표·행·열·경로·원문 인용) 확인 | 화면 표시 |
| 7 | 한글 프로그램에서 그 칸 찾기 | 관리자 |
| 8 | 값과 원문 대조 | 관리자 |
| 9 | 확정값 입력 + **그 필드 근거 노드의 Locator 중 하나** 선택(다른 항목 근거는 목록에 없음). 원문에 없으면 "원문에 없음 확인" + 확인한 칸 | 관리자 |
| 10 | "한글 프로그램에서 위 위치의 원문을 직접 대조했습니다" 직접 체크 | 관리자(자동 체크 없음) |
| 11 | 요청 미리보기 확인 → 확정 | 관리자 |
| 12 | 서버 검증(`API-CONTRACT-REVISED.md` §3-4) 후 저장. 실패하면 아무것도 저장하지 않음 | 서버 |

## 2. 네 가지를 구분한다

| 구분 | 의미 | 의미가 아닌 것 |
|---|---|---|
| SHA 비교 | 관리자 브라우저가 계산해 **보고한** 파일 동일성 | 서버가 원본을 검사함 |
| Locator 검증 | 선택한 위치가 이 Run·과목·근거 노드에 있음(구조·참조 관계) | 그 위치의 글이 값과 맞음 |
| 관리자 확인 | 사람이 원문을 대조했다는 **선언** | 시스템이 열람을 증명함 |
| 운영 감사 | 인증된 관리자 신원·시각 | (지금은 Mock ID라 운영 감사 불가) |

어느 하나만으로 검토 완료로 보지 않는다. 화면·API·보고서에서 "원본 검증 완료", "열람 증명" 같은 표현을 쓰지 않는다. 저장 기록의 이름은 "관리자가 제출한 수동 확인 기록"이다.

## 4. 운영 제한

- 실험 Flag(`assessment.multiformat.experimental`) 기본 OFF 유지. 계약·D-1이 승인돼도 자동으로 켜지 않는다.
- 실제 관리자 인증이 준비되기 전에는 운영 환경에서 HWP·HWPX 확정을 켜지 않는다. 승인 후 Backend에 "Mock 관리자 인증이면 HWP·HWPX 확정 거절" 같은 운영 보호 장치를 둘지 함께 결정한다(제안).
- 합성 문서와 Mock 관리자로 한 시험은 "합성 데이터 기반 검토 API 시험"이며 사람 검토 실적이 아니다.
