# assessment-inquiry — 심화 탐구·탐구 노트·결과 파일·자료·성장 기록

> 위치: `docs/specs/suyeon/features/assessment-inquiry.md`  
> 대상 Surface: 기존 LearnersHigh **Student**의 `Assessment` 내부  
> 담당 기능: **ST-07~ST-13, ST-16~ST-20**  
> 목적: 자율 심화 탐구와 모의고사·대학 공개 자료, 편집 가능한 탐구 과정 노트, 결과물 버전, 개인 자료함과 아카이브를 정의한다.  
> 상태: **Feature Spec 작성본**. 실제 API·코드·테스트 완료를 뜻하지 않는다.

## 1. Scope

이 문서는 학교 수행평가와 선택적 심화 탐구에서 **함께 사용할 수 있는 과정 기록·자료·산출물 기능**을 정의한다. 학생이 학교에서 제출해야 하는 실제 과제 정보는 `assessment-student.md`, 피드백 요청/답변은 `assessment-feedback.md`, 관리자 콘텐츠 공급·관리와 원본 열람은 `assessment-admin.md`를 따른다.

## 3. ST-16 — 심화 탐구 Task의 탐색·시작·직접 생성

```text
심화 탐구 → 과목·키워드·탐구 분야 검색/필터
→ 관리자 공개 Task 선택 → 우측 Preview(목표·방법·참고자료·자기점검)
→ 이 탐구 시작하기 → 내 심화 탐구 상세 → 노트·자료·결과물 기록
```

직접 생성:

```text
심화 탐구 → 새 탐구 만들기 → 제목·과목·탐구 목표 입력
→ 필요하면 관련 학교 수행평가 선택 → 저장 → 내 심화 탐구 목록
```

- 관리자 Task는 **공개된 콘텐츠의 추천 소재**다. 학생이 시작하면 학생의 `EnrichmentTask` 및 노트/파일은 별개 Identity로 관리한다.
- 관리자 원본 Task가 나중에 수정·비공개·보관되어도 학생이 시작한 탐구의 글·파일·진행 기록을 자동 변경/삭제하지 않는다.
- 학생 직접 생성 Task에 관리자 승인 절차나 주제·진로 강제 연결을 요구하지 않는다.
- 진행 상태는 `시작 전 / 진행 중 / 완료`로 단순하게 표현한다. 구형 8단계 전이와 독립적이다.
- 리스트에서 다른 카드로 이동했을 때 선택 카드와 우측 미리보기 내용이 서로 맞아야 한다. 미리보기 로딩 실패 시 이전 카드 정보를 현재 카드 내용처럼 표시하지 않는다.
- 마감은 학생 자율 Task에서는 **선택적**이며, 공식 학교 과제 마감과 혼동하지 않는다.

## 4. ST-07 — 모의고사 지문에서 탐구 소재 발견

모의고사 기반 기능은 **문제 풀이·성적 채점이 아니라 탐구 소재 탐색**이다. 학생은 다음 두 출처를 구분해 사용할 수 있다.

1. 관리자가 등록·공개한 지문 기반 탐구 카드
2. 학생이 자신의 학습용 지문 PDF·이미지·출처 링크를 등록해 만든 **개인 탐구 자료**

| 데이터 영역 | 표시 항목 |
|---|---|
| 원문 정보 | 연도·시행월·학년·과목·문항 번호·실제 출처·원문 링크/제공 허용된 파일 |
| 탐구 내용 | 핵심 소재, 연관 교과 개념·분야, 탐구 주제명·선정 이유, 목표·탐구 질문 |
| 실행 안내 | 관찰·실험·자료 조사·사례 비교 등의 방법, 심화 질문, 참고자료 |
| 행동 | 카드 열람, 저장/즐겨찾기, 아이디어 연결, 새 심화 Task 시작 |

```text
모의고사 탐구 카드 → 검색·과목 필터 → 카드 상세
→ 출처/탐구 방법 확인 → 수행평가에 아이디어 참고 또는 별도 심화 Task 생성
```

- 원문 출처와 LearnersHigh가 별도로 작성한 **해설·탐구 아이디어**를 시각적으로 구분한다.
- 실제 시험 원문 PDF/이미지의 재배포·복사 권한을 가정하지 않는다. 허용되지 않는 전문은 원본 URL로 연결한다.
- 학생이 등록한 개인 지문 자료는 관리자 공개 콘텐츠로 자동 발행하지 않는다.
- 특정 모의고사 카드(관리자 공개 카드 또는 학생 개인 자료)에서 **새 심화 Task를 시작하면 실제 출처를 추적할 수 있어야** 한다. 현행 Task 생성 API §18 초안은 출발 자료를 `sourceReference { type, sourceId }`(`MOCK_EXAM_MATERIAL` / `PERSONAL_MOCK_EXAM_MATERIAL`)로 전달하며, 관리자 공통 심화 Task 참조인 `catalogTaskId`와 구분한다. 시작한 학생 Task는 원본 카드와 별도 Identity이고, 카드가 수정·비공개되어도 학생 기록은 자동 변경되지 않는다. 최종 DTO/Enum과 `catalogTaskId` 동시 사용 규칙은 API-OD-A12에서 확정한다.
- 탐구 주제에 진로 연결을 의무화하지 않는다. 예를 들어 교통시설을 다룬 영어 지문에서 역 내 이동 동선을 조사하는 심화 Task로 발전시킬 수 있다.

## 5. ST-08 — 탐구 과정 노트 (실제 결과물과 분리)

학생은 학교 수행평가 또는 심화 탐구에 연결된 `AssessmentNote`를 **자유롭게** 작성한다. 관리자 원본 노트 편집은 불가하고 읽기 전용 열람/피드백만 가능하다.

지원할 편집 동작:

- 제목, 소제목, 본문, 목록, 번호 목록, 체크리스트, 인용/메모, 표, 링크 카드
- 이미지·PDF 등 참고자료 블록 삽입과 위치 이동·순서 변경·삭제
- 템플릿으로 생성된 이모지 소제목을 **일반 본문 텍스트처럼 수정·삭제**
- 자동 저장 상태 표시, 중복 저장 방지, 저장 실패 재시도
- 작성·수정 이력 열람, 과거 Revision 확인(복원이 지원되면 **새 Revision**으로 저장)
- 과목/Task 맥락, 참조 링크, 출처를 필요한 범위에서 연결

```text
수행평가/심화 Task 상세 → 탐구 과정 노트 열기
→ 자유 블록 편집 → 저장 중 → 저장됨(서버 확인 후)
→ 수정 이력 확인 → 편집 이어하기
```

- **탐구 노트 = 조사/생각/시행착오/성찰을 기록하는 본문**, **결과 파일 = 학교 제출·발표용 산출물 원본**이다. 노트 자동저장이 DOCX/PPTX를 생성했다는 뜻은 아니다.
- 저장 실패를 `저장됨`으로 속이지 않고 입력 내용을 보존하여 재시도하게 한다. 자동저장 주기·편집 동시성·충돌 정책은 API/Editor 기술 확정 전에 임의로 명시하지 않는다.
- 과거 NoteRevision 및 피드백 요청 당시의 Note Snapshot은 현재 편집으로 바뀌지 않는다.
- 다른 Task에서 같은 에디터 컴포넌트를 재사용해도 데이터 식별자/저장 대상은 분리한다.

## 6. ST-09 — 탐구 노트 템플릿 10종

### 6-1. 공통 적용 규칙

```text
탐구 노트 → 템플릿 선택 → 본문 미리보기
→ 새 노트로 만들기 또는 기존 노트 뒤에 추가
→ 본문 블록 삽입 → 자유 작성·자동저장
```

- 템플릿의 이모지는 **선택 카드에만 보이는 장식이 아니라 실제 에디터 본문 소제목에 포함**되어야 한다.
- 기존 내용이 있으면 이를 묻지 않고 덮어쓰지 않는다. 템플릿 적용 취소/새 노트 또는 뒤에 추가를 제공한다.
- 템플릿은 시작점이며, 모든 항목을 채우는 강제 절차가 아니다. 내용·순서·이모지·소제목을 자유롭게 바꿀 수 있다.
- `TPL-01`~`TPL-10`은 문서 추적용 ID이며 실제 DB PK/Enum으로 단정하지 않는다.

## 7. ST-10~11 — 과목별 자료 추천·자료함·노트 삽입

### 7-1. 실제 추천 가능한 자료원

| 유형 | 자료원 예시 |
|---|---|
| 뉴스·시사 | 뉴닉, 연합뉴스, KBS 뉴스, YTN, 한겨레, 경향신문 |
| 영상·다큐 | 크랩(KLAB), EBS 다큐, KBS 다큐, YTN 사이언스 |
| 논문·학술 | ScienceON, RISS, DBpia, KCI |
| 통계·공공데이터 | KOSIS, 공공데이터포털 |
| 과학·기술 | 사이언스올, 사이언스타임즈, 연구기관, SW 중심사회 |
| 국어·역사·인문 | 국립국어원, 국립중앙도서관, 국사편찬위원회, 국가기록원 |

이는 **검색·추천의 자료원 목록**이다. 해당 기관의 모든 기사/논문에 시스템이 접근할 수 있다는 뜻이 아니다. 실제 개별 자료는 존재·출처를 확인하고, 유료/로그인 필요 자료는 그 상태를 표시한다.

### 7-2. 수집 및 활용

```text
과목·탐구 주제 → 추천 자료원/검색 → 실제 기사·논문·영상 원문 확인
→ 자료 저장(제목·원본 URL·출처·저자/게시일 가능한 범위)
→ 학생 메모·태그 추가 → 탐구 노트에서 '노트에 추가'
→ 출처가 포함된 편집 가능한 링크 카드/참고자료 블록 생성
```

- 학생이 직접 URL·PDF·이미지 자료를 추가할 수 있는 범위를 제공한다. `URL만 입력됨`과 `원문/메타데이터 검증됨`은 다른 상태로 표시한다.
- 노트에 자료를 삽입하는 행위는 원문 전문 복사나 저작권 승인을 의미하지 않는다.
- 학생 `Scrap`과 관리자 내부 `Scrap`은 노출 정책이 다르다. 관리자 자료는 명시적으로 추천·공개할 때까지 학생에게 자동 노출하지 않는다.
- 기존 LearnersHigh Library와 동일한 데이터 소유권을 가정하지 않는다. 교육 참고자료 링크/과정 기록에 필요한 신규 필드만 추가하고, 중복 가능성은 Integration Boundary에서 검토한다.
- 자료 원문 URL이 깨졌거나 서버 연결에 실패하면 원본 링크 오류를 분명히 표시하고 학생 메모를 보존한다.

## 8. ST-12~13 — 실제 결과 파일과 산출물별 독립 버전

### 8-1. 결과 파일 등록

`AssessmentNote`와 별개의 `Artifact`에 실제 제출/발표 파일을 연결한다.

```text
학교 수행평가/심화 탐구 상세 → 결과 파일 → 새 결과물 등록
→ 유형/제목 지정 → 파일 업로드 → 결과물 A의 v1 생성
→ (나중에) 수정본 업로드 → 같은 결과물 A의 v2 생성
→ 버전별 메모·원본 열람 / 다운로드
```

지원 고려 형식: PDF, DOC/DOCX, HWP/HWPX, PPT/PPTX. 이미지, XLSX, Google Docs URL은 확장 대상이며 업로드/원본 링크의 실제 지원 범위는 File Provider 검증 결과에 따른다.

**서로 다른 결과물은 독립적인 버전 계보**를 갖는다.

```text
수행평가 A
├─ 보고서(Artifact R01) → v1 DOCX → v2 DOCX → v3 PDF
├─ 발표자료(Artifact R02) → v1 PPTX → v2 PPTX
└─ 조사 데이터(Artifact R03) → v1 XLSX
```

파일 형식이 DOCX에서 PDF로 바뀌어도 *같은 보고서*의 수정본으로 추가할 수 있지만, PPT가 보고서 v4로 잘못 합쳐져서는 안 된다.

### 8-2. 버전 기록 및 열람

- 버전 번호, 파일명, 유형, 파일 크기, 업로드 시각, 버전 설명, 작성자, 최신 여부와 연결된 피드백 요청/답변을 확인한다.
- **이전 파일을 덮어쓰지 않는다.** 이미 피드백 요청에 포함된 v2는 새 v3 업로드 후에도 동일 원본을 가리킨다.
- PDF는 가능하면 페이지 뷰어, PPTX는 가능하면 슬라이드 미리보기, DOCX/HWP는 실제 변환기 지원 여부에 따라 뷰어·다운로드·외부 열기로 대체한다. 지원하지 않는 미리보기를 임의로 그리지 않는다.
- **학생과 관리자 모두 동일 결과물의 두 버전 선택·비교를 목표 동작으로 정의한다.** 비교 불가 형식은 개별 원본 열람·파일 정보·메모 비교로 대체한다. 현행 API 초안은 학생 비교(§25-1)와 관리자 비교(§37)를 별도 Endpoint로 정의한다. 학생은 **본인 Artifact의 동일 결과물에 속한 업로드 완료 Version 두 개**만 비교하며, 관리자 비교와 같은 버전 무결성 원칙을 따른다. 비교는 과거 Version이나 FeedbackSnapshot을 바꾸지 않는다. 형식별 실제 Diff 지원 범위는 API-OD-A12로 미확정이며, 학생의 버전 목록·개별 열람과 혼동하지 않는다.
- 업로드 실패·용량 초과·지원하지 않는 확장자·변환 실패는 서로 구분하고, **서버 저장 성공 전에** 버전을 생성한 것처럼 표시하지 않는다.

### 8-3. 학생의 문서/파일 권한

학생은 본인의 결과 파일을 추가·열람하고 기존 과거 버전을 확인한다. 관리자에게는 읽기 전용 원본 열람과 **별도 피드백**만 제공한다. 학생이 원본 파일을 새 버전으로 바꾼다고 기존 관리자 의견의 대상 버전이 바뀌지 않는다.

## 9. ST-17 — 대학 공식 공개 PDF 자료실

```text
심화 탐구 → 대학 공개 자료 → 대학·학년도·분야/유형 선택
→ 공식 게시처·출처/이용 조건 확인 → 원본 PDF/링크 열람
→ 관련 교과 개념·탐구 아이디어 참고 → 선택적으로 별도 심화 Task 시작
```

- 관리 대상 대학 예시: 서울대학교·연세대학교·고려대학교·KAIST.
- 자료 메타데이터: 대학명, 공식 출처 URL, 제목, 학년도, 자료 유형, 원본 발행일/확인일, 관련 교과 개념, 탐구 연계 정보.
- **공식 PDF 원문과 서비스가 자체 작성한 탐구 Task는 서로 다른 개체**이며, 공개 자료 활용이 입시 정보의 공식 해석이나 합격을 보장하지 않는다.
- 이용 허락이 불분명할 경우 문서 자체를 무단 재업로드하지 않고 공식 URL 안내를 우선한다.
- 별도 면접 연습·AI 면접관·답변 채점 기능은 생성하지 않는다.
- 대학 공개 자료에서 시작한 심화 Task도 출처 추적이 필요하다. 현행 API §18 초안의 `sourceReference { type: UNIVERSITY_RESOURCE, sourceId }`로 출발 자료를 참조하며, 서버가 공개 여부를 검증한다. 원문 PDF를 Task에 자동 복제하지 않고, 이용 조건이 불분명하면 공식 URL 참조만 보존한다. 계약 초안이 있다고 **자료 → Task 생성 연결이 구현 완료**된 것으로 표기하지 않는다.

## 10. ST-18 — AI 학습 도우미

현재 수행평가·심화 Task의 **교과 개념 설명, 공식 기준의 쉬운 해석, 자료 요약, 논리·근거 점검, 탐구 방향 제안**을 지원한다. 실제 기능 제공 범위와 AI Provider는 별도 계약/검증 대상이다.

```text
노트/Task 상세 → AI 도우미 패널
→ 학생이 질문/관련 자료 선택 → 결과 확인(출처·불확실성 표시)
→ 필요하면 학생이 스스로 노트 내용에 반영
```

- AI가 학생의 실제 실험 결과·협업 역할·개인 성찰을 **창작해서 공식 기록처럼** 저장하지 않는다.
- AI 결과는 `Suggestion`으로 표시하고 학생이 명시적으로 적용하기 전 원문을 바꾸지 않는다.
- 외부로 전송되는 학생 자료의 범위는 최소화하고 인증·제공자·보관 정책을 확인한다.
- 실패·지연·응답 불완전 시 재시도/수동 작성이 가능하고, 실패 결과를 성공 사실로 저장하지 않는다.

## 11. ST-19 — 성장·세특 참고 기록

```text
학교 수행평가/심화 Task 또는 독립 활동 선택
→ 활동 동기·과목·기간·나의 역할·협업·구체적 실행 과정
→ 문제·해결·결과·배운 점·후속 탐구 작성
→ 근거 자료·결과 파일·피드백 연결 → 개인 성장 기록 저장
```

- 학생 **실제 경험과 본인 기여**를 중심으로 작성한다. AI/관리자가 학생의 성찰 문장을 몰래 대신 작성하지 않는다.
- 성장 기록은 실제 학교 교사가 작성하는 **공식 세특/생활기록부가 아닌 개인 참고 기록**이다. 자동 등재·학교 공식 인정·실제 입시 평가를 보장하지 않는다.
- 같은 활동의 노트·결과물·피드백·참고자료를 연결할 수 있지만 파일 자체를 중복 저장해야 하는 것은 아니다.
- 학생의 선택적 후속 탐구는 새 심화 Task로 연결할 수 있다. 졸업학년·진로와의 연계를 의무화하지 않는다.

## 12. ST-20 — 개인 아카이브 및 휴지통

| 탭 | 포함할 자료의 관점 | 주의 |
|---|---|---|
| 최근 | 최근 열람·수정/생성된 기록 | 원본 수정일과 열람일을 혼동하지 않음 |
| 즐겨찾기 | 학생이 중요 표시한 자료 | 원본을 별도 복제하지 않음 |
| 완료 | 완료 상태의 학교 수행평가·심화 탐구 | 피드백 답변 상태와 독립 |
| 지난 학기 | 이전 학기/학년도 기록 | 당시 학교·학기 컨텍스트 보존 |
| 휴지통 | 삭제/보관 처리된 복구 가능 항목 | 보관 기간·영구 삭제 정책 미정 |

```text
보관함 → 탭·학년도·과목·유형·검색 필터 → 기록 선택
→ 연결된 노트·파일 버전·피드백 확인 → (허용 시) 복구·내보내기
```

- 개인 자료함/아카이브와 기존 LearnersHigh Library의 데이터 중복을 피하고, 기존 사용자의 관리 규칙을 확인한다.
- 삭제·복구가 연결된 피드백 Snapshot과 파일 원본의 무결성을 깨뜨리지 않아야 한다.
- **현재 API §30은 탭 조회·즐겨찾기·복원 명령만 제안**하고, §12의 `SchoolAssessment DELETE` 외에는 심화 Task·노트·결과물/버전·자료·성장 기록의 삭제/휴지통 이동 명령이 없다. 따라서 다섯 탭의 표시 요구와 **전체 유형의 삭제·복구 지원이 완료되었다는 주장**을 구분한다. 대상별 공백은 API §30의 표와 API-OD-A08에서 추적한다.
- 보관함을 **별도 테이블**로 만들지, 원본 Entity를 조회한 View로 둘지는 `domain.md` §19·OD-A11 Open Decision을 따른다. 정책 확정 전에는 삭제 버튼을 임의 활성화하지 않는다.

## 13. 공통 사용자 흐름·예외

**학교 과제 연계**: `수행평가 상세 → 노트 작성 → 결과물 v1 업로드 → (선택) 피드백 → 이후 v2 업로드 → 성장 기록 → 보관함`.

**자율 심화**: `모의고사 카드 또는 대학 자료 → 독립 Task 시작 → 자유 노트/템플릿 → 자료 링크 추가 → 결과물 → 성장 기록`.

**예외 대응**: 목록 없음, 비공개 콘텐츠, PDF 원문 접근 불가, 뉴스 기사 삭제/유료자료, 템플릿 적용 취소, 에디터 저장 실패·편집 충돌, 잘못된 파일 형식, 업로드 중 취소·중복 요청, PPT/HWP 변환 실패, 과거 버전 다운로드 실패, 아카이브 복구 정책 미확정, 타인 데이터 접근 차단.
