# assessment-student — 학교 수행평가·학교/학업 정보

> 위치: `docs/specs/suyeon/features/assessment-student.md`  
> 대상 Surface: 기존 LearnersHigh **Student**의 `Assessment` 내부  
> 담당 기능: **ST-01 ~ ST-06**  
> 목적: 학교·학기 정보, 평가계획서 활용, 실제 수행평가 등록·관리 및 교과 기반 학습 보조의 사용자 동작을 정의한다.  
> 상태: **Feature Spec 작성본**. 실제 API·코드·테스트 완료를 뜻하지 않는다.

## 1. Scope

학생이 학교에서 실제로 부여받은 수행평가의 **안내·평가기준·일정·준비 과정**을 관리한다. `SchoolAssessment`는 자율 심화 탐구인 `EnrichmentTask`와 다른 업무 객체다. 둘 다 노트와 결과물을 연결할 수 있지만, 자율 탐구가 학교 공식 성적 항목으로 자동 등록되지는 않는다.

| ID | 학생 기능 | 주요 행동 | 이 문서의 기준 절 |
|---|---|---|---|
| ST-01 | 학업정보 설정 | 학교·학년도·학년·학기·수강과목 확인·설정 | §4 |
| ST-02 | 학교알리미 PDF 분석 | 공통/개인 PDF 선택·업로드, AI 추출 결과 원본 대조 | §5 |
| ST-03 | 수행평가 등록·관리 | 직접 추가·PDF 기반 추가, 수정·삭제·상태 관리 | §6 |
| ST-04 | 평가기준 AI 설명 | 공식 평가기준 쉬운 설명·예시·자기 점검 | §7 |
| ST-05 | 수행평가 꿀팁 | 교과 연결·주제·근거·과정 기록 등 6종 | §8 |
| ST-06 | 수행평가 주제명 추천 | 교과 개념 기반 3~5개 제목 후보 비교·선택 | §9 |

**범위 제외:** 구형 수행평가 8단계/7탭 강제 진행, 주제 승인·반려, 필수 AI 검토·필수 피드백·필수 재제출, 대학 면접 모듈, 기존 LearnersHigh 학습계획·Library·Timer의 재구현. 자율 탐구·노트·파일·성장 기록은 `assessment-inquiry.md`, 요청 피드백은 `assessment-feedback.md`가 소유한다.

>
> **Assessment 홈·알림 범위(목업 `ST_Assessment-Home_01~03`):** 다가오는 과제·최근 기록·피드백 상태 요약 및 기존 상세 화면으로 이동하는 **UI 구성 목표**다. 데이터는 현행 목록·피드백 조회 계약을 재사용하는 방향으로 검토하지만, **홈 전용 요약 API 및 푸시/읽음 알림 계약은 현재 없다**. 새 Feature ID·알림 Provider·자동 발송을 목업만으로 확정하지 않고, 구현 전에 추가 계약 필요 여부를 판단한다.

- 기존 LearnersHigh 학생 상단바의 **`Assessment`** 진입점을 사용하며, Assessment 내부 메뉴는 `홈 / 학교 수행평가 / 심화 탐구 / 선생님 피드백 / 자료함 / 성장 기록 / 보관함 / 수행평가 꿀팁`, 과목 바로가기, `학교·학업 정보`를 제공한다. 심화 탐구 이하 메뉴의 동작은 해당 기능 문서에서 정의한다.
- `공통국어2 / 통합과학2 / 통합사회2 / 과학탐구실험2`는 **예시 과목**이며 고정 Enum이 아니다.
- 목록에서 상세로 진입하고 돌아올 때 과목·학기·검색·필터·스크롤 등 기존 탐색 맥락을 복원한다. 선택한 학기를 바꿔도 다른 학기의 기록이 변경되지 않는다.

## 4. ST-01 — 학교·학업 정보

### 사용자 목표 및 데이터

학생은 학교, 학년도, 학년, 학기, 수강과목을 확인하고 현재 적용할 학업 컨텍스트를 선택한다. 과거 학기 기록의 **원래 소속 학교/과목/시기**는 유지한다.

```text
Assessment → 학교·학업 정보 → 학교·학년도·학년·학기 확인
→ 과목 확인·설정(허용된 범위) → 저장 → 해당 학기 수행평가 목록 갱신
```

- 기존 LearnersHigh가 학교·학년·과목을 보유하면 기존 데이터를 우선 조회하고 Extension의 별도 원천 데이터를 중복 생성하지 않는다.
- 학교/학년 변경 권한, 자유 입력 과목 허용 여부, 과거 학기 변경 정책은 실제 인증·원천 데이터 소유권을 확인한다.
- 학기 선택은 우선 **조회 필터**다. 이미 작성한 노트나 첨부파일을 다른 학기로 자동 이동시키지 않는다.
- 학교 정보가 없거나 접근할 수 없는 경우 설정 방법을 안내하되, 다른 학생/기관 데이터를 보여주지 않는다.

### 수용 기준

- [ ] 학교·학년·학기·과목 정보를 변경하고 같은 컨텍스트를 목록·상세에서 일관되게 사용한다.
- [ ] 지난 학기·다른 학교에 속했던 수행평가가 현재 학기 기록으로 잘못 합쳐지지 않는다.
- [ ] 기존 사용자 데이터 소유권이 불명확하면 새 DB 필드·값을 가정하지 않는다.

## 5. ST-02 — 학교 평가계획서 PDF 확인·분석

학생은 **관리자가 학교별로 등록한 공통 PDF를 이용**하거나 **개인이 PDF를 업로드**하여 평가계획서를 분석할 수 있다. 공통 평가정보, AI 추출값, 관리자 확인 결과, 학생의 개인 정정값은 별도로 취급한다.

```text
학교·학기 선택 → 공통 PDF 조회 또는 개인 PDF 업로드
→ 업로드·분석 상태 확인 → 과목·평가 항목 분석 후보
→ 원본 PDF의 근거 페이지 대조 → 필요한 부분 선택·수정
→ 자신의 수행평가에 반영/추가
```

**분석 범위**는 수행평가에만 한정하지 않는다.

| 정보 | 표현과 주의사항 |
|---|---|
| 문서 맥락 | 학교, 학년도, 학년, 학기, 과목, PDF 개정본·출처 |
| 교수·학습 계획 | 단원, 성취기준, 교수학습 방법, 평가 방식 |
| 지필평가 | 1·2차 시험, 선택형/논술형, 반영비율, 만점 등 원본에 명시된 항목 |
| 수행평가 | 영역/과제명, 유형, 시기, 반영비율, 배점, 평가 요소 |
| 채점·성취 | 수준별 세부 채점기준, 성취도 체계, 성취수준, 기준 성취율 |
| 검증 근거 | PDF 페이지와 문서에 인쇄된 쪽 번호를 구분하여 연결 |

- 한 PDF에 여러 과목이 있거나, 학교가 여러 PDF를 나누어 제공하는 경우를 모두 고려한다.
- `미확인`, `추출 실패`, `원본에 없음`을 숫자 `0` 또는 빈 수행평가 목록과 혼동하지 않는다.
- AI는 평가비율·마감·성취기준을 자동 확정하거나 합계 오류를 임의 수정하지 않는다. 후보와 해당 원본 페이지를 함께 표시한다.
- 전년도 PDF는 **과거 참고자료**로 명시하고 올해 평가 일정으로 자동 사용하지 않는다.
- 공통 PDF가 갱신되어도 학생 개인 수행평가·노트·결과물·피드백 Snapshot을 덮어쓰지 않는다.
- 분석 실패/부분 성공이면 원본 PDF 열람과 학생 수동 입력은 가능하도록 한다.

**상태**: 파일 업로드 중/실패와 AI 분석 중/완료/확인 필요/실패는 별개의 상태다. 실제 상태 Enum, 파일 크기 제한, 분석 제공자, 캐시/재시도 API는 공통 계약에서 결정한다.

**수용 기준**

- [ ] 공통 PDF 선택과 개인 PDF 업로드가 분리되어 동작하며 잘못된 학교/학기 문서를 경고한다.
- [ ] 지필·수행평가를 모두 분석하되 **지필 항목을 수행과제처럼 추가하지 않는다**.
- [ ] 과목별 정보와 원본 근거를 대조하고 학생이 수정한 개인 값만 자신의 기록에 반영한다.
- [ ] 분석 실패가 빈 데이터 상태로 표현되지 않는다.

## 6. ST-03 — 학교 수행평가 등록·관리

### 등록·수정·목록

**등록 A — PDF 기반:** `학교 수행평가 → PDF 가져오기 → 원본/추출 후보 확인 → 대상 수행평가 선택 → 개인 항목 수정 → 등록`.

**등록 B — 직접 입력:** `수행평가 추가 → 제목 + 과목 입력 → 선택적 제출일/비율/준비물/평가기준/설명 → 저장 → 목록·상세 진입`.

- 제목·과목을 기본 필수로 하여 마감일을 모르는 학생도 등록할 수 있다. 학교가 미공개한 날짜·평가기준을 자동 채워 넣지 않는다.
- 목록: 학년도·학기·과목·상태·마감일·검색·중요 표시. 과목별 바로가기는 이 목록에 **같은 필터**를 적용한다.
- 상세: 과제명, 교과, 실제 공지·평가기준과 출처, 관련 자료, 노트, 결과 파일 및 피드백 링크. 학생은 자신의 허용 범위에서 수정·보관을 할 수 있다.
- **진행 상태는 `시작 전 / 진행 중 / 완료` 세 가지**. 학생의 자기 관리 상태이며 실제 학교 제출 여부·점수 확정의 증명으로 오해시키지 않는다.
- 피드백 답변 대기/완료, PDF 분석 상태, 파일 업로드 상태를 과제 진행 상태와 합치지 않는다.
- 삭제·복원은 노트 Revision·ArtifactVersion·피드백 기록의 무결성 및 보존 정책을 준수한다. 현행 API §12의 `DELETE`는 Soft Delete **후보**이며 휴지통 전체 동작은 확정되지 않았다(§30, `domain.md` OD-A11). 영구 삭제/연쇄 삭제는 별도 결정 전 임의 구현하지 않는다.

### 예외와 수용 기준

- [ ] 직접 추가, PDF 기반 추가, 수정, 검색·필터, 세 상태 전환이 동작한다.
- [ ] 이미 등록된 공식 과제를 다시 가져올 때 중복 가능성을 알리고 학생 데이터를 무단 병합하지 않는다.
- [ ] 완료 상태가 피드백 없이도 가능하다. 모든 학생에게 순서 고정 8단계를 요구하지 않는다.
- [ ] 데이터 삭제·다른 학기 이동 후에도 연결된 노트·파일·피드백의 보존 정책이 일관된다.

## 7. ST-04 — 공식 평가기준의 AI 쉬운 설명

```text
수행평가 상세 → 원본 평가기준 확인 → AI 설명 요청
→ 기준별 쉬운 용어·구체적 예시·준비 체크 사항 확인
→ 학생이 필요한 내용만 노트·계획에 직접 반영
```

- 원본 평가문서의 평가요소·배점·성취기준을 **우선 그대로 확인할 수 있게** 하고, AI 설명은 별도의 보조 영역에 표시한다.
- 설명은 기준을 학생이 이해하도록 돕는 것이지, 교사 의도·채점 결과·예상 점수를 공식 사실처럼 보증하는 기능이 아니다.
- 분석 대상 텍스트/원본 페이지를 표시해 학생이 원본으로 돌아갈 수 있다.
- AI 미사용·실패·재시도 상태에서도 공식 평가기준은 열람하고 노트는 작성할 수 있다.
- AI 설명을 학생 원본 노트나 공식 평가정보에 자동 적용하지 않는다.

## 8. ST-05 — 수행평가 꿀팁

| 팁 | 실제 설명·예시에서 다룰 사항 | 연결 가능한 기능 |
|---|---|---|
| 📚 교과와 연결 | 교과서 개념이 탐구 질문의 근거가 되는 방법 | 평가기준, 노트 |
| 🎯 진로 연결은 선택 | 관심 분야·진로 연결을 억지로 강제하지 않기 | 주제명 추천 |
| 🔍 주제 구체화 | 범위가 넓은 주제를 대상·방법·변수로 구체화 | 주제명 추천 |
| 📝 과정 기록 | 조사·실험·시행착오·협업·해결 과정 기록 | 탐구 노트 |
| 🔗 출처 정리 | 기사·논문·영상·통계의 출처/발행 연도 기록 | 자료함 |
| 🌱 후속 탐구 | 과정에서 생긴 새 질문을 별도 자율 Task로 발전 | 심화 탐구 |

```text
수행평가 꿀팁 → 6종 중 선택 → 설명·사례 확인
→ 필요하면 주제명 추천 / 노트 / 자료함 / 심화 탐구로 이동
```

- 팁 6개를 모두 읽거나 체크해야 다음 단계를 열어주는 방식은 사용하지 않는다.
- 팁은 강의자료나 AI 제안과 구분된 안내 콘텐츠다. 참고 영상에서 확인되지 않은 내용을 영상의 직접 인용처럼 만들지 않는다.
- 각 팁에서 돌아오면 이전 과제·탭 문맥을 유지한다.

## 9. ST-06 — 교과 중심 수행평가 주제명 추천

```text
수행평가 상세 → 주제명 추천 모달
→ 과목 / 교과 개념 / 현재 주제 / 목적·방법 / 관심사 입력
→ 3~5개 제목 후보 + 추천 이유 + 탐구 방향 확인
→ 비교·수정 → 학생이 명시적으로 선택·적용
```

| 기준 | 동작 |
|---|---|
| 추천 유형 | 교과 개념 중심, 교과+실생활, 교과+관심사, 선택적 진로 연계 |
| 후보 수 | 대략 3~5개. 결과가 없거나 불완전하면 그 이유를 설명하고 재시도 |
| 확정 권한 | 학생만 후보를 편집·선택하여 **자신의 개인 탐구/주제 정보**에 적용 |
| 공식 사실 보호 | 학교의 수행평가 원제목, 공식 채점기준, 학사정보를 AI 추천으로 덮어쓰지 않음 |

예: `세균에 대해 탐구하기` → `지수함수 모델을 활용한 세균 증식 패턴 분석` (교과 개념과 분석 방법을 구체화한 **제안 예시**, 학교 확정 과제가 아님).

진로 연결은 선택 사항이며, 어떤 후보도 세특/입시에 그대로 반영된다고 보장하지 않는다. 추천 실패 시 직접 입력할 수 있다.

## 10. 공통 Loading / Empty / Error / Permission

| 상태 | 대응 동작 |
|---|---|
| 학업정보 미설정 | 설정 진입 안내, 필요한 기본 항목 표시 |
| 수행평가 0건 | 추가/PDF 등록 유도, API 오류와 다른 빈 화면 |
| 과목·검색 결과 없음 | 필터 초기화·검색어 변경 제공 |
| PDF 업로드 중·실패 | 진행/재시도, 중복 제출 방지, 실패 파일의 저장 성공 표시 금지 |
| PDF 부분 추출·오인식 | 원본 페이지 비교·학생 수정·해당 항목 확인 필요 표시 |
| 이전 학년도 자료 | 과거 참고 배지 및 날짜 확인 요청 |
| AI 설명·추천 실패 | 수동 작업 유지, 재시도, 공식 원본 표시 |
| 미저장 변경/중복 등록 | 이탈 안내·중복 확인, 임의 데이터 손실 금지 |
| 인증 만료·권한 없음 | 다른 학생 기록 노출 없이 인증/권한 안내 |
| Existing LearnersHigh 오류 | 연동 실패 표시. 빈 수행평가로 위장하지 않음 |

업로드/분석/저장 버튼은 진행 중 중복 동작을 방지하고, 오류 복구 뒤 학생의 입력 내용과 목록 필터를 유지한다.

## 11. Cross-Surface 및 정보 보호

```text
Admin 학교 평가계획서 등록·검토
→ 해당 학교/학년/학기 범위의 공통 평가정보 제공
→ Student 원본 비교·개인 과제 생성·개인 수정
→ Authorized Admin이 학생 기록 조회
```

- 관리자가 공통 평가계획서를 수정해도 학생 노트·개인 정정·파일 이력은 삭제되지 않는다.
- 학생은 자기 자료만 편집하고, 관리자 읽기 권한은 담당 학생·기관 범위로 제한한다.
- 기존 Student Care/상담은 별개의 Wangyu-owned 영역이다. 구형 `School & Admissions`의 Topic 승인/강제 단계/면접 기능을 새 화면에 재구현하지 않는다.
