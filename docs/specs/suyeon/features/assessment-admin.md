# assessment-admin — 관리자 Assessment 운영

> 위치: `docs/specs/suyeon/features/assessment-admin.md`  
> 대상 Surface: **기존 LearnersHigh Admin Shell**의 `Assessment 관리`  
> 담당 기능: **AD-01~AD-13, AD-17** (`AD-14~AD-16`은 `assessment-feedback.md`)  
> 목적: 관리자 화면의 학생 Assessment 열람, 학교 평가계획서 분석, 심화 탐구 콘텐츠·참고자료 운영, 문서·버전 확인 및 활동 현황을 정의한다.  
> 상태: **Feature Spec 작성본**. 기존 Admin Shell·Wangyu Student Care 및 공통 API는 이 문서로 변경되지 않는다.

## 1. Scope / 기존 관리자 영역과의 관계

관리자는 **새 관리자 앱을 만들지 않고** 기존 좌측 내비게이션에 `Assessment 관리`를 추가한다. 기존 관리자 메뉴와 Student Care/상담 화면·라우트·데이터를 유지하고 그 아래에 Assessment 운영 기능을 새로 연결한다. 학생용 화면에 표시되는 `선생님께 피드백 요청`의 수신자는 이 관리자 기능이며 별도 Teacher Role/Surface는 없다.

**범위 제외:** 기존 Admin Student Care/상담 CRM의 재구현, 구형 Student 360·Today Board·Operations 전체 재구축, Mentor Case 추천, Parent Report, 대학 입시 면접 관리, 학생 작성 원문 직접 편집, 수행평가 승인·반려·필수 재제출.

## 3. AD-01 — 기존 관리자 화면 안에 Assessment 통합

### 관리자 정보 구조

```text
Existing LearnersHigh Admin (기존 Shell·Navigation 보존)
└─ 학습관리 / Assessment 관리
   ├─ 전체 현황
   ├─ 학생 Assessment
   ├─ 피드백 관리
   ├─ 학교별 평가계획서
   ├─ 심화 탐구 콘텐츠
   │  ├─ 심화 Task
   │  ├─ 모의고사 탐구 소재
   │  └─ 대학 공개 자료
   └─ 관리자 참고자료실
```

- 실제 최상위 메뉴 위치는 **기존 관리자 IA와 목업**을 함께 확인한다. 기존 Admin Shell을 다른 레이아웃으로 교체하지 않는다.
- '관리자'와 '선생님'은 별도 서비스가 아니라 동일 관리자 영역에서 운영한다. 별도 계정 종류·Role 값을 임의 추가하지 않는다.
- **권한 있는 관리자만** 학생 Assessment를 열람·피드백할 수 있다. 기존 소속 기관/지점/담당 학생의 접근 범위를 그대로 확인하며, 합의 없이 관리자 범위를 확장하지 않는다.
- 다른 관리자 기능을 지우거나 `frontend/admin/src/features/student-care/` 등 Wangyu 소유 코드를 수정하지 않는다. Assessment 진입점 추가를 위한 **Admin Shell/Sidebar/Router의 최소 변경은 Shared 변경 절차에 따라 허용**하되 기존 항목의 삭제·교체는 금지한다.

## 4. AD-02 — 학생 Assessment 조회

```text
Assessment 관리 → 학생 Assessment → 학생 검색/학교·학년 필터
→ 접근권한 있는 학생 선택 → 수행평가/심화 탐구 목록
→ 상세 → 노트·결과 파일·버전·자료·성장 기록 열람
```

권한 있는 관리자는 학생이 **피드백 요청을 보냈는지와 무관하게** 허가 범위의 기록을 읽을 수 있다.

| 상세 정보 | 표시/접근 원칙 |
|---|---|
| 학생 컨텍스트 | 학교·학년·학기·수강과목, 기존 Identity 재사용 |
| 학교 수행평가 | 과목, 제목, 일정·상태, 평가기준·공식 자료 출처 |
| 심화 탐구 | 공통 Task 또는 개인 Task, 과정·결과, 관련 학교 과제 |
| 탐구 과정 | 원본 Note·이모지 소제목·표·체크리스트·출처 링크·Revision |
| 결과 파일 | Artifact별 전체 버전, 크기·날짜·메모, 실제 미리보기/다운로드 |
| 성장 기록 | 활동 과정, 역할, 학생 성찰, 연결된 증빙 |
| 피드백 | 요청 당시 Snapshot과 답변·추천 자료·부분별 코멘트 |

- 열람은 **읽기 전용**. 학생의 텍스트·파일·성찰을 관리자 화면에서 대신 수정하지 않는다.
- 조회 시 현재 노트/최신 파일과 예전 피드백 요청 Snapshot을 분명하게 구분한다.
- 상담 내용·학생 케어 상태를 Assessment 상세에 자동 끌어오지 않는다. 필요하면 다른 도메인 담당자의 공개 계약을 검토한다.
- 학생 계정 인증/기관 Scope를 서버에서 검증하고 타인의 학생/파일 ID를 직접 호출하더라도 거부한다.

## 5. AD-03 — 학교별 평가계획서 PDF 관리

### 5-1. 등록 단위

```text
학교 → 학년도 → 학년(1/2/3) → 학기(1/2)
→ PDF 등록 슬롯 → DocumentRevision[] → 과목별 분석 결과
```

고등학교 **학년×학기 6개 슬롯**을 기본 화면으로 제공한다. 한 슬롯에 여러 원본/개정본을 등록할 수 있으며, `1 PDF=1 과목` 또는 `1 PDF=다수 과목` 어느 방식도 허용한다. 학교가 실제로 제공하지 않은 슬롯은 미등록으로 남겨야 한다.

### 5-2. 등록·수정 흐름

```text
학교별 평가계획서 → 학교 검색·선택 → 학년도 선택
→ 학년·학기 슬롯 → 원본 PDF 업로드
→ 학교·학년도·학기·출처 검토 → 분석 요청
→ 상태 확인 → 과목별 결과·원본 열람 / 개정본 등록
```

목록/상세에 필요한 항목:

- 학교, 학년도, 학년, 학기, PDF 이름·출처, 문서 등록자·업로드 시각, 마지막 수정일
- 분석 전/분석 중/확인 필요/완료/실패 등 **현재 진행 중인 분석 표시 상태** (정확한 Enum은 계약에서 확정)
- 원본 열람·권한 내 다운로드·개정본 추가·과목별 요약으로 이동
- 자료가 전년도 것이면 해당 학년도 그대로 표시; 올해의 공식 일정처럼 자동 승격하지 않음

PDF 원본 교체는 단순 overwrite가 아니라 **Revision 추적**이 가능하도록 해야 한다. 이미 학생이 확인·수정한 개인 평가정보를 소급 덮어쓰지 않는다.

## 6. AD-04~05 — 지필·수행평가 통합 분석과 추출 검토

### 6-1. 필요한 분석 항목

| 구분 | 상세 내용 |
|---|---|
| 공통 | 학교·학년도·학년·학기·과목 |
| 교수·학습 | 단원, 성취기준, 교수학습 방법, 평가 방법 |
| 평가 구성 | 지필평가·수행평가 전체 반영비율 |
| 지필평가 | 1차·2차 정기시험, 선택형/논술형, 만점·영역별 반영비율 |
| 수행평가 | 영역별 과제명, 수행 유형·시기, 만점·반영비율 |
| 세부 기준 | 평가요소·수준별 채점기준·배점 |
| 성취수준 | 성취기준·성취도 체계·기준 성취율 |
| 근거 | 실제 PDF 파일 식별자·페이지와 문서 인쇄 쪽 번호(확인 가능 시) |

지필 50%·수행 50% 같은 상위 구조뿐 아니라 **지필 1차/2차·각 수행평가 영역별 세부 비율/배점**도 확인할 수 있어야 한다. 예시 비율은 실제 학교 데이터가 아니다.

### 6-2. 원본 비교·수정·공개

```text
해당 PDF 분석 결과 → 과목 선택 → 종합 비율·지필 상세·수행 상세
→ AI 후보 값의 원본 페이지 표시 → 관리자 직접 대조/수정
→ 저장·확인된 정보가 학생용 공통 평가정보에 반영
```

- AI 추출 후보를 공식 사실로 자동 확정하지 않는다. 신뢰도 점수 유무와 무관하게 원본의 근거 위치를 추적할 수 있어야 한다. **PDF 등록·검토·공개 가능한 관리자 범위(전체/기관/지점)는 학생 기록 조회 권한과 별도로 확정해야 한다(OD-A08)**.
- PDF 한 페이지에 인쇄된 두 개 쪽이 포함될 수 있으므로 **PDF 페이지 인덱스와 인쇄 쪽 번호를 구별**한다.
- 원본에 없는 항목은 `미기재`, 찾을 수 없는 항목은 `추출 미확인`, 명백히 누락된 항목은 검토 대상으로 표시한다. `0`으로 임의 채우지 않는다.
- 비율·배점 합계가 불일치해도 공식 원문을 자동 보정하지 않는다. 관리자에게 검토 경고를 제공한다.
- 관리자 공통 정보의 재검토는 학생의 **개인 수행평가 상태·NoteRevision·ArtifactVersion·피드백 Snapshot**을 수정하지 않는다.
- 파일 분석/페이지 변환에 실패해도 원본 PDF 열람과 수동 검토·입력 경로를 남긴다.

## 7. AD-06 — 모의고사 지문 기반 탐구 소재 운영

| 입력 | 내용 |
|---|---|
| 원문 출처 | 학년도, 시행월, 학년, 과목, 문항 번호, 공식 확인 가능한 URL/허용된 파일 |
| 핵심 개념 | 지문 소재, 관련 교과 개념·학문 분야 |
| 탐구 확장 | 주제명·선정 이유·탐구 목표, 방법(관찰·실험·조사·비교), 심화 질문 |
| 보조 자료 | 실제 출처가 확인된 뉴스·논문·통계·영상 링크 |
| 운영 | 관리자 내부 메모, 태그, 임시저장/공개/비공개 상태(계약 확정 필요) |

```text
모의고사 탐구 소재 → 카드 등록 → 원문 출처 확인
→ 교과 개념·추천 주제·탐구 방법·참고자료 작성
→ 학생 카드 미리보기 → 공개 → Student 모의고사 탐구 카드에 표시
```

- 학생 공개 필드와 관리자 내부 메모는 분리한다. 내부 메모를 공개 카드에 자동 삽입하지 않는다. 등록·수정·공개 권한의 기관/지점 범위와 관리자 역할 정책은 OD-A08의 운영 권한 결정 전까지 임의 확장하지 않는다.
- 원문 PDF 또는 지문 이미지는 이용조건을 확인한다. 허가되지 않은 지문 전문·도표의 무단 배포 금지.
- 카드 수정·비공개 시 학생이 이미 시작한 개인 탐구 노트·Task는 변경되지 않는다.
- 모의고사 카드와 시험 응시/점수 채점 기능을 연결하지 않는다.

## 8. AD-07~08 — 관리자 참고자료실·스크랩

관리자는 학생용 참고자료의 자료원을 탐색하되, **개인 업무 메모와 콘텐츠 연결**을 별도 관리한다.

### 자료원 예시

- 뉴스·시사: 뉴닉, KBS 뉴스, 연합뉴스, YTN, 한겨레, 경향신문
- 영상: 크랩(KLAB), EBS·KBS 다큐, YTN 사이언스
- 논문·학술: ScienceON, RISS, DBpia, KCI
- 통계·공공데이터: KOSIS, 공공데이터포털
- 과학·인문: 사이언스올, 사이언스타임즈, 국립국어원, 국사편찬위원회, 연구기관 등

### 스크랩 항목과 흐름

```text
관리자 참고자료실 → 자료원 선택·원문 확인
→ 자료 저장(제목·유형·저자·기관·발행일·원본 URL)
→ 과목·태그·메모·탐구 주제 아이디어 작성
→ 수행평가/모의고사 카드/심화 Task/학생 피드백에 선택적 연결
```

- 내부 스크랩은 **기본 비공개**. 링크와 함께 학생에게 명시적으로 추천하거나 공개할 때만 학생에게 전달한다.
- 자료원 목록이 실제 개별 기사/논문 데이터 전체를 보유한다는 뜻은 아니다. 존재가 확인되지 않은 제목·출처·URL을 생성하지 않는다.
- 유료 자료·로그인 필요한 자료는 실제 접근 가능 범위를 표시한다.
- 스크랩 삭제가 이미 공유한 학생 피드백/노트의 출처 메타데이터를 조용히 제거하지 않도록 참조 정책을 검토한다.

## 9. AD-09 — 공통 심화 Task 운영

관리자 **공통 콘텐츠**와 학생의 **개인 진행 Task**를 분리한다.

```text
심화 탐구 콘텐츠 → 심화 Task → 생성
→ 제목·과목·교과 개념·문제 상황·목표·수행 안내 입력
→ 탐구 방법·참고자료·예상 결과물·자기점검 항목 추가
→ 저장·미리보기 → 공개 → Student 라이브러리에 노출
```

운영 행동: 목록 검색·필터, 신규 생성, 수정, 공개/비공개, 기존 Task와 원문/자료 연결, 보관. 실제 상태 Enum과 공개 권한은 API 계약 기준으로 확정한다.

- 공개 시 학생이 새로 시작하는 `EnrichmentTask`는 공통 원본의 시작 시점 데이터를 참조/복사할 수 있지만 **학생 소유 개별 기록**을 가져야 한다.
- 공통 Task 수정/비공개 이후에도 기존 학생의 노트·결과 파일·피드백·성장 기록은 보존한다.
- 관리자 Task를 학생이 학교 공식 수행평가로 등록한 것처럼 보여주지 않는다. 심화 Task에 자동 입시/진로 링크를 강제하지 않는다. 공개·수정·보관 가능한 관리자 범위는 OD-A08에서 별도 결정한다.

## 10. AD-10 — 대학 공식 공개 PDF 자료 운영

```text
심화 탐구 콘텐츠 → 대학 공개 자료 → 대학·학년도·분야/유형 선택
→ 공식 게시처·파일/URL·저작권/이용조건 확인
→ 문서 메타데이터 및 관련 교과·심화 Task 연결 → 공개
```

- 서울대학교·연세대학교·고려대학교·KAIST의 **공식 공개 자료**를 관리 대상으로 한다.
- 원본 메타데이터(문서명·대학·학년도·발행 주체·원본 URL·확인일)와 서비스가 작성한 탐구 아이디어를 분리한다.
- 원문 재배포가 허용되지 않는 경우 직접 PDF 보관·전송 대신 **공식 사이트 링크**를 제공한다.
- 이 영역은 학생의 탐구를 돕기 위한 참고 자료실이며 **면접 시뮬레이션·문답 채점·입시 예측 모듈이 아니다**.

## 11. AD-11 — 학생 탐구 노트 전체 열람

```text
학생 Assessment → 학생 선택 → 수행평가/심화 Task 상세
→ 탐구 노트 탭 → 학생 원본 블록·수정 이력 읽기
```

관리자가 보아야 할 내용: 학생이 작성한 **이모지 소제목, 본문, 표·체크리스트, 이미지, PDF/링크 카드, 출처, 과정 기록, 문제·해결·성찰**. 에디터가 렌더링한 원본 구조와 실제 학생 기록의 의미를 보존한다.

- **읽기 전용**. 관리자에게 학생 노트 수정/자동 저장/원본 블록 삭제 권한을 주지 않는다.
- 학생 최신 노트와 피드백 요청 시점 NoteRevision을 구분하고, 어떤 버전을 보는지 표시한다.
- 후속 조언은 별도의 `FeedbackReply`/`FeedbackComment`로 작성한다(`assessment-feedback.md`).
- Note 렌더링이 일부 미지원인 경우 내용을 손실 없이 확인할 수 있는 대체 열람/다운로드를 검토하며 가짜 편집 상태를 노출하지 않는다.

## 12. AD-12 — 학생 결과 파일 원본·미리보기 열람

| 결과물 | 관리자 열람 | 미지원 시 동작 |
|---|---|---|
| PDF | 페이지 이동, 확대/축소 가능한 문서 뷰어 | 허용된 원본 다운로드 |
| PPT/PPTX | 변환 가능한 경우 슬라이드별 미리보기 | 원본 다운로드/외부 열기 안내 |
| DOC/DOCX | 변환 가능한 경우 문서 미리보기 | 원본 다운로드 |
| HWP/HWPX | 호환 뷰어/변환 가능한 경우 열람 | 지원 불가 명시 + 원본 다운로드/외부 열기 |
| Google Docs URL | 권한·링크 유효성 확인 후 외부 열기 | 권한 없음/깨진 링크 안내 |
| XLSX/이미지 | 실제 뷰어가 지원하는 범위에서 미리보기 | 메타데이터·다운로드 |

```text
학생 상세 → 결과 파일 목록 → 결과물 종류·버전 선택
→ 해당 파일명·버전·크기·업로드 시각·메모 확인
→ 미리보기(지원 시) 또는 원본 다운로드 → 검토
```

- 학생이 업로드한 **진짜 원본 파일**과 변환·요약 미리보기를 구분한다. 임의의 샘플 문서/가상 Preview를 실제 학생 제출물로 보여주지 않는다.
- 파일 접근은 기관·학생 접근권한과 각 파일의 보안 정책을 서버에서 확인한다. URL만 알면 열람 가능한 공개 저장소로 만들지 않는다.
- 미리보기 불가 ≠ 파일 부재 ≠ 권한 없음 ≠ 서버 오류. 각 경우를 분리하여 안내한다.

## 13. AD-13 — 결과물별 버전 이력·두 버전 비교

```text
학생 결과 파일 → 보고서(Artifact A) 선택
→ v1/v2/v3 목록·설명 확인 → 개별 버전 열람/다운로드
→ (필요 시) 두 버전 선택 → 비교 지원 확인 → 나란히 확인
```

예시:

| 결과물 | 버전 | 파일 | 표시해야 할 관계 |
|---|---|---|---|
| 실험 보고서 A | v1 | 보고서_초안.docx | 이전 버전 |
| 실험 보고서 A | v2 | 보고서_수정.docx | 피드백 요청 당시 버전일 수 있음 |
| 실험 보고서 A | v3 | 보고서_최종.pdf | 최신 버전 |
| 발표자료 B | v1 | 발표자료_초안.pptx | **보고서 A와 별도 버전 계보** |

- 버전별 업로드 시각·형식·크기·메모·최신 여부·해당 피드백 요청을 조회한다.
- 실제 지원되는 형식이면 텍스트/페이지 차이 비교를 제공한다. **지원되지 않으면 두 원본 개별 열람 + 파일정보·변경 메모 비교**로 대체하고 가짜 자동 차이를 생성하지 않는다.
- 학생이 v3를 업로드해도 **v2에 작성된 피드백**과 요청 Snapshot은 v2를 계속 참조한다.
- 미리보기 공급자 및 형식별 정확한 비교 범위는 기술 검증 전까지 미확정이다.

## 14. AD-17 — 담당 학생의 Assessment 활동 현황

```text
Assessment 관리 → 전체 현황 또는 학생 Assessment
→ 담당 학교/학년/과목 필터 → 학생별 수행평가·심화 탐구·피드백 현황
→ 특정 학생/과제 선택 → 상세 열람
```

표시 정보: 학교·학년·과목별 수행평가, 과제 마감(실제 입력된 경우), `시작 전/진행 중/완료`, 탐구 진행 상태, 최근 Note/ArtifactVersion 변경, 피드백 `답변 대기/완료`, 심화 Task 시작/완료, 활동 기록.

- `수행평가 완료`와 `피드백 답변 완료`는 다른 상태다. 한 쪽 상태를 바꿔 다른 쪽을 자동 변경하지 않는다.
- 조회 가능한 학생/기관 범위에 해당하는 실제 원천 데이터를 집계한다. 가짜 KPI Counter/fixture 통계를 운영 데이터로 취급하지 않는다.
- 과거 학년·학기 데이터는 해당 Context와 함께 표현하며, 날짜가 없는 과제에 임의 마감일을 부여해 위험 알림을 만들지 않는다.
- 구형 Student 360/Operations를 통째로 다시 만드는 것이 아니라 **Assessment 전용 요약과 상세 연결**을 제공한다.

## 15. AD-14~16과의 접점 — 피드백 관리

이 문서는 피드백 작성 Workflow를 중복 소유하지 않는다. 다음 연결만 보장한다.

```text
학생 Assessment의 노트·결과물/이력 읽기
→ FeedbackRequest가 있을 때 '피드백 관리'로 이동
→ `assessment-feedback.md`에 따른 Snapshot 열람·전체/위치별 의견·추천
→ 학생에게 전달 / 원본 학생 기록 유지
```

피드백 없이도 관리자가 학생 기록을 열람할 수 있다. 관리자 열람 자체가 학생 요청이나 수행평가 완료 상태를 발생시키지 않는다.

- [ ] AI 추출 후보와 사람이 확인한 공통 평가정보, 학생 개인 수정정보가 분리된다.
- [ ] 모의고사 탐구 카드·심화 Task·대학 공개 PDF의 실제 출처·공개 상태가 Student와 일치한다.
- [ ] 관리자 내부 스크랩·메모를 학생에게 자동 공개하지 않는다.
- [ ] 학생 Note/Reflection은 구조를 유지해 읽기 전용으로 열람한다.
- [ ] PDF/PPTX/DOCX/HWP 등 실제 파일별 지원 뷰어·다운로드·오류 상태를 테스트한다.
- [ ] 독립된 Artifact 버전 이력 및 두 버전 선택·지원 범위 내 비교가 동작한다.
- [ ] 요청 Snapshot의 원본 버전 연결은 학생의 새 파일 추가 이후에도 유지된다.
- [ ] Assessment 완료 상태와 Feedback 답변 상태를 별도로 조회·집계한다.
- [ ] 빈 화면·로딩·오류·비공개·권한 제한/개인정보 누출·기존 Shell 회귀 테스트를 통과한다.

## 19. Open Decisions / 실제 구현 전에 확인

- Admin Shell 메뉴 연결의 실제 Router/Permissions와 기존 Auth·Organization/Branch Scope
- 학교 평가계획서 PDF 등록·Revision·AI 결과 확인/정정의 실제 DB·API와 사람 검토 승인 범위
- 관리자 공개 콘텐츠의 공개·비공개 Enum, 학생 시작 시 스냅샷/원본 변경 정책
- 파일 원본·변환·인쇄 쪽 번호·댓글 앵커와 PDF/PPTX/DOCX/HWP 뷰어 공급자
- 외부 모의고사/대학 원문·기사/논문 접근 및 재배포 이용조건
- 신규 Assessment의 Endpoint, DTO, Error/Status Codes. **피드백 공용 요청함은 ADR-0009가 문서상 결정했고**, 기존 Queue 코드 재사용/팀 승인 기록은 별도 확인
- 평가계획서·심화 Task·모의고사 소재·대학/참고자료의 **등록·검토·공개 운영 권한(전체/기관/지점/담당자)** 정책(OD-A08)
- 휴지통/보관 시 원본 학생 기록·피드백 Snapshot 보존 정책(OD-A11)

이 문서는 **신규 관리자 Assessment 기능의 Behavior Spec**이며 기존 프로젝트 전체 운영 정책을 대신하지 않는다. 실제 API·DB·코드·테스트 상태는 별도 소스와 `docs/specs/suyeon/progress.md`에서 확인한다.
