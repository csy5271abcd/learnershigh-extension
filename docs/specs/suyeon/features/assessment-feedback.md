# assessment-feedback — 학생·관리자 피드백

> 위치: `docs/specs/suyeon/features/assessment-feedback.md`  
> 대상 Surface: 기존 LearnersHigh **Student / Admin Assessment**  
> 담당 기능: **ST-14, ST-15, AD-14, AD-15, AD-16**  
> 목적: 학생 요청 당시 노트·결과 파일의 고정 Snapshot, 관리자 읽기·의견 작성·전송, 학생 확인·선택적 반영을 정의한다.  
> 상태: **Feature Spec 작성본(DRAFT)**. 신규 Assessment API 초안이 존재하지만, 실제 구현 완료와 구형 Queue API 재사용 확정을 의미하지 않는다.

## 1. Scope / 역할 구분

학생은 별도의 질문을 입력하지 않아도 `선생님께 피드백 요청` 버튼으로 **탐구 과정 노트와 자신이 선택한 결과 파일 버전**을 관리자에게 보낼 수 있다. 화면의 버튼 이름은 '선생님'을 유지해도 실제 수신자는 별도의 Teacher Surface가 아니라 **기존 관리자 화면의 `Assessment 관리 > 피드백 관리`**다.

| ID | 대상 | 기능 |
|---|---|---|
| ST-14 | Student | 질문 없이 노트 및 선택 파일 버전을 담아 요청 |
| ST-15 | Student | 답변·문서별 위치별 의견·추천 내용 열람, 선택적 수정·재요청 |
| AD-14 | Admin | 담당 학생의 피드백 요청 목록·상태·요청 시점 자료 확인 |
| AD-15 | Admin | 노트/문서 전체, 노트 블록·페이지·슬라이드·섹션별 피드백 작성 |
| AD-16 | Admin | 자료·교과 보완 방향·관련 심화 Task 추천 |

**제외:** 학생 질문 입력 필수, 주제 승인/반려, 관리자 검수 완료 후에만 과제 완료, AI 동의/제외/수정후전달의 구형 강제 검토 절차, 필수 재제출, 상담 CRM, 별도 Teacher 계정·앱.

## 3. Domain 관계와 반드시 유지할 불변조건

```text
Student / SchoolAssessment 또는 EnrichmentTask
  ├─ AssessmentNote ── NoteRevision r1, r2, r3 ...
  └─ Artifact A ── ArtifactVersion v1, v2 ...

FeedbackRequest F001 (요청 시각·작성 학생)
  └─ FeedbackSnapshot (immutable)
     ├─ Assessment Context (과목·제목·평가기준·시기·출처)
     ├─ NoteRevision r2 또는 동등한 본문 Snapshot
     ├─ 학생이 선택한 ArtifactVersion A-v2 / B-v1
     └─ 해당 요청의 출처/자료 링크
  └─ FeedbackReply
     ├─ 전체 의견
     ├─ 대상 버전·위치별 FeedbackComment[]
     └─ 추천 Resource / EnrichmentTask[]
```

- `FeedbackRequest`는 특정 학교 수행평가나 심화 Task에 연결된다. 해당 과제가 어떤 유형인지에 따라 공식 기준의 유무가 달라도 같은 선택형 피드백 원칙을 사용한다.
- **요청 당시 읽기 가능한 Note 본문·선택 ArtifactVersion**이 고정되어야 한다. 이후 학생이 노트를 편집하거나 v3를 올려도 요청 F001이 가리키는 r2/v2가 변경되면 안 된다.
- `FeedbackComment`는 대상 노트/문서 식별자뿐 아니라 **요청 Snapshot 내의 특정 버전**에 연결된다. 같은 파일명의 새 업로드에 피드백을 자동 옮기지 않는다.
- 노트가 없어서는 안 되는지 여부는 요청 모달에서 안내하고, 최소한 **결과 파일이 없는 노트만으로 요청**할 수 있다. 질문은 **필수 입력이 아니다.**
- 원본/버전과 관리자 의견은 서로 다른 저작물이다. 관리자가 학생 작성 원문을 직접 수정하지 않는다.
- 관리자 `Assessment 학생 기록 열람`은 피드백 요청과 독립된 권한 있는 조회다. 관리자가 요청 없이 노트를 열람할 수 있다는 이유로 **자동 피드백 요청**이 생성되지는 않는다.

## 4. ST-14 — 질문 없는 학생 피드백 요청

### 사용자 흐름

```text
학교 수행평가 또는 심화 Task 상세 → 노트 편집
→ 선생님께 피드백 요청 클릭
→ 노트 자동 저장 완료 및 요청 기준 Revision 확정
→ (선택) 검토받을 결과 파일/각 파일 버전 선택
→ 요청 내용·첨부 파일·시점 확인 → 전송
→ 답변 대기 표시 / 관리자 요청 목록에 반영
```

요청 확인창에는 다음을 표시한다.

| 구분 | 필수/선택 및 의미 |
|---|---|
| 학생·과제 정보 | 학생·과목·수행평가 제목/심화 Task, 요청 시각, 이용 가능한 평가기준 |
| 과정 노트 | 요청 기준 NoteRevision 또는 저장된 본문 Snapshot, 출처·표·체크리스트·이미지 포함 |
| 결과물 | **선택 사항**. 학생이 체크한 결과물과 **특정 버전** 목록 |
| 참고자료 | 요청 범위의 출처 링크/노트 내 링크 카드 |
| 질문 문장 | **입력란 불필요**. 요청 전송을 막는 필수 질문 없음 |

- 노트 자동저장이 끝나지 않았다면 `요청 성공`으로 표시하지 않는다. 저장 실패/재시도 또는 기존 저장 Revision으로 요청할지 명확히 안내해야 하며 **미저장 텍스트를 무단 누락**하지 않는다.
- 파일 업로드 중인 버전을 `업로드 완료`로 가정하지 않는다. 선택 파일 목록의 크기·유형·버전 표시를 확인시킨다.
- 대기 중인 **동일 범위의 요청**은 더블 클릭/재시도에 의해 중복 생성되지 않아야 한다. 같은 과제에서 실제로 다른 NoteRevision/파일 버전을 다시 요청하는 정책은 별도 계약으로 정한다.
- 요청 실패 후 기존 텍스트와 파일 선택 상태를 보존한다. 네트워크 재시도 결과가 불명확할 때 중복 요청 생성 여부를 확인할 수 있어야 한다.
- 요청 취소는 `domain.md`에 개념이 있으나, **답변 전 취소 허용·파일 보존·상태 Enum**은 공통 계약 확정 전 필수 기능으로 단정하지 않는다.

### 수용 기준

- [ ] 결과 파일이 없어도 저장된 노트만으로 요청을 보낼 수 있다.
- [ ] 질문 작성란을 강제하지 않고 요청 확인·전송이 가능하다.
- [ ] 전송 후 r2/v2 등 당시 버전 연결을 관리자/학생 화면에서 동일하게 확인한다.
- [ ] 요청 실패·중복 클릭·서버 응답 지연에도 스냅샷 무결성이 유지된다.

## 5. AD-14 — 관리자 피드백 요청 목록·상세

```text
기존 관리자 화면 → Assessment 관리 → 피드백 관리
→ 전체 / 답변 대기 / 답변 완료 목록 → 학생·과제·과목 검색/필터
→ 요청 선택 → 요청 당시 노트·결과 파일 목록 및 버전 열람
```

목록: 학생 식별정보(허가된 범위), 과목, 과제/심화 Task, 요청 시각, 결과 파일 수, 요청 대상 파일 버전, 답변 상태, 마지막 응답 시각(있는 경우). 업무 현황 수치는 실제 `FeedbackRequest` 상태에서 파생한다.

- **담당 기관·학생 권한 확인은 서버에서 수행**한다. 다른 관리자/지점 학생 정보를 화면에서만 숨겨 접근 차단한 것으로 취급하지 않는다.
- 목록은 피드백 요청 중인 학생의 Snapshot으로 이동한다. 학생의 **최신 문서**와 **요청 당시 문서**를 혼동하지 않도록 상단에 고정 표시를 둔다.
- 요청 당시 노트·선택 파일이 권한 변경/삭제/미리보기 불가인 경우, 정책상 허용되는 데이터만 보여주고 그 이유·상태를 명확히 표시한다.
- 같은 학생에 대한 요청 2건이 서로 다른 r2/v2, r3/v3을 참조할 수 있으며, 날짜와 버전을 기준으로 구분해야 한다.
- 요청이 없는 학생 기록은 `학생 Assessment` 상세에서 별도로 조회할 수 있다(`assessment-admin.md`).

## 6. AD-15 — 문서 전체·위치별 상세 피드백

### 관리자 작성 유형

1. **전체 의견**: 해당 노트/결과 파일의 전체적인 잘한 점·보완할 점·논리성·근거·내용 정확성.
2. **부분별 의견**: 실제 지원되는 위치에 고정된 구체적 코멘트.
3. **학생에게 전달할 요약**: 자유 문장. 승인·반려 같은 최종 판정값을 요구하지 않는다.

| 대상 | 위치 선택 예시 | 지원 한계 |
|---|---|---|
| 탐구 과정 노트 | 본문 블록/소제목/섹션 | 해당 `NoteRevision`에 고정 |
| PDF | 페이지 번호 | 원본 PDF 페이지와 인쇄 쪽 번호 혼동 방지 |
| PPT/PPTX | 슬라이드 번호 | 실제 슬라이드 뷰어/변환 가능해야 위치 지정 |
| DOCX/HWP 등 | 지원되는 경우 섹션·문단 | 뷰어가 위치를 보장하지 못하면 **문서 전체 의견** |
| 이미지/XLSX | 실제 뷰어가 지원하는 영역 | 지원되지 않는 선택 좌표 임의 생성 금지 |

**부분별 의견 예시 (내용 예시이지 실제 저장 데이터 아님)**

- `실험보고서 v2 · PDF 3쪽`: 측정 오차를 그래프와 연결해 설명해보도록 제안.
- `발표자료 v1 · 5번 슬라이드`: 통계 자료의 조사연도와 출처 표기 제안.
- `보고서 v2 · 결론 섹션`: 본문 분석 결과와 결론의 연계 개선 제안.

```text
요청 상세 → 노트 Snapshot 확인 → 대상 결과 파일 버전 열기
→ 전체 의견 / (지원되면) 위치 선택 후 부분 의견 작성
→ 필요한 보완 방향·추천 자료 선택 → 미리보기 → 학생에게 전달
```

- 관리자 의견 저장(작성 중)과 **학생에게 전달 완료** 상태를 구분한다. 저장 실패 시 전달됨으로 표시하지 않는다.
- 관리자 본문 수정은 피드백 기록 편집 권한 내에서만 가능하고 학생 Note/Artifact 원본은 읽기 전용이다.
- `Location` 정보와 파일/노트 버전이 결합된 상태로 저장·조회되어야 하며, 원본 변환 결과가 변경되었을 때 코멘트 위치가 틀어지지 않도록 처리한다.
- 한 위치를 클릭하면 해당 파일/버전/쪽 번호에 대응하는 의견만 보여준다. 다른 과제·버전의 댓글이 섞이지 않는다.

## 7. AD-16 — 다음 학습·심화 탐구 추천

학생 피드백 본문에 **학생이 선택할 수 있는 후속 제안**을 첨부할 수 있다.

| 유형 | 추천 예시 | 데이터 출처 |
|---|---|---|
| 내용 보완 | 실험 오차 추가 분석, 결과 해석 보강 | 관리자 자유 의견 |
| 근거 보완 | 공식 통계·관련 논문 확인 | 관리자 참고자료실의 실제 링크 |
| 교과 복습 | 연관 개념·단원 복습 | 확인된 과목·교과 정보 |
| 후속 조사 | 관찰·비교·설문·추가 실험 제안 | 관리자 자유 의견 |
| 심화 Task | 공개된 관리자 공통 Task 또는 학생에게 개별 제안 | 공개 Task/관리자 메시지 |
| 모의고사 소재 | 관련 교과 개념의 탐구 카드 | 실제 공개·허용된 카드 |

관리자 개인 참고자료/메모가 학생에게 **자동 공개되어서는 안 된다**. 전달하려는 링크·Task만 명시적으로 선택한다. 추천을 수락하지 않아도 수행평가·피드백은 정상적으로 완료/열람 가능하다.

## 8. ST-15 — 학생의 답변 확인·선택적 반영

```text
Assessment → 선생님 피드백 → 전체 / 답변 대기 / 답변 완료
→ 요청 상세 → 당시 노트·파일 버전과 관리자 의견 확인
→ 전체 의견·부분별 의견·참고자료·후속 Task 열람
→ 필요 시 학생 스스로 노트 수정 또는 새 파일 v3 업로드
→ 필요 시 새 Snapshot으로 피드백 재요청
```

- 기존 피드백에서 받은 코멘트는 **항상 당시 문서/버전**에 남는다. 학생이 새 v3를 만들어도 v2 피드백을 자동으로 v3의 위치 의견으로 옮기지 않는다.
- `읽음/확인` 같은 UI 상태와 관리자 `답변 완료` 업무 상태는 구분한다. 실제 저장/전송 정책은 API 계약에서 확정한다.
- `피드백 반영 여부`는 학생에게 도움 되는 **선택적 자기 관리 정보**일 수 있지만, 강제 체크·관리자 승인·재제출 상태로 만들지 않는다.
- 학생은 피드백 없이 수행평가를 `완료`로 바꿀 수 있다. `SchoolAssessment=완료, FeedbackRequest=답변 대기`가 가능한 상태다.

## 9. State / Cross-Surface 동기화

| 대상 | 상태/표시 | 독립성 |
|---|---|---|
| `FeedbackRequest` | `PENDING`(답변 대기) → `DELIVERED`(답변 완료); 취소 정책 미확정 | 수행평가 진행 상태와 분리 |
| `SchoolAssessment` / `EnrichmentTask` | 시작 전 / 진행 중 / 완료 | 요청 생성·답변 전달로 강제 변경하지 않음 |
| `NoteRevision` | 학생의 저장된 Revision | 요청 당시 Revision을 보존 |
| `ArtifactVersion` | 결과물별 v1/v2/v3 | 전송 후 새 Version으로 자동 교체하지 않음 |
| `FeedbackReply` 임시 작성 | `DRAFT_SAVED`(관리자 내부) → `DELIVERED`(학생 공개); 실패 시 대기 유지 | 학생에게 보이는 `답변 완료`와 혼동하지 않음 |

```text
학생 요청 확정
→ Snapshot 동결 + Admin 목록에 요청 노출
→ 관리자 답변 저장·전달
→ Student 피드백 상세 및 답변 완료 상태 갱신
→ 학생 필요에 따라 자율적인 수정/추가 버전
```

위 과정에서 알림 표시·읽음 기록·메시지 전송은 실제 공통 Notification Provider/계약 확인 후 붙인다. **학생 Assessment 홈의 ‘답변 도착’ 표시는 전달 완료된 요청을 요약하는 UI 목표**이지만, 신규 알림 발송/읽음 기록 API는 현재 계약에 없으므로 별도 구현 확정이 아니다. 알림 실패를 피드백 Reply 저장 실패와 혼동하지 않는다.

## 10. Loading / Empty / Error / Privacy

| 상황 | 필요한 화면 동작 |
|---|---|
| 학생 요청/답변 목록 없음 | 안내와 새 요청 진입 링크. API 실패와 구분 |
| 요청 시 노트 저장 중/실패 | 진행 안내·재시도·원문 보존. 전송 성공 처리 금지 |
| 업로드 완료 전 버전 선택 | 잘못된 미완성 Version을 Snapshot에 포함하지 않음 |
| 동일 요청 중복 제출 | 진행 버튼 비활성/결과 확인, 중복 기록 방지 |
| 관리자 권한 없음 | Student·Note·파일·댓글 정보를 노출하지 않음 |
| 특정 파일 미리보기 불가 | 해당 버전 정보·허용된 다운로드/외부 열기 안내 |
| 댓글 위치 지정 미지원 | 문서 전체 피드백 제공, 가짜 페이지 마커 금지 |
| 관리자 저장/전달 실패 | 학생에게 완료 표시 금지, 관리자 입력 보존·재시도 |
| 원본 삭제/보존 정책 충돌 | Snapshot 보존 요구와 개인정보 삭제 의무를 함께 검토. 임의 영구 보관 금지 |
| Existing/Provider 오류 | '요청 없음'처럼 보여주지 않고 오류·재시도 표시 |

개인정보는 기관·담당자 권한에 따라 필요한 범위만 제공한다. Wangyu 학생 케어/상담 메모와 피드백 Snapshot을 자동 병합하지 않는다.

## 11. Acceptance Checklist

- [ ] ST-14·15 / AD-14·15·16의 실제 학생↔관리자 왕복 흐름을 검증한다.
- [ ] 질문 없이 요청 가능하며 **노트만 포함해도** 요청된다.
- [ ] 요청 당시 NoteRevision과 선택 파일 Version이 이후 수정·업로드에 영향을 받지 않는다.
- [ ] 결과물 종류가 여러 개여도 각각 선택한 Version만 Snapshot에 포함된다.
- [ ] 관리자 답변·전체/부분 의견은 대상 문서의 특정 Version/위치에 연결된다.
- [ ] PDF 쪽·PPT 슬라이드·지원되는 문서 섹션 외의 가짜 위치 피드백을 만들지 않는다.
- [ ] 관리자 원본 노트/파일은 읽기 전용이고, 직접 수정은 거부된다.
- [ ] 담당 기관/학생 권한을 서버에서 확인하며 미권한 요청에서 PII가 누출되지 않는다.
- [ ] 승인/반려·의무 재제출·강제 피드백 없이 과제 완료가 가능하다.
- [ ] 저장 중·오류·빈 목록·미지원 미리보기·중복 전송·재시도 흐름을 테스트한다.
- [ ] ADR-0009의 공용 요청함·무자동배정 원칙을 따르고, 구형 Queue 코드/API의 물리적 재사용은 별도 검토한다.
