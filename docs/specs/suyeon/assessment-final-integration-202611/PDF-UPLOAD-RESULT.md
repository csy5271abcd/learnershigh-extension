# Admin PDF 등록·개정 결과 (2026-11-10)

도달 수준: **브라우저 조작 검증 완료.** 이번에 Frontend 코드를 고치지 않았다. 지난 작업의 Adapter와 안내 문구가 그대로 동작했다. 합성 PDF만 사용했다(v21.1 `synthetic-e2e.pdf`, 30,783 byte, 2쪽).

## 1. 업로드 성공의 의미

**PDF 메타데이터와 Revision 등록 성공**이다. 서버는 파일 이름·크기·SHA-256·쪽 수만 저장하고 원본 바이트는 보관하지 않는다(`file_ref` NULL).

- 화면 안내: "서버는 원본 PDF를 보관하지 않고(파일 메타데이터·SHA-256·쪽 수만) 서버 분석도 아직 없어요. 분석 결과는 외부 분석기 수신으로만 들어와요."
- "원본 PDF" 버튼은 비활성이다(서버 열람·다운로드 없음).
- 업로드로 분석이 시작되지 않는다. 문서 카드는 "분석 요청" 상태로 남는다(서버 분석 실행 Endpoint 없음).

## 2. 브라우저 검증 (12건 PASS)

화면 경로: Admin → 학교별 평가계획서 → `school_001` 2026학년도 고1 1학기 칸 → "이 칸에 PDF 추가".

| # | 경우 | HTTP | 화면 | DB |

| 2 | 빈 파일(0 byte `.pdf`) | 415 | 파일 오류 | 변화 없음 |

참고:

- 빈 파일은 서버가 415(PDF 아님)로 거절했다. 지시서의 "빈 파일" 오류 코드가 계약에 따로 없어 기존 서버 동작을 그대로 기록한다.
- "파일 선택 없이 등록"은 등록 버튼이 비활성이라 요청이 나가지 않는다(기존 화면 동작, 이번 스크립트에서 별도 검사는 하지 않음).
- 서버 500은 재현하지 않았다(검증 안 함).
- 6은 Playwright로 요청을 끊어 만든 상황이다.

## 3. 이어진 흐름 (합성)

등록한 Revision 1에 v21.1 분석기 JSON 원본을 수신 API로 보냈다(201, `UNREVIEWED`). 그 뒤 관리자 검토 화면에서 원본 대조·과목 매핑·확정까지 이어서 확인했다(`ADMIN-REVIEW-RESULT.md`).
