# Student 수행평가 수정 결과 (2026-11-10)

도달 수준: **브라우저 조작 검증 완료** (Chrome + Playwright 라이브러리, 실제 Backend 18080, 로컬 MySQL `lh_assessment_final2`, 개발용 Mock 인증 `stu_001`). 운영 환경 검증 아님.

## 1. 구현

- 상세 화면의 기존 "평가 정보 수정" 버튼(이전에는 안내 Toast만)을 새 Modal `EditSchoolAssessmentModal`에 연결했다. 디자인은 기존 등록 Modal의 `Modal`·스타일을 그대로 쓴다.
- 수정 가능: `title`(필수, 200자), `deadlineDate`(비우면 null = 날짜 미정), `description`(2000자).
- 바꿀 수 없음(요청에 넣지 않음): Assessment ID·학생·과목·상태·`evaluationItemRef`·평가계획서·AI 결과.
- **바뀐 필드만** PATCH로 보낸다. 보내지 않은 필드는 서버에서 유지된다(Backend 규칙).
- 설명: §12 상세 응답에 `description`이 없어 기존 설명을 입력칸에 채울 수 없다. 그래서 "설명 바꾸기"를 켤 때만 보내고, 켜고 비우면 지운다. 안내 문구로 이 사실을 화면에 표시한다.
- 저장 성공 → Modal 닫기 → Toast → `notifyDataChanged()`로 상세·목록을 **서버에서 다시 조회**한다(응답 값을 그대로 화면에 쓰지 않음).
- 오류 처리: 필드 오류(`required`·`size`·`format`)는 입력 옆에, 404는 "찾을 수 없어요(ASSESSMENT_NOT_FOUND)", 그 밖(401·네트워크 등)은 "입력한 내용은 그대로 있어요" + 코드. 실패 시 Modal과 입력값을 유지한다.
- 중복 제출 방지: `submittingRef` + 버튼 비활성. 바뀐 내용이 없거나 제목이 비면 저장 비활성.
- 관리자 읽기 전용 보기(P-28)에서는 버튼 비활성, Modal 대신 기존 차단 안내.
- Mock 모드: 같은 함수(`updateSchoolAssessmentMock`)로 동작(브라우저 확인).
