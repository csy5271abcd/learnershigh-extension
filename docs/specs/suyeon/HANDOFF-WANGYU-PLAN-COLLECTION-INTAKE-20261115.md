# Suyeon(계정 A) → Wangyu: 학교알리미 평가계획서 자동 수집 결과 연동 입력 계약 (제안 · 2026-11-15)

> 상태: **제안(미합의)**. 자동 수집기 코드·API는 Wangyu 소유이며 계정 A는 수정하지 않는다. 이 문서는 수집 결과가 Assessment의 기존 등록·분석·검토·확정 파이프라인으로 들어오기 위해 필요한 입력과 결정 사항만 정리한다. 자동 수집 API 규격은 Wangyu와 합의해 확정한다.

## 1. 목표 흐름

```
(Wangyu) 학교 이름 입력 → 학교알리미 공시 문서 수집
   ↓ 아래 §2 입력
(Assessment) 원문 등록(Revision) → 서버 분석(계정 B 분석기) → 후보 저장 → 관리자 검토 → 확정 → 학생 공개 · 학년도 비교(§38-5)
```

수동 업로드와 자동 수집은 **같은 등록 API·같은 저장 구조**를 쓴다. 수집 결과라고 검토·확정 단계를 건너뛰지 않는다.

## 2. 필요한 최소 입력 (문서 1건)

| 항목 | 필수 | 현재 Assessment에 있는 곳 | 비고 |
|---|---|---|---|
| 학교 식별자 `schoolId` | ✓ | 등록 API `schoolId` | **학교 이름이 아니라 코드**(동명이교 구분). 코드 체계는 1팀 학교 Master(API-OD-A01) 기준 — 합의 필요 |
| 학교명 | 표시용 | 학업 Context에서 확인 | 수집기가 보낸 이름은 표시·대조용, 식별에 쓰지 않음 |
| 학년도 `academicYear` | ✓ | 등록 API | 공시 문서의 학년도. 원문 표기와 다르면 관리자 검토(아래 §4) |
| 학년 `grade` · 학기 `semester` | ✓ | 등록 API | 학년·학기 통합 문서는 결정 필요(§5-3) |
| 원본 파일(PDF·HWP·HWPX) | ✓ | multipart `file` | 서버가 바이트로 형식을 판별·보관 |
| 파일 형식 | 참고 | 서버가 판별 | 수집기 값과 다르면 서버 판별이 우선 |
| 출처 URL | 권장 | 등록 API `sourceUrl` (기존) | 학교알리미 게시 주소 |
| 원본 SHA-256 | 권장 | 서버가 계산해 저장 | 수집기가 보내면 서버 계산값과 대조(불일치 거절) — 추가 필요 |
| 수집 시각 `collectedAt` | 권장 | **없음** | 추가 필요(Revision 메타데이터) |
| 공시 문서 식별자 | 있으면 | **없음** | 학교알리미 문서 ID 등 — 같은 공시의 재수집 판별에 사용 |
| 출처 구분 `sourceKind` | 권장 | **없음** | `MANUAL_UPLOAD` / `AUTO_COLLECTED` (제안) |

## 3. 중복·병합 규칙 (현재 동작 + 제안)

- 같은 문서(Plan)에 같은 원문(SHA 동일) 재등록 → 이미 거절(409).
- **다른 학년도에 같은 원문**이 등록되면 학년도 비교 응답에 경고를 낸다(§38-5 `warnings`, 구현됨). 자동으로 합치거나 지우지 않는다.
- 제안: 공시 문서 식별자가 같고 SHA가 같으면 "이미 수집됨"으로 응답(새 Revision 없음), SHA가 다르면 같은 Plan의 새 Revision(공시 문서 교체)으로 등록.

## 4. 학년도 충돌

원문 안 학년도 표기와 등록 학년도가 다르면 자동으로 고치지 않고 관리자 검토를 요구한다. 계정 B 0.3 제안의 issue `CONTEXT_CONFLICT`(학년·학기 불일치)를 받으면 검토 화면에 표시한다. 0.2 결과에는 학년도 정보가 없어 지금은 검사하지 못한다.

## 5. 결정이 필요한 것

1. 수집 결과 전달 방식: 수집기가 Assessment 등록 API(관리자 인증)를 호출 / Assessment가 수집 결과 저장소를 조회 / 공유 큐.
2. 학교 코드 체계(1팀 학교 Master와 같게).
3. 학년·학기가 한 파일에 합쳐진 공시 문서 처리(문서 1건을 여러 슬롯에 등록할지).
4. `collectedAt`·공시 문서 식별자·`sourceKind` 저장 위치(Revision 컬럼 추가 = 새 Migration, 계정 A 구현).
5. 수집 실패·부분 수집(파일 없음, 형식 미지원)의 표시 방법 — 학년도 비교 화면은 문서 없음(`NO_PLAN`)으로 표시한다.

## 6. 계정 A가 지금 하지 않은 것

자동 수집 API·수집기 연동 코드, 새 메타데이터 컬럼(합의 후 구현), 학교 Master 연결. Student Care·상담·자동 수집기 코드는 변경하지 않았다.
