# 결과물 버전 비교

## 방식

`GET .../artifacts/{artifactId}/compare?fromVersionId=&toVersionId=` (§25-1·§37 Shape)

- 같은 결과물의 서로 다른 두 버전만 비교한다. 같은 버전이면 400, 다른 결과물의 버전이면 404다.
- `mode`는 항상 `METADATA_ONLY`다. 파일 내용(문장·쪽)을 비교하는 엔진이 없어서 "변경 문장 자동 비교"를 표시하지 않는다.
- `changes`에는 실제로 다른 항목만 담는다: 파일 이름·형식·크기·SHA-256(지문)·올린 시각·변경 메모.

## 화면

- Student: Viewer 상단에서 "비교할 버전"을 고르거나 결과물 카드의 "버전 비교"(최신 vs 바로 이전)를 누른다. 위에는 파일 정보 표(다른 칸 강조, 지문이 같은지 다른지)가 나오고, 아래에는 왼쪽 이전 버전·오른쪽 나중 버전 원본이 나란히 나온다. PDF·이미지는 각자 미리보기, 미지원 형식은 파일 정보와 내려받기만 보여 준다.
- Admin: 기록 도구 "버전 비교"가 http 서버 비교를 쓴다(이전에는 Mock 전용). 항목 이름을 한국어로 바꿔 보여 준다.

## 무결성

비교는 조회만 한다. 비교한 뒤에도 v1 원본 SHA가 그대로임을 E2E로 확인했다. 피드백 Snapshot이 가리키는 이전 버전도 그대로다.

## 한계

- 동기 스크롤은 없다. PDF는 브라우저 내장 보기라 페이지 간 스크롤 동기화를 제어할 수 없다.
- HWP·HWPX·DOCX 내용 비교와 PDF 텍스트 Diff는 없다(안전한 변환기·추출기가 없음).
