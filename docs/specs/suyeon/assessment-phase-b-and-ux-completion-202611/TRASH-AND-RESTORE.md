# 삭제·휴지통·복원

## 정책 (사용자 지시, OD-A11 일부)

- 즉시 영구 삭제와 자동 영구 삭제는 없다. 영구 삭제 Endpoint도 만들지 않았다.
- 보존 기간, 영구 삭제, 개인정보 삭제 의무는 OD-A11·API-OD-A08에 미결로 남겨 두었다.
- 삭제 표시(`deleted_at`·`deleted_by`, `V202611111620`)는 상위 항목에만 한다. 노트 Revision, 결과물 Version, 피드백 요청·Snapshot·답변, 실제 파일 바이트는 바꾸지 않는다.

## 대상

| 대상 | 삭제 | 복원 | 비고 |
|---|---|---|---|
| 학생 수행평가 | `DELETE /school-assessments/{id}` (§12) | `POST /archive/restore` | 그 노트·결과물도 함께 가려진다(소유 확인이 활성 수행평가만 통과) |
| 결과물 | `DELETE /artifacts/{id}` | 같음 | 상위 수행평가가 휴지통이면 결과물만 복원 불가(400 `parent_in_trash`) |
| 개인 자료 | `DELETE /resources/{id}` | 같음 | |
| 성장 기록 | `DELETE /growth-records/{id}` | 같음 | |
| 관리자 참고자료 | `DELETE /reference-library/{id}` (§43) | `POST /reference-library/{id}/restore`, 목록 `GET /reference-library/trash` | 만든 관리자만. 공개 중이던 자료는 학생 공개 목록에서 빠지고, 복원하면 다시 나온다 |
| 탐구 노트 | 따로 삭제하지 않음 | — | 수행평가와 1:1이다. 수행평가 휴지통으로 함께 가려진다 |
| 공식 평가계획서·확정 기록·피드백 감사 기록 | 삭제 없음 | — | 참조 무결성 보호 |

- 학생은 본인 것만, 관리자는 본인이 만든 자료만 삭제·복원한다. 남의 ID는 존재 여부도 드러내지 않고 404다.
- 휴지통에 든 결과물은 새 버전, 피드백 요청, 성장 기록 연결, 학생 미리보기에 쓸 수 없다.
- 관리자 피드백 상세(요청 당시 노트·파일)와 관리자 파일 열람은 휴지통과 상관없이 유지된다(감사 기록).

## 화면

- Student
  - 수행평가 상세 "휴지통으로 이동"
  - 결과물 카드 "휴지통"
  - 자료 상세·성장 기록 상세 "휴지통으로 이동"(확인 대화상자 있음)
  - 보관함 › 휴지통 탭: 유형·제목·삭제 시각·원래 소속(예: "수행평가 'X'의 결과물"), "복구" 버튼
- Admin: 참고자료실 › 내 스크랩 › 삭제 확인 → "휴지통" 펼침 목록 → "복원"
- Mock 모드에는 휴지통이 없다고 안내한다(Mock 값을 꾸며 내지 않음).

## 검증

| 항목 | 결과 |
|---|---|
| 결과물 휴지통 → 목록에서 빠짐 → 휴지통 탭 표시 → 화면에서 복구 → 같은 ID·v1·v2 | E2E |
| 휴지통 상태에서도 관리자 피드백 Snapshot(r1·v1)·답변·파일 보존, 학생 전달 답변 그대로 | E2E·통합 테스트 |
| 수행평가 휴지통 → 노트 접근 404 → 결과물 먼저 복원 400 → 수행평가 복원 → Revision 그대로 | 통합 테스트 |
| 성장 기록·자료 삭제·복원, 다른 학생 404 | 통합 테스트 |
| 실제 파일 수·Snapshot 행 수 줄지 않음 | 통합 테스트 |
| 관리자 자료 휴지통 → 학생 공개 목록에서 빠짐 → 화면에서 복원 → 다시 표시, 다른 관리자 삭제 404 | E2E·통합 테스트 |
