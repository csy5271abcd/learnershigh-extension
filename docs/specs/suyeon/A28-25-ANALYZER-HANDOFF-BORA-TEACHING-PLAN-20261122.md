## 4. 변경 제안(분석기 담당 구현용)

1. `TeachingPlanRules.rows(List<List<String>> g, Integer monthFromContext)` 오버로드(기존 `rows(g)` 는 `rows(g, null)` — 기존 동작 그대로).
   - 머리 줄에 `MONTH` 열이 **없고** `WEEK` 열과 (`UNIT` 또는 `STANDARD`) 열이 있으며 `monthFromContext != null` 일 때만 진도표로 인정.
   - 각 행: `month = monthFromContext`, `monthTo = null`(행 시기에 월 범위가 따로 없으면), 주는 기존 `WEEK` 해석(`3-4` → 3~4, `1~2`, `5`) 그대로. `weekLabel` = 원문 주 표기. **날짜를 만들지 않는다**(정밀도 `WEEK_IN_MONTH`, 학기 누적 주차 아님).
   - `evidence` 는 원문 주 표기 + 단원(기존 규칙)과 함께 월 출처를 남긴다(예 `"■ 9월 · 1~2"`).
2. `PlanExtractor` (5) 진도표 연결 단계에서 표마다 월 문맥을 구한다:
   - `ctx` 의 **마지막** `■\s*(1[0-2]|[1-9])\s*월`(또는 줄 머리 `^\s*(\d{1,2})\s*월\s*$`)을 그 표의 월로 쓴다.
   - ctx 에 월 제목이 없고, 바로 앞 운영계획형 표가 **같은 과목**(`subjAt` 같음)이며 쪽이 이어지면(같은 쪽 또는 다음 쪽) 앞 표의 월을 이어받는다(p.94 `#288` 같은 연속 표).
   - ctx 에 새 과목 머리(`[과목]과 교수·학습 및 평가 운영 계획` 또는 `N [ 과목 ] 교수·학습 운영 계획`)가 있으면 이어받기를 끊는다(과목 전환 초기화). 월 근거가 없으면 그 표는 지금처럼 버린다(가짜 월 금지).
3. 허위 행 방지: 머리 반복 줄·빈 줄·`주` 칸이 비고 단원·성취기준도 빈 줄은 기존 규칙대로 건너뛴다. 성취수준·평가 기준표(머리 `성취기준|성취수준`, `평가 영역명` 등)는 `WEEK` 열이 없어 대상이 아니다(덤프 #7~#20 확인).
4. 학년도·학기·학년은 문서 슬롯 그대로(행에 넣지 않음). 다른 학교 형식(머리에 `월` 열이 있는 기존 진도표)은 영향 없음.

## 6. 시험 제안

- 정상: 셀 격자 `[["주","단원명","교육과정 성취기준","수업방법"],["3-4","1. 한국 문학의 흐름","[10공국2-05-01] …","강의법"],["5","5. 함께 읽고 쓰는 즐거움","[10공국2-03-01] …","토의"]]` + ctx `"… ■ 8월"` → 2행, month=8, week 3~4 / 5, 날짜 없음.
- 연속 표: 같은 과목 다음 쪽 표 ctx 에 월 없음 → 앞 표 월 이어받음. 과목 머리가 바뀐 ctx → 이어받지 않고 버림.
- 음성: ctx 에 월 없음·앞 표 없음 → `null`(기존과 같음). 머리에 `월` 열이 있는 기존 진도표 → 기존 결과와 같음(회귀). 성취수준 표 → `null`.
- 실파일 재현(로컬, 사용자 DB 쓰기 없음): `a28-25\TmpBoraTableDump.java` 를 시험 사본의 `src/test/java/.../service/plan/` 에 두고
  `BORA_PDF=<위 보관 위치> BORA_OUT=<출력 경로> ./gradlew test --tests '*TmpBoraTableDump'` → 수정 전 `planLikeTables=62 withMonthHeadingInCtx=61 rulesNull=62`, 수정 후 `rulesNull` 감소 확인(덤프는 `TeachingPlanRules.rows(g)` 를 부르므로 새 오버로드에 맞춰 한 줄 바꿀 것).
