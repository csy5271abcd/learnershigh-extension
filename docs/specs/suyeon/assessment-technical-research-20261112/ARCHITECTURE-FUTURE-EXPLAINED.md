## 1. 현재와 목표의 차이

| 영역 | 현재 | 목표 | 상태 |
|---|---|---|---|
| 인증 | Mock Header | 기존 LearnersHigh 인증, `reviewer_auth=VERIFIED` | 미구현(API-OD-A01) |

| 정확도 측정 | 없음 | Golden Dataset·Benchmark | 설계·도구만 |

## 2. 데이터 흐름(목표)

1. 학생·관리자가 실제 인증으로 로그인한다.
2. 관리자가 계획서를 올리면 Backend가 서명·악성 파일 검사 후 원본을 운영 Storage에 보관한다.
3. Backend가 분석 작업을 만들고 분석 서비스를 호출한다(브라우저를 거치지 않음).
4. 분석 서비스는 파싱 → 규칙 추출 → (실패·모호 구간만) LLM → 근거 검증 순서로 후보를 만든다. 근거 검증을 통과하지 못한 값은 버린다.
5. 후보는 REVIEW_REQUIRED로 저장된다. 관리자가 원문과 대조해 fieldPath별로 확정한다.
6. 확정값이 학생 수행평가 흐름(evaluationItemRef 등)에 쓰인다.
7. Golden Dataset으로 규칙·LLM 각각의 지표를 같은 시험 분할에서 측정해 적용 여부를 정한다.

## 3. 포함하지 않은 것

- 비동기 Queue 제품(Kafka 등)·OCR 엔진 이름: 근거 문서가 없어 특정하지 않았다.
- 모델 학습: 계획 기록 없음.
