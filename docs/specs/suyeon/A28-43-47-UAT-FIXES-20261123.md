## 2. 학교 검색(A28-45) — 목록 불완전과 학교 식별의 분리

- 후보 하나의 선택 가능 조건(서버, `SchoolDirectoryService`): 학교알리미 학교 ID 있음 · 이 검색 결과 안에서 ID 유일 · 상세 조회 성공 · 주소 있음 · (정식 이름 + 주소) 유일. 하나라도 아니면 `ID_MISSING`·`ID_CONFLICT`·`ADDRESS_MISSING`·`ADDRESS_DUPLICATE` 로 선택 불가. **목록이 잘렸다는 이유(`SEARCH_INCOMPLETE`)로는 더 이상 막지 않는다.**
- 불완전 경고는 그대로: `complete=false`·`incompleteReason`. 화면 문구 '학교알리미 검색 목록 일부만 읽었어요 · 확인된 N곳 선택 가능 · 확인하지 못한 M곳 · 찾는 학교가 없으면 정확한 이름으로 다시 검색 [다시 확인]'.
- 상세 조회 실패 학교: 후보로 내지 않고 `unverifiedCount` 로 수만 알린다. 그런 검색은 캐시하지 않아 '다시 확인'(= `refresh=true`, 캐시 우회 재검색)으로 다시 확인한다. 외부 호출은 기존 관리자당 1분 20회 상한·클라이언트 유한 재시도 그대로(무한 재시도·폴링 없음).
- 선택 보증(변경 없음): 서버가 발급한 `candidateId`(10분)만 받는다 → 위조·만료·선택 불가 후보 409. 자동 선택 없음: '이 학교 선택' → 대상 확인(18구간) → '이 학교로 조회 시작'을 눌러야 선택 POST. 고른 후보의 학교알리미 ID 로만 매핑(다른 학교로 바뀌지 않음). 학생 학적·담당·기존 매핑 불변. 학교알리미 검색 자체 실패는 502(고를 수 있는 척하지 않음).
- 시험: `SchoolDirectoryOfficialViewApiTest` 7/7 — 신규 'A28_45 5곳 중 상세 1곳 실패 → 4곳 선택 가능 · `unverifiedCount=1` · 매핑 0 · 다시 검색하면 다시 확인(5곳) · 동명 2곳 주소로 구별 · 고른 학교만 매핑 · 위조 409 · 검색 실패 502', 기존 '잘림 → 경고 유지 + 식별된 후보 선택 가능'으로 갱신.
- 계약: §38-15 DRAFT 개정(`unverifiedCount`·`refresh`·사유 코드, '불완전하면 모두 선택 불가' 규칙 대체).
