- PDF·HWP·HWPX 원문을 앱 안에서 열람(PDF는 기존 PDF Viewer, HWP·HWPX는 구조 뷰어).
- 학년도별 열람(3탭 유지)과 검토 Wizard 양쪽에서 분석 근거 → 원문 위치 이동·강조.

- HWP·HWPX **공식 확정**은 기존대로 운영 기본 거절(`structured-confirm-dev=false`, 실제 관리자 인증 연결 전) — 검토 화면은 읽기·근거 확인용이다.

## 4. PDF 변환 시험 결과와 채택 여부 — **채택하지 않음(자동 변환 불가)**

- 환경: 한컴오피스 2024 COM(`HWPFrame.HwpObject`). 시험 전 실행 중인 한글 없음 확인. 공개 HWP 1건의 **복사본**만 사용.
- 방식: 실행 정책 우회(`-ExecutionPolicy Bypass`) 없이 인라인 PowerShell 명령, 한컴 보안 모듈 등록(`RegisterModule`) **하지 않음**.
- 결과: `Open` 단계에서 멈춤 → 120초 시간 초과(PDF 미생성). 한글은 자동화의 파일 접근을 사용자 승인 창으로 확인하는데, 무인 자동 변환에는 보안 모듈(파일 경로 확인 DLL) 레지스트리 등록이 필요하다. 이것은 지시상 금지 사항(보안 모듈 무단 등록)이고 사용자 승인이 필요하므로 진행하지 않았다. 같은 경로인 HWPX는 반복하지 않았다.
- 정리: 제가 띄운 한글 프로세스 1개만 종료, 남은 프로세스 0, 복사본 SHA 불변, 원본 미접근.
- 따라서 페이지 넘김·특정 쪽 이동·글꼴/이미지 재현·documentLocator ↔ 변환 쪽 대응은 **검증하지 못했다**. 쪽 번호를 연결하지 않았다.
- 결론: 구조 뷰어를 기본으로 유지한다(P0 충족, §3). 변환을 다시 검토하려면 ① 사용자가 한컴 보안 모듈 등록을 승인하거나 ② 사용자가 직접 한글에서 "PDF로 저장"한 파일로 품질만 비교하는 방법이 있다. 운영 서버에 한컴 데스크톱 제품을 무인 실행하는 것은 별도 라이선스 확인이 필요하다.

## 7. 추가로 해결한 결함

1. **(중요) 검토 Wizard 화면 확정이 분석 과목 번호를 보내지 않음**: A10은 예전 확정 패널(`PlanReviewConfirmPanel`)만 고쳤고, 실제 Wizard는 `reviewModel.confirmRequestOf`로 요청을 만들고 있었다. 실제 다과목 PDF를 화면으로 확정해 보고 발견(`#undefined`) → 수정 후 재확인(§6). 재발 방지로 E2E `evaluation-flow`의 화면 확정 뒤 확정값의 `analysisSubjectIndex = 0`을 확인한다. A10 이후 이 결함 기간에 화면으로 확정한 PDF는 번호가 없을 수 있다 — 시연 DB 확정값은 0건이라 영향 없음(A10 확인), 일회용 DB만 사용.
2. Wizard 필드 행: 근거 버튼이 여러 개면 값이 한 글자씩 꺾이던 배치 → 행 줄바꿈·버튼 짧은 이름·한 줄 버튼으로 수정.
3. 구조 뷰어: 표만 담은 최상위 문단(글자 없음)에는 위치 표시가 없어 그 문단 Locator로 이동할 수 없던 점 → 위치 표식 추가.

## 8. 실제 평가계획서 상태 표현 (PART 3)

- 열람 화면(A9·A10)은 이미 확정 / 원문에 없음(확정) / 원문에 없음(분석) / 분석하지 못함 / 후보 / 정보 없음을 구분한다(유지).
- 검토 Wizard에 같은 구분을 추가했다(§1 '값 없음 사유'). 분석 실패(FAILED)는 기존대로 확정 불가 + 안내(A7·A8), 운영계획만 있는 PARTIAL은 운영계획 단계로 확정 가능(A8).
- 미추출 값의 관리자 직접 입력: 기존 '수정' → 값·근거 쪽 입력 → 확정 흐름(PDF)을 점검했고 결함은 없었다. HWP·HWPX 직접 확정은 운영 보호로 닫혀 있다(§2).
- 과목 연결이 불분명한 과거 데이터는 보정하지 않고 '후보'로 둔다(A10 우선순위 유지). 연도 간 비교는 복구하지 않았다.
