# 학생 케어 시안 디자인 검토

이 스킬은 공개된 두 검토 방법을 이 프로젝트에 맞게 조금 고친 것이다. 원문은 `upstream/`에 그대로 두었다.

- OneRedOak `claude-code-workflows`의 design-review 에이전트(MIT, `upstream/oneredoak-design-review-agent.md`): 라이브 화면 우선, 단계별 점검(준비 → 상호작용 → 반응형 → 시각 → 접근성 → 예외 상태 → 문구·콘솔), 심각도 4단계, 처방보다 문제와 영향.
- pbakaus `impeccable`의 critique(Apache-2.0, `upstream/impeccable-critique.md`): 평가를 서로 격리된 하위 에이전트로 돌림, Nielsen 10원칙 0–4점, 인지 부하 점검, 페르소나별 막힌 곳, P0–P3, "이 제품을 위해 만든 화면인가"(다른 제품에 그대로 써도 되는 화면이면 실패).
- 차트 하나하나는 설치된 `dataviz` 스킬의 기준(표현법 선택, 색, 표시 요소, 상호작용)으로 본다.

## 원문에서 바꾼 점

1. 검토 기준이 하나 더 있다: `docs/design/ops-redesign/reviews/xyz-checklist.md`(누적 피드백 S·R과 원문 F·G 항목). 원문의 일반 원칙보다 이 점검표가 우선한다. 지적마다 점검표 번호를 단다.
2. 관점이 둘(설계 검토·자동 탐지)이 아니라 역할 다섯이다. 각 역할이 세 시안을 모두 보되, 시안마다 그 시안의 컨셉으로 본다(예: 일반 사용자가 Y를 '데이터 분석 화면'으로서 쓸 수 있는가).
3. 화면 폭은 관리자 데스크톱 기준 1600·1280·1024, 라이트·다크 둘 다. 원문의 768·375는 이번 범위가 아니다.
4. Playwright MCP 대신 Playwright 스크립트로 조작·캡처한다(환경은 아래).
5. 원문의 "좋은 점부터 말하기"는 짧게 한 줄만. 지적이 본론이다. 기본 태도는 '고장 나 있다'.
6. 원문 critique의 detector 실행, 결과 저장(.impeccable), 추세 기록, 사용자 질문 단계는 쓰지 않는다. 합친 보고서는 부모(이 스킬을 부른 쪽)가 만든다.
7. 화면을 줄여 보고 판정하지 않는다. 구성 요소를 원래 크기로 잘라 본다(이전 검토가 이 때문에 실패했다).

## 실행 순서(부모가 한다)

1. 서비스가 떠 있는지 확인: 관리자 화면 `http://localhost:5174`, 학생 케어 API `http://localhost:8081`, 이미지 인식 서버 `http://localhost:39741`.
2. 역할 다섯을 **서로 격리된 하위 에이전트로 동시에** 띄운다. 각 에이전트에게 `reviewer.md` 전체와 자기 역할 이름만 준다. 다른 역할의 결과를 보여 주지 않는다. 하위 에이전트를 띄울 수 없으면 첫 줄에 `⚠️ 단일 문맥 검토(이유)`를 적는다.
3. 다섯 보고서가 모두 온 뒤에만 합친다. 합칠 때 그냥 이어 붙이지 않는다: 여러 역할이 같이 짚은 것, 한 역할만 짚은 것, 서로 다르게 본 것을 나눈다.
4. 합친 보고서: `docs/design/ops-redesign/reviews/agent-review/round-<n>.md`
   - 시안별 Nielsen 점수(역할별·평균), 막는 지적(P0·P1) 목록(점검표 번호·역할·캡처), 나머지(P2·P3)
   - 열린 요청 R과 시안 컨셉이 화면에 있는지(PM 판정)
5. 고친 뒤 같은 다섯을 다시 띄운다. 이전 회차 결과는 보여 주지 않는다. P0·P1이 0건이 될 때까지 반복한다. 만든 사람(부모)은 통과를 판정하지 않는다.

## 역할

- **꼼꼼한 분석가**: 데이터 한 줄 단위. 화면 값·막대·빨강을 API 값과 대조, 겹침·잘림·정렬·간격·대비·빈 상태·예외 데이터 처리.
- **시니어 디자이너**: 위계, 경계·구획, 밀도, 색감, 두께, 정렬 리듬, 표현법이 의미를 살리는지. '난잡함·의미 퇴색'을 근거로 말한다.
- **일반 사용자**: 학생 150명을 맡은 학습관 관리 선생님. 차트 용어를 모르고 10분 안에 오늘 연락할 학생을 골라 상담을 남겨야 한다.
- **도메인 전문가**: 관리형 독서실·스터디카페 운영 실무. 지표의 실제 의미, 정상 개인차, 신규·주 2일·퇴실 미기록·계획 미사용 같은 운영 상황.
- **PM(컨셉 검토자)**: 세 시안의 컨셉과 열린 요청이 화면에 있는지, 세 시안이 코드·디자인 모두 다른 이유로 존재하는지, 요청을 좁게·다르게 해석한 곳.
